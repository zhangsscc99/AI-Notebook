Claude Code 有哪些工具，怎么调度、纠错，失败怎么自动恢复

Claude Code 的工具调用不是“模型随便输出一个函数名然后执行”。源码里它被做成一套完整协议：工具注册表 → 模型 tool_use → schema 校验 → 权限/Hook → 并发调度 → tool.call() → tool_result 回填 → 下一轮模型纠错或继续。

一句话：Claude Code 把工具调用当成 agent 主循环的控制流。模型只负责提出 tool_use；运行时负责验证、授权、调度、执行、格式化结果和失败恢复。

1. 工具从哪里来

核心入口是 src/tools.ts。getAllBaseTools() 收集内置工具；getTools() 根据 permission context、simple mode、REPL mode、feature flag、deny rule 过滤；assembleToolPool() 再把内置工具和 MCP tools 合并去重。

所以“Claude Code 有哪些工具”不是固定死的一张表，而是由运行环境、权限模式、MCP 连接、feature flags 和 agent 配置共同决定。

2. 工具对象长什么样

src/Tool.ts 定义了统一 Tool 接口：name、inputSchema、call()、validateInput()、checkPermissions()、isConcurrencySafe()、mapToolResultToToolResultBlockParam() 等。

buildTool() 会补默认行为：默认启用、默认非并发安全、默认非只读、默认权限 allow。关键点是：每个工具都必须能把自己的返回值映射成 Anthropic API 需要的 tool_result。

按能力分，Claude Code 的主要工具可以这样记：

文件与代码

Read、Edit、Write、NotebookEdit、Glob、Grep、可选 LSP。这是读代码、搜代码、改代码的主力。

Shell 与系统

Bash、可选 PowerShell、可选 REPL。源码提示里也要求：读文件优先用 Read，搜内容优先用 Grep，编辑优先用 Edit，不要滥用 shell 代替专用工具。

Web / MCP / Skill

WebFetch、WebSearch、ListMcpResourcesTool、ReadMcpResourceTool、动态 MCP tools、Skill、ToolSearch。其中 ToolSearch 用于延迟加载工具 schema，减少首轮上下文压力。

Agent / Team / 任务

Agent、SendMessage、TaskOutput、TaskStop、TeamCreate、TeamDelete、TaskCreate、TaskGet、TaskList、TaskUpdate、TodoWrite。这些不是普通“工具”，而是多 agent / 多任务编排入口。

模式切换

EnterPlanMode、ExitPlanMode、可选 EnterWorktree、ExitWorktree。它们改变执行模式、审批边界或工作区隔离方式。

用户与自动化

AskUserQuestion、Config、SendUserMessage / Brief、可选 CronCreate、CronDelete、CronList、RemoteTrigger 等。部分工具只在 Anthropic 内部用户、实验 feature 或特定模式下出现。

一次工具调用的调度链路如下：

query.ts 调模型，流式收 assistant message。如果 assistant content 里出现 tool_use block，就加入 toolUseBlocks。
如果本轮没有 tool_use，主循环进入 stop hooks / 收尾 / recovery；如果有，就进入工具执行。
工具执行有两条路：开启 streaming execution 时用 StreamingToolExecutor，否则用 runTools()。
runTools() 会按 isConcurrencySafe() 分批：连续的并发安全工具并行跑；写文件、shell 等不安全工具串行跑。
每个 tool_use 进入 runToolUse()：查工具名、解析输入、跑权限、执行 tool.call()。
结果被包装成 user message 里的 tool_result，带回 query.ts，追加到 messages，然后下一轮模型继续判断。
assistant message
  -> content includes tool_use blocks
       [{ id: "toolu_1", name: "Read", input: {...} }]
  -> query.ts 收集 toolUseBlocks
  -> StreamingToolExecutor / runTools
  -> runToolUse
       1. findToolByName
       2. inputSchema.safeParse
       3. validateInput
       4. PreToolUse hooks
       5. permission decision / canUseTool
       6. tool.call
       7. PostToolUse hooks
       8. mapToolResultToToolResultBlockParam
  -> user message: tool_result(tool_use_id="toolu_1")
  -> 回到下一轮模型

3. 怎么纠错：先把错误变成模型可读的 tool_result

Claude Code 的核心恢复策略不是“运行时报错就崩”，而是尽量把错误包装成 is_error: true 的 tool_result 喂回模型。模型下一轮看到错误原因，就可以改参数、换工具、先读文件、重新搜索或请求用户确认。

例如工具名不存在时，runToolUse() 返回 No such tool available；输入 schema 不匹配时，返回 InputValidationError；工具自己的 validateInput() 不通过时，返回具体校验消息。

4. ToolSearch 纠错：工具 schema 没加载时提醒模型先加载

当 ToolSearch / deferred tool 开启时，有些工具 schema 不在首轮 prompt 里。模型可能凭名字猜参数，导致数组、布尔、数字被写错类型。buildSchemaNotSentHint() 会在 Zod 错误后追加提示：先调用 ToolSearch 选择这个工具，再重试。

这是一种很典型的“上下文工程式恢复”：不是扩大所有工具 schema，而是在失败时给模型一个明确修正路径。

5. 权限失败怎么处理

工具执行前会跑 PreToolUse hooks、通用权限系统和工具自己的 checkPermissions()。如果结果不是 allow，就返回错误 tool_result；如果是 auto-mode classifier 拒绝，还会跑 PermissionDenied hooks。Hook 可以返回 retry 信号，告诉模型“现在可以重试”。

所以权限失败不是静默失败，而是变成下一轮模型能读懂的反馈。

6. 工具运行异常怎么处理

tool.call() 外层有 try/catch。异常会被 formatError() 转成错误 tool_result；同时记录 telemetry，MCP auth 错误会把 MCP client 状态改成 needs-auth，并执行 PostToolUseFailure hooks。

这保证一次工具崩溃不会直接破坏整个消息协议。

失败后的“自动恢复”可以分三层理解：

第一层：工具级恢复

输入错、工具名错、权限拒绝、文件没读过就 Edit、Write 覆盖前没 Read、MCP 需要认证等，都会尽量变成错误 tool_result。下一轮模型根据错误信息自行修正动作。

第二层：调度级恢复

StreamingToolExecutor 会控制并发：并发安全工具可以同时执行；非安全工具独占。若并发 Bash 出错，它会中止兄弟 Bash 子进程并生成 synthetic error，避免一批依赖链命令继续乱跑。

第三层：模型/API 级恢复

query.ts 对 prompt-too-long、max_output_tokens、图片/媒体过大、模型 fallback 等有专门 recovery 逻辑：先 withheld 可恢复错误，尝试 context collapse、reactive compact、提高输出 token 或切 fallback model；失败后才把错误暴露出去。

协议闭合恢复

中断、异常或 fallback 时，Claude Code 会尽量补齐缺失的 tool_result，避免出现 assistant 发了 tool_use 但 user 没有对应 tool_result 的非法消息结构。这个细节很关键，否则下一次 Anthropic API 调用会因为消息不闭合而失败。

最重要的心智模型：Claude Code 的工具系统不是“工具执行器”，而是一个可纠错的模型-工具协议层。 它让模型用 tool_use 表达意图，让运行时用 schema、权限、并发、安全、hook 和错误 tool_result 把意图变成可审计、可恢复的工程动作。
