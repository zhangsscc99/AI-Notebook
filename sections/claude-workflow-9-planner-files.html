C9

Claude Code planner 层涉及哪些文件：路径清单与概括解读

Claude Code 里没有一个单独叫 Planner.ts 的总控文件。它的 planner 层是Plan Mode 机制：通过权限模式、plan 文件、Enter/ExitPlanMode 工具、plan mode system attachment、Explore/Plan 子代理、用户审批和恢复逻辑共同组成。

核心理解：Claude Code 的 planner 层不是“模型先输出一段计划文本”这么简单，而是一个工程化状态：进入 mode='plan' 后，模型只能读代码和写 plan 文件；最终通过 ExitPlanMode 把 plan 提交给用户或 team lead 审批，审批通过后才恢复实现模式。

1. 入口命令：/plan

src/commands/plan/index.ts

注册本地 JSX 命令 /plan，描述是“Enable plan mode or view the current session plan”。它只是命令声明，真正逻辑 lazy-load 到 plan.tsx。

src/commands/plan/plan.tsx

如果当前不是 plan mode，就调用 prepareContextForPlanMode()，再把 permission mode 切到 plan。如果已经在 plan mode，则读取当前 plan 文件并展示；/plan open 会用外部编辑器打开 plan 文件。

2. 进入计划模式：EnterPlanModeTool

src/tools/EnterPlanModeTool/EnterPlanModeTool.ts

这是模型可以主动调用的“进入计划模式”工具。它会拒绝 agent 子上下文调用，只允许主线程进入 plan mode。调用后更新 toolPermissionContext.mode = 'plan'，并返回明确指令：现在应该探索代码、设计实现方案，不能写业务文件。

src/tools/EnterPlanModeTool/prompt.ts

定义什么时候该进入 plan mode：新功能、多种实现路径、架构决策、多文件修改、需求不清、用户偏好会影响实现等。也定义什么时候不该用：拼写修复、简单单函数、纯研究任务。

src/tools/EnterPlanModeTool/UI.tsx

负责终端 UI 展示：进入、拒绝或结果消息。

3. 退出计划模式：ExitPlanModeTool

src/tools/ExitPlanModeTool/ExitPlanModeV2Tool.ts

这是 planner 层最关键的“闸门”。模型不能随口说“计划好了我开始写”，而要调用 ExitPlanMode。这个工具会读取 plan 文件，触发用户确认；如果是 teammate 且要求 plan approval，则把计划写入 team lead mailbox 等待审批。审批通过后，它把 mode 从 plan 恢复到进入 plan 前的模式。

src/tools/ExitPlanModeTool/prompt.ts

规定 ExitPlanMode 的使用边界：只在已经写好 plan 文件、准备让用户审批时调用；研究任务不要调用；不要用普通文本或 AskUserQuestion 去问“计划可以吗”，这正是 ExitPlanMode 的职责。

src/tools/ExitPlanModeTool/UI.tsx

负责显示“Exited plan mode”“Plan submitted for team lead approval”“Plan rejected”等 UI 状态，并展示 plan 文件路径。

4. Plan 文件存储：utils/plans.ts

src/utils/plans.ts

管理 plan 文件的生命周期。它为每个 session 生成一个 word slug，并把 plan 存到 plans directory。主会话路径类似 <slug>.md，子代理路径类似 <slug>-agent-<agentId>.md。

  • getPlanSlug()：为 session 生成 / 缓存 plan slug。
  • getPlansDirectory()：决定 plan 文件目录，默认在 Claude config home 的 plans 下，也可由 settings 指定项目内目录。
  • getPlanFilePath()：得到当前会话或 agent 的 plan 文件路径。
  • getPlan()：读取 plan 内容。
  • copyPlanForResume() / copyPlanForFork()：恢复或 fork 会话时保留 plan。

5. 权限模式：permissionSetup / bootstrap state

src/utils/permissions/permissionSetup.ts

这里是 plan mode 的权限语义中心。prepareContextForPlanMode() 会把当前模式保存到 prePlanMode，这样退出计划模式时能恢复。它还处理“plan 期间是否沿用 auto mode 语义”，必要时会 strip / restore dangerous permissions。

src/bootstrap/state.ts

保存 session 级 plan 状态：hasExitedPlanMode、needsPlanModeExitAttachment、planSlugCache，并通过 handlePlanModeTransition() 在进入 / 退出 plan mode 时设置一次性 attachment 提示。

src/state/AppStateStore.ts

AppState 里定义 initialMessage.allowedPrompts、pendingPlanVerification 等 plan 相关状态；teammate 如果要求 plan approval，初始 permission mode 会直接是 plan。

6. Plan Mode 指令注入：utils/messages.ts

src/utils/messages.ts

这是 planner 层的 prompt 编排核心之一。它把 plan_mode attachment 转成系统提醒，告诉模型：

  • 当前是 plan mode，除 plan 文件外不能编辑任何文件。
  • 只能做只读探索、代码阅读、搜索、提问和计划编写。
  • 计划文件路径是什么，是否已经存在。
  • 默认 workflow 是 Phase 1 初步理解 → Phase 2 设计 → Phase 3 review → Phase 4 写最终 plan → Phase 5 调用 ExitPlanMode。
  • 另一种 interview workflow 会要求边探索边更新 plan 文件，并用 AskUserQuestion 澄清。

这层才是模型“像 planner 一样工作”的主要 prompt 来源。

7. Compact 后保留计划上下文

src/services/compact/compact.ts

计划模式不能因为上下文压缩就丢失。这个文件里有：

  • createPlanAttachmentIfNeeded()：如果 plan 文件存在，压缩后继续把 plan 内容作为 attachment 保留。
  • createPlanModeAttachmentIfNeeded()：如果当前仍在 plan mode，压缩后重新注入 plan mode 指令，避免模型忘记“只允许写 plan 文件”。

这说明 planner 层不是一次性 prompt，而是和长上下文恢复机制绑定。

8. 工具注册和 agent 限制

src/tools.ts

把 ExitPlanModeV2Tool 和 EnterPlanModeTool 加进基础工具池；如果 feature gate 打开，还可能加入 VerifyPlanExecutionTool。

src/constants/tools.ts

定义哪些工具在 agent / async agent 里被禁用。注释明确说 ExitPlanModeTool 是 main thread abstraction，普通 async agent 不能随便退出主线程 plan mode。

src/tools/AgentTool/agentToolUtils.ts

有一个例外：如果 agent 的 permissionMode 是 plan，允许 ExitPlanMode，用于 in-process teammates 这种需要 plan approval 的场景。

9. Explore / Plan 内置子代理

src/tools/AgentTool/builtInAgents.ts

根据 feature gate 注册内置 Explore 和 Plan agents。plan mode 指令会建议复杂任务先并行启动 Explore agent 搜代码，再启动 Plan agent 设计方案。

src/tools/AgentTool/built-in/exploreAgent.ts

定义只读搜索型子代理，禁止 Write/Edit/NotebookEdit/ExitPlanMode 等工具，目标是快速找文件、grep、读代码并报告发现。

src/tools/AgentTool/built-in/planAgent.ts

定义软件架构规划子代理，同样只读，输出实现步骤、关键文件、依赖顺序和 trade-off。它复用 Explore agent 的工具集合，但系统 prompt 强调“只能探索和规划，不能改文件”。

10. 外部 API / CLI 模式入口

src/entrypoints/sdk/coreSchemas.ts

把 PermissionModeSchema 定义为包含 'plan'，说明 SDK / headless 入口也能设置 planning mode。

src/main.tsx

CLI 参数里有 --plan-mode-required；如果 agent swarm teammate 要求 plan approval，启动时 effective permission mode 会被设成 plan。

Claude Code planner 层心智模型：

入口
  /plan command 或 EnterPlanMode tool
    -> prepareContextForPlanMode()
    -> toolPermissionContext.mode = 'plan'
    -> 记录 prePlanMode，方便退出后恢复

计划过程
  messages.ts 注入 plan_mode instructions
    -> 只读探索代码
    -> 可写的唯一文件是 plan file
    -> 可用 Explore / Plan agents 辅助搜索和设计
    -> 必要时 AskUserQuestion 澄清
    -> 把最终方案写入 plan markdown

退出
  ExitPlanMode tool
    -> 读取 plan file
    -> 用户 / team lead 审批
    -> 审批通过后恢复 prePlanMode
    -> tool_result 把 approved plan 带回模型
    -> 模型开始真正实现

持久化 / 恢复
  utils/plans.ts 保存 plan 文件
  compact.ts 在上下文压缩后重新注入 plan 和 plan_mode 约束
  bootstrap/AppState 记录 session 级 plan 状态
最短总结：Claude Code planner 层 = plan permission mode + plan file + Enter/ExitPlanMode tools + plan_mode attachment prompt + Explore/Plan agents + approval gate。 它不是单点 planner 函数，而是把“先计划、审批后执行”做成了运行时状态机。
