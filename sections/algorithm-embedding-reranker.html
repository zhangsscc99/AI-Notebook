embedding 模型和 reranker 模型原理是什么

这里不要先从 RAG 应用讲，而要从模型结构和训练目标讲。embedding 模型和 reranker 模型本质上都是把“文本相关性”变成可学习的函数，但它们建模方式不同：embedding 模型学的是独立编码后的向量空间；reranker 模型学的是query 和 document 放在一起后的交互匹配函数。

一句话：embedding 模型通常是 bi-encoder / dual-encoder：query 和 doc 分开编码，再算向量相似度；reranker 通常是 cross-encoder：query 和 doc 拼在一起进 Transformer，让注意力层直接建模两者 token 之间的交互，然后输出相关性分数。

1. embedding 模型的模型结构

典型 embedding 模型是一个 Transformer encoder。输入文本经过 tokenizer 变成 token ids，再经过多层 self-attention 和 MLP，得到每个 token 的 hidden state。

最后需要一个 pooling 操作把 token-level 表示变成 sentence-level / passage-level 向量。常见做法有：取 [CLS] 向量、mean pooling、last token pooling，或者专门训练一个 projection head。

2. 为什么叫 bi-encoder

bi-encoder 的意思是 query 和 document 分开进模型：

q_vec = Encoder(query)
d_vec = Encoder(document)
score = cosine(q_vec, d_vec) 或 dot(q_vec, d_vec)

这里的 Encoder 可以共享参数，也可以 query encoder / doc encoder 分开。现在很多通用 embedding 模型会共享一个 encoder。

3. embedding 学到的是什么

它学到的是一个语义向量空间。训练目标不是让模型生成文字，而是让相关文本在向量空间里靠近，不相关文本远离。

如果做了 L2 normalize，那么向量都落在单位球面上，dot product 等价于 cosine similarity。模型训练本质上是在塑造这个球面上的语义几何结构。

4. embedding 的核心损失函数

最常见的是 contrastive learning / InfoNCE。给定一个 query、一个正样本 document 和多个负样本 document，目标是让正样本分数最高：

sim(q, d) = q · d / temperature
loss = -log exp(sim(q, d+)) / Σ exp(sim(q, di))

这里 temperature 控制分布尖锐程度；in-batch negatives 会把同一 batch 里其他样本的正例当成当前 query 的负例，训练效率很高。

embedding 模型训练时，关键不是“背知识”，而是构造正负样本关系：

正样本。query 和真正相关的 passage、问句和答案、标题和正文、相似句对、点击日志里的 clicked document，都可以构成正样本。
随机负样本。从语料里随机抽不相关文档，简单但太容易，模型很快学会。
hard negative。字面很像但语义不对的文档。它们最能提升 embedding 模型，因为模型必须学会细粒度区分。
蒸馏。用更强的 cross-encoder/reranker 给候选打分，再把这些分数蒸馏给 embedding 模型，让双塔模型逼近交叉编码器的排序能力。

5. reranker 的模型结构

reranker 通常是 cross-encoder。它不是分别编码 query 和 document，而是把两者拼成一个序列：

[CLS] query tokens [SEP] document tokens [SEP]

然后整个序列一起进 Transformer。self-attention 允许 query token 直接 attend 到 document token，也允许 document token 反向 attend query token。

6. reranker 输出什么

reranker 通常在 [CLS] hidden state 上接一个线性层，输出一个相关性分数：

h_cls = CrossEncoder(query, document)[CLS]
score = Linear(h_cls)

如果是分类式 reranker，输出可以是 relevant / irrelevant 的 logits；如果是排序式 reranker，输出就是一个实数 relevance score。

7. reranker 为什么更强

因为 cross-attention 能建模 token 级别交互。比如 query 里有“2020 年之前”“不是美国”“第二任 CEO”，reranker 可以逐 token 检查文档是否满足这些约束。

embedding 模型必须把整段文本压成一个向量，很多细节会被压缩掉；reranker 不需要提前压缩成单向量，所以表达能力更强。

8. reranker 的核心损失函数

常见训练方式有三类：

Pointwise:  BCE(score(q,d), label)
Pairwise:   max(0, margin - score(q,d+) + score(q,d-))
Listwise:   softmax(scores) 对齐理想排序分布

pointwise 学“相关/不相关”；pairwise 学“正样本要排在负样本前”；listwise 学“一组候选的整体排序”。

两者最本质的算法差异是相似度函数是否可分解：

embedding / bi-encoder:
score(q, d) = sim(f(q), f(d))
特点：q 和 d 可以独立编码，文档向量可预计算。
代价：q-d 细粒度 token 交互弱。

reranker / cross-encoder:
score(q, d) = g(q, d)
特点：q 和 d 必须一起进模型，注意力层直接建模交互。
代价：每个 query-document pair 都要重新前向计算。

embedding 的算法瓶颈

最大瓶颈是信息瓶颈：一段文档无论多复杂，最后都要压成一个固定维度向量。否定关系、数字条件、长距离依赖、多实体关系容易损失。

reranker 的算法瓶颈

最大瓶颈是计算复杂度。cross-encoder 的 self-attention 是对拼接后的 token 序列做交互，序列越长越贵；而且不能离线预计算所有文档的最终分数。

中间路线：late interaction

ColBERT 这类模型介于两者之间：query 和 doc 仍可分别编码成 token vectors，但打分时保留 token-level 最大相似度交互。它比纯 embedding 准，比 full cross-encoder 快。

模型能力排序

粗略看：bi-encoder 最快但交互最弱；late interaction 居中；cross-encoder 最准但最慢。这个差异来自模型结构，不是来自工程封装。

最短总结：embedding 模型学一个可检索的向量空间，reranker 模型学一个更精细的相关性判别函数。embedding 的核心是对比学习和向量几何；reranker 的核心是 cross-attention 和排序损失。前者牺牲交互换速度，后者牺牲速度换判断精度。
