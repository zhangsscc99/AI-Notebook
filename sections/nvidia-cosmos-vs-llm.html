Cosmos 和 LLM 的区别是什么

Cosmos 和 LLM 都用了 Transformer、token、conditioning、sampling 这些概念，所以容易混。但它们的目标对象、数据表示、训练目标、输出空间和评估方式都不一样。

一句话：LLM 学的是“文本 token 的下一个词/指令响应”；Cosmos 学的是“视频世界 latent/token 的生成和延展”。LLM 的输出是语言；Cosmos 的输出是世界视频帧或未来视觉状态。

1. 输出空间不一样

LLM

输出自然语言 token：字、词、subword、代码 token。它可以描述世界，但默认不直接生成视频 latent、像素帧或物理场景状态。

输入：问题 / 指令 / 上下文
输出：token_1, token_2, token_3 ... → 文本

Cosmos

输出视频世界表示：diffusion 路线输出 continuous video latent；AR 路线输出 discrete visual token，再 decode 成视频帧。

输入：prompt / 图像 / 短视频
输出：video latent 或 visual tokens → decode → 视频帧

2. Token 的含义不一样

LLM 的 token 是语言符号；Cosmos 的 token/latent 是视觉压缩表示。Cosmos Tokenizer 会把视频压到时空 latent/token 网格里。例如 AR pipeline 里，生成出来的一维 token 序列会 reshape 成 [B,T,H,W]，再由 video tokenizer 解码成视频。这个 token 对用户不可读，代表的是局部时空视觉模式。

3. 模型主干相似，但任务目标不同

相似点

  • 都有 Transformer 类结构。
  • 都可以用 cross-attention 接条件。
  • 都可以采样生成，而不是确定性检索。
  • 都可以用大规模预训练 + 后训练适配。

不同点

  • LLM 的序列主要是一维文本序列。
  • Cosmos 的序列/latent 有时间、空间、高宽、通道结构。
  • LLM 关注语义、推理、工具调用、代码。
  • Cosmos 关注视觉连续性、运动、物体外观、时序世界演化。

4. Cosmos 里面有没有 LLM？有，但不是主生成器

Cosmos 里有几类“语言模型相关组件”：

  • T5 text encoder：CosmosT5TextEncoder 默认加载 google-t5/t5-11b，只把 prompt 编码成 hidden states，不负责输出视频。
  • Prompt Upsampler：Text2World / Video2World 用 prompt upsampler 把输入提示词扩写或结合视觉输入生成更好的条件描述。
  • Aegis guardrail：pre-Guard 中有 LLM-based harmful prompt blocking。

这些组件的角色是条件构造和安全审查。真正生成视频世界的是 DiT diffusion 主干或 autoregressive visual-token 主干。

5. 为什么 AR Cosmos 看起来像 LLM，但仍不是普通 LLM

AR pipeline 的确很像 LLM：都有 tokenizer、vocab、Transformer、top-p、temperature、逐 token 生成。区别在于：

LLM：prompt_tokens 是文本 token，生成的还是文本 token。
Cosmos AR：prompt_tokens 包含视频上下文 token，生成的是 video tokenizer 的视觉 token。

LLM decode：token ids → 文字。
Cosmos decode：video token ids → 视频 latent/像素帧。

所以 Cosmos AR 可以理解为“把 LLM 的序列建模范式搬到视频世界 token 上”，但它的知识和能力边界不在文字，而在视频时空演化。

最短总结：LLM 是语言世界模型；Cosmos 是视觉/物理世界视频模型。它们共享部分 Transformer 工程范式，但 Cosmos 多了视频 tokenizer、时空 latent、DiT/扩散采样、视频解码、视频安全过滤这些 LLM 没有的关键组件。
