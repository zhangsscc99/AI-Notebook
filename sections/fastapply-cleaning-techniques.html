数据清洗的几个关键技巧是什么

FastApply 这类代码 patch 数据，清洗重点不是“样本越多越好”，而是让每条样本都满足：diff 能复现、修改点可定位、代码能解析、训练目标不含噪声。

先 replay patch。 SEARCH/REPLACE 必须真的能把 old_source 变成 new_source，否则模型学到的是错编辑。
用 Hunk 行号对齐 AST。 通过 Span、Hunk、ChangeContext 判断改动属于 import、function、class 还是 statement。
过滤非功能改动。 纯注释、纯空白、纯 docstring、格式化大改，reward 很容易误判，训练价值低。
控制长度和 hunk 数。 太长会吃上下文，hunk 太多会把任务变成“大重写”，不适合早期 GRPO。
按文件 / repo 做 split。 不要同一个文件的相似 patch 同时出现在 train 和 test，否则评估虚高。
近重复去重。 用 signature / MinHash / LSH 去掉模板化样本，避免模型靠背答案刷 reward。

我们项目里对应哪里

  • build/parse.py：把 diff 切成 hunk，再生成 changes。
  • data/types.py：Span/Hunk/UnitState/ChangeContext。
  • build/filter.py：AST 规则过滤 functional/import 修改。
  • build/generate.py：长度、语法、规则综合清洗。
  • build/deduplicate.py：近重复去重。

最容易踩坑

  • 只看 diff 文本，不验证 patch 是否可应用。
  • 把语法检查当单测：syntax 只能说明“能 parse”，不能说明逻辑正确。
  • 随机 split 导致同 repo 同文件泄漏。
  • 去重只按全文 exact，漏掉变量名不同但结构一样的重复样本。
一句话：高质量清洗 = 可复现编辑 + AST 定位 + 语法过滤 + 长度控制 + 去重 + 防泄漏 split。
