Claude Code 中 Agent 工作流编排的核心设计目标是什么？

Claude Code 的 Agent 工作流编排目标，不是把任务写成固定 DAG，而是把自然语言任务稳定地转成一个可恢复、可审计、可控权限、可长时间运行的 模型-工具闭环。

一句话：LLM 负责判断“下一步做什么”，运行时负责“怎么安全、稳定、可追踪地执行这一步，并把结果闭环回模型”。

1. 统一主循环

query.ts 承载主 agent、subagent、teammate 的核心循环：准备上下文 → 调模型 → 收 tool_use → 执行工具 → 回填 tool_result → 下一轮。

2. 工具调用即控制流

模型不能直接改文件或启动 agent，只能输出 tool_use。运行时用 schema、权限、工具接口和 result mapping 把文本意图变成确定动作。

3. 长任务可恢复

通过 transcript、compact、microcompact、tool result budget、max output token recovery、max turns，让长任务在上下文膨胀或中途失败后仍可继续。

4. 安全边界可控

敏感工具经过 canUseTool、permission mode、plan mode、worktree isolation；子 agent 和 team 不是绕过权限，而是把权限做成运行时协议。

5. 多入口复用

REPL、print/headless、SDK、background task、AgentTool、team swarm 都复用同一套 query/tool/task 机制，只是外层入口和输出格式不同。

6. 多 agent 工具化

AgentTool、TeamCreate、SendMessage、TaskList 都是工具/任务系统的一部分，多 agent 是统一协议上的扩展。

设计目标：
LLM 负责策略选择
Runtime 负责确定性执行：schema 校验、权限判断、工具执行、结果规范化、transcript、compact、错误恢复、多 agent 调度
