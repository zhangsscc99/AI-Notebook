LoRA 的 rank 过小或者过大有什么影响

LoRA rank 决定低秩增量矩阵的表达能力。rank 越大，可训练参数越多，能拟合更复杂的行为；rank 越小，训练更省资源，但可能表达不够。

rank 过小

  • 优点：显存低、训练快、不容易剧烈破坏原模型。
  • 缺点：容量不足，复杂 patch 合并、多文件风格迁移、长上下文定位能力提升有限。
  • 表现：reward 有一点提升，但遇到长 diff 或多 hunk 时仍然输出不完整、漏改、格式飘。
  • 适合：只做格式约束、短代码片段、轻量行为校正。

rank 过大

  • 优点：容量更强，能学复杂任务分布。
  • 缺点：显存和优化状态增加，训练变慢，更容易过拟合 tiny 数据。
  • 风险：reward shortcut、输出风格塌缩、泛化下降。
  • 适合：真实数据量足够大、任务变化多、需要强编辑能力时。
LoRA 参数量大致 ∝ rank · (输入维度 + 输出维度) · 目标层数量

本次用 rank=16 是一个烟测级折中：足够让 Qwen3 4B 在 Apply 格式和简单合并上产生变化，又不会把资源成本拉得太高。真实训练可以从 16/32 起步，对比 reward、验证集 exact apply、语法 pass rate 和长 diff 表现。

经验上：rank 小了像“只调提示词风格”，rank 大了像“给模型更多改写自由”。FastApply 这种代码编辑任务，如果数据足够，rank 16–64 都值得试；tiny 数据不建议盲目加大。
