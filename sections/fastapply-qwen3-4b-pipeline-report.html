FastApply GRPO 完整复刻：Qwen3 4B MinT 训练报告

现在已按 18 张图里的训练路线复刻：source + patch → 采样 rollouts → FastApply verifier reward → group-relative advantages → loss_fn="importance_sampling" 的 GRPO 训练。数据仍然只用 1–2 条 tiny test 样本，不扩造大数据。

18 张图对应的 pipeline

  • Apply 任务：把 patch 合并进 source，输出完整更新后代码。
  • Prompt contract：只输出 <updated>...</updated>，不要解释、不要 Markdown fence、不要冲突标记。
  • Patch 形式：SEARCH/REPLACE、structured changes、unified diff/AST 变更都预留。
  • 数据构造：Git commit/diff → old/new source → patch replay 校验 → 过滤 → 去重 → AST 顶层作用域检查。
  • 训练核心：用 verifier reward 做 GRPO，对应 MinT 的 importance_sampling。
  • 服务化：训练后保存 LoRA sampler，并用同一 Apply prompt 做采样验证。

代码模块

  • patching.py：SEARCH/REPLACE 与 structured changes 回放。
  • filters.py：尺寸、patch replay、AST/syntax、dedupe 过滤。
  • ast_tools.py：Python AST 与 JS 顶层符号分析。
  • rewards.py：exact、similarity、tag、no-extra-prose、syntax verifier。
  • grpo.py：reward centering，生成 weights/logprobs/advantages。
  • train_mint_fastapply_grpo.py：MinT GRPO 主训练循环。
从 tiny Apply 数据构造 prompt：<language>、<source>、<patch>。
保存当前 LoRA 权重拿 sampler，对同一 prompt 采样 policy rollout。
用 FastApply verifier 打分，并对同组 reward 做中心化：advantage = reward - mean_reward。
构造 MinT RL Datum：prompt 权重为 0，response 权重为 1，同时填入 sampled logprobs 和 advantages。
调用 forward_backward(..., loss_fn="importance_sampling")，再 optim_step，完成 GRPO 更新。
