builtin SQLite 表结构

builtin memory index 的核心数据在 SQLite。它不是只存一堆文本，而是把文件状态、chunk、FTS、embedding cache、可选 vector table 分开维护。

meta

存索引元数据，例如 provider/model、chunk 参数、vector 维度、FTS tokenizer、scope hash。用于判断是否需要 full reindex。

files

按 path 记录文件 hash、mtime、size、source。sync 用它判断文件是否变了，以及哪些旧文件已经不存在。

chunks

每个 chunk 一行：id、path、source、start_line、end_line、hash、model、text、embedding、updated_at。它是搜索结果和 memory_get 行号的基础。

chunks_fts / chunks_vec

chunks_fts 是 FTS5 虚表；chunks_vec 是 sqlite-vec 虚表，只有 vector enabled 且扩展可用时创建。

meta
files(path, source, hash, mtime, size)
chunks(id, path, source, start_line, end_line, hash, model, text, embedding, updated_at)
chunks_fts(text, id, path, source, model, start_line, end_line)
chunks_vec(id, embedding)
研究表结构时重点看两件事：source 字段如何区分 memory / sessions，以及 model 字段如何避免不同 embedding 模型的索引混在一起。
