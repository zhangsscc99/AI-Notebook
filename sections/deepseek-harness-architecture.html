DeepSeek Harness 的插件化架构怎么工作

DeepSeek Harness 的架构中心是 Cordis 插件树。插件把服务、类型化事件和可逆副作用注册到一个共享 context；其他插件通过类似 ctx.tools、ctx.llm、ctx.sessions 的 key 找到能力，而不是直接依赖某个具体实现。

一句话：Profile 决定启动哪些 bundle，bundle 携带可 patch 的插件配置，插件向 Cordis context 注册能力；卸载插件时，其注册和监听会被可逆地撤销。

四层组合模型

Profile
web、headless、sdk、acp 等具名应用组合。
Bundle
分发一组 Cordis 配置项和挂载代码，例如共享基础层 dsh-base。
Patch
按 id 替换整段 config 或插入新插件，支持 profile、home 和命令行 overlay。
Plugin Tree
最终挂载的 Cordis 插件树，提供 Agent 实际运行所需的服务。

核心服务

Session

ctx.sessions 保存追加式事件日志。模型历史、transcript、resume、fork 和遥测都从持久事件派生。

Tools

ctx.tools 是作用域化工具注册表，并把 pre-execute、execute、post-execute 串成可拦截流水线。

LLM

ctx.llm 定义消息与流式词汇，具体 provider 以 adapter 形式插入。

Agent Loop

ctx.agentLoop 驱动 inbox、模型请求、工具调用、失败恢复和 turn 关闭。

为什么这种架构可替换

文件系统、进程、PTY、LSP、沙箱和 subagent 都通过 capability seam 连接。比如把文件系统与子进程 provider 指向远程沙箱，Bash、PTY 和 LSP 可以一起迁移，而不需要为每种工具复制一套 fork。模型可见的每个事实还必须可从 Session 日志重建，这使恢复、审计和 UI 投影共享同一真相源。
