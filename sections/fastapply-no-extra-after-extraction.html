既然规则已经能抽到 updated 标签，为什么 reward 里还要 no_extra_prose

关键点是：规则抽取 updated 是为了拿到 candidate 去判断“代码内容对不对”；no_extra_prose 是为了判断“模型原始输出干不干净”。 这两个目标不一样。

抽取只服务内容评分

项目会先用规则从原始输出里抽取 <updated>...</updated> 内部代码：

extracted = extract_updated_tag(output)
candidate = extracted if extracted is not None else output
exact = candidate == expected_source

所以即使原始输出是：

好的，修改如下：
<updated>
def add(a,b): return a+b+1
</updated>
解释：这里把 +1 加上了。

规则仍然能抽出中间代码，exact / similarity / syntax 可能很高。

no_extra_prose 服务输出纪律

no_extra_prose 检查的是原始输出整体：

stripped = output.strip()
no_extra = stripped.startswith("<updated>") \
        and stripped.endswith("</updated>")

它不是再判断代码内容，而是惩罚标签外的“好的、解释、Markdown fence、废话、额外总结”。

规则抽取：让 reward 能评估代码内容，不被前后废话完全干扰。
exact/similarity/syntax：评估抽出来的 candidate 是否正确。
no_extra_prose：回头检查 raw output 是否只有机器需要的标签块。
GRPO：同时奖励“代码对”和“输出干净”。
所以不是“抽掉两段后 no_extra_prose 没意义”。正相反：抽取让内容评分鲁棒；no_extra_prose 防止模型学会在正确代码外面继续聊天。
