用一张架构图解释 JoyAgent 工作流编排

下面这张图按源码里的真实分层画：上面是产品入口和 SSE 流式层，中间是 Java 自研 Agent runtime，下面是工具服务和外部能力。理解 JoyAgent 编排时，重点看两条主路径：REACT 单 agent 工具循环和PLAN_SOLVE 规划-执行-总结循环。

读图方式：左到右是请求流；中间橙色区域是 JoyAgent 自研 Java Agent 框架；右侧是 LLM function calling；底部是 Python 工具服务、MCP、数据/检索/文件产物。

图里最重要的 3 条线

  • 请求线：UI → Controller → AgentContext → HandlerFactory。
  • 执行线：Handler → React 或 PlanSolve → LLM.askTool → ToolCollection。
  • 回传线：Printer/SSE 把 plan、tool thought、tool result、summary、result 流式推回前端。

为什么说它是产品级编排

因为 JoyAgent 不只是模型和工具循环。它还处理前端交互、SSE 心跳、输出样式、文件交付、MCP 工具接入、并行子任务、SOP 召回、最终总结。这些都属于“能不能成为完整产品”的编排部分。

Architecture reading order

1. User submits query in UI
2. GenieController creates SseEmitter and AgentContext
3. ToolCollection is built from built-in tools + MCP tools
4. AgentHandlerFactory selects REACT or PLAN_SOLVE
5. REACT:
     ReactImplAgent loops think/act until no tool calls
6. PLAN_SOLVE:
     PlanningAgent creates tasks
     ExecutorAgent executes tasks
     multiple tasks can run in parallel
     results go back to planner
7. SummaryAgent summarizes memory and product files
8. SSEPrinter streams all visible events back to UI
图的结论：JoyAgent 的工作流编排核心是自研 Java agent runtime，把 ReAct、Plan-Solve、并行 Executor、工具集合、LLM function calling 和 SSE 产品输出串成一条端到端链路。
