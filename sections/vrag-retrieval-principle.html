VRAG 用的是什么检索原理

从源码看，VRAG 的检索不是 BM25，也不是 LLM 直接读全量图片，而是多模态 dense retrieval：把文本、图片、视频片段编码到同一个向量空间，然后用 FAISS 做向量相似度检索。

一句话：VRAG 检索原理 = 多模态 embedding 模型把 query 和视觉/文本语料都变成向量，FAISS 用内积相似度找 topK，agent 再把召回的图片/视频/文本喂给 VLM 继续推理。
建库。SearchEngine.build_index() 扫描 corpus。文本记录保存 content，图片保存 file_path，视频保存 file_path 和抽帧参数。
编码。如果用 GVE，就通过 VLProcessor 把 text/image/video 包成 Qwen2.5-VL 风格消息，再 model.encode()；如果用 Qwen3-VL Embedding，就调用 Qwen3VLEmbedder.process()。
归一化。GVE 的 AutoModelForSentenceEmbedding.encode() 默认会 F.normalize；Qwen3-VL Embedding 的 process(..., normalize=True) 也会 L2 normalize。
入库。向量写入 faiss.IndexFlatIP。IP 是 inner product，向量归一化后基本等价于 cosine similarity。
查询。SearchEngine.search() 把 query 编成向量，然后调用 _index.search(query_vectors.astype('float32'), top_k) 返回分数和索引位置。

所以它的 ranking 目前是纯向量相似度排序：FAISS 返回的 similarities 和 indices 直接映射回 file_data_list，形成 score / indice / data。
