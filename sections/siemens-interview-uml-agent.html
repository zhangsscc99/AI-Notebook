UML 类图：设计一个 Coding Agent

这题考的不是"聊天机器人"，而是工具调用协议 + 循环 + 权限治理。图里的类能直接和 Claude Code 源码对上：Tool.ts、QueryEngine.ts、src/tools/。

一句话答案：引擎驱动"模型 → 工具 → 结果回灌"的循环；工具是接口并自带元数据（只读 / 破坏性 / 可并发），权限据此决定放行还是询问。

Q：设计一个能读写代码、执行命令的 Coding Agent，画出核心类图

先问清边界（CLI 还是服务、工具只读还是可写、单 agent 还是多 agent），再按"一次请求的生命周期"抽类，最后补扩展点。

三个关键设计点

  • 工具自带元数据：isReadOnly() / isDestructive() / isConcurrencySafe()，引擎读元数据决定策略，而不是硬编码工具名——新增工具时权限逻辑零改动。
  • 权限随调用下传：canUseTool 是参数不是全局单例，多会话、子 agent 并行时才不会串权限。
  • 上下文压缩是一等公民：没有 ContextManager，agent 跑到十几轮就爆 context；shouldCompact() / compact() 是长任务能跑下去的前提。
追问："工具误删文件怎么办？"——三道闸：工具声明 isDestructive → 权限策略要求人工确认 → 命令沙箱/白名单兜底。回答里带上"三道闸"，比只说"加个确认"高一个档次。
