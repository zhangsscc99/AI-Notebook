VRAG 的 embedding 模型和 reranker 模型用的是什么

从当前源码看，VRAG 明确实现了 embedding 检索模型接入，但没有实现独立 reranker 模型。排序主要靠 FAISS inner product 分数。

embedding：默认 Qwen3-VL-Embedding-2B

search_engine/search_engine_api.py 里写死 model_path = "Qwen3-VL-Embedding-2B"。search_engine/search_engine.py 的 main 示例也初始化 SearchEngine("Qwen3-VL-Embedding-2B")。

embedding：可选 GVE-3B / GVE-7B

README 支持 Alibaba-NLP/GVE-3B，维度 2048；Alibaba-NLP/GVE-7B，维度 3584。源码里 GVE 基于 Qwen2.5-VL embedding，支持 text/image/video 编码。

embedding：可选 Qwen3-VL-Embedding-2B / 8B

README 里列出 Qwen/Qwen3-VL-Embedding-2B 维度 2048，Qwen/Qwen3-VL-Embedding-8B 维度 4096。源码按名字里的 2B/8B 设置维度。

文本 baseline：bge-m3

SearchEngine 也支持 bge-m3 分支，用 SentenceTransformer，维度 1024。但这是文本 embedding 路线，不是 VRAG 视觉检索的主线。

GVE 和 Qwen3-VL Embedding 的向量生成方式也能从源码看出来：

GVE：AutoModelForSentenceEmbedding.encode() 取最后一层 hidden state，支持 last 或 mean pooling，默认 normalize。
GVE 训练侧：AutoModelForSentenceEmbeddingTriplet.forward() 会编码 query、positive、negative，用 cross entropy 做对比学习；还计算 t2v 和 v2t 两个方向的 loss。
Qwen3-VL Embedding：Qwen3VLEmbedder.process() 把 text/image/video 包成 conversation，前向后取 attention mask 最后一个有效 token 的 hidden state，再 L2 normalize。
检索排序：这些 embedding 向量进入 faiss.IndexFlatIP，search 返回 inner product 分数。
reranker 结论：当前仓库没有看到独立的 reranker/cross-encoder 重排模块，也没有 search 后二阶段 rerank。VimRAG 的 priority_score 和 memory energy 是 agent 记忆筛选逻辑，不是传统检索 reranker。VRAG 的检索结果排序主要就是 embedding 相似度排序。
