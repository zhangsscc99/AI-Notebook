Wan2.2 完整 pipeline 是什么，有别于 LLM 的组件结构是什么

我读的是服务器源码 /root/Wan2.2。Wan2.2 的完整生成链路不是“Transformer 直接输出视频文件”，而是一个视频 latent 扩散/flow matching 系统：CLI 选择任务 → prompt / image / audio 条件预处理 → T5 / VAE / 其他条件 encoder 编码 → 初始化整段视频 latent 噪声 → scheduler 多步采样 → WanModel/DiT 预测更新方向 → CFG 合成条件/无条件预测 → VAE 解码成 RGB 帧 → 保存 mp4。

一句话：LLM 的 pipeline 是“tokenizer → Transformer → 下一个离散 token → detokenize”；Wan2.2 是“条件编码器 → 视频 latent 噪声 → DiT 多步去噪 → VAE 解码 → 视频编码保存”。两者都用 Transformer，但 Wan 多了 VAE、scheduler、timestep、视频时空 latent、3D patch、CFG、多模态条件、high/low noise expert、分布式/显存调度这些非 LLM 组件。

1. 从 generate.py 看顶层任务路由

generate.py 是 CLI 入口。它根据 args.task 选择不同 pipeline：WanT2V、WanTI2V、WanI2V、WanS2V、WanAnimate。这点和 LLM 不同：LLM 通常只有文本输入输出主干；Wan 的输入形态会决定额外条件分支。

generate.py 顶层路由：
T2V    -> WanT2V.generate(prompt)
TI2V   -> WanTI2V.generate(prompt, optional image)
I2V    -> WanI2V.generate(prompt, image)
S2V    -> WanS2V.generate(prompt, image, audio, pose...)
Animate-> WanAnimate.generate(reference, motion...)
最后统一 save_video(video, fps=cfg.sample_fps)

2. 文生视频 T2V 的主 pipeline

配置决定模型组件。wan_t2v_A14B.py 配置 T5 checkpoint、VAE checkpoint、vae_stride=(4,8,8)、patch_size=(1,2,2)、high/low noise checkpoint、采样步数、boundary 和 CFG scale。
T5 文本编码。WanT2V.__init__() 创建 T5EncoderModel。生成时对正向 prompt 和 negative prompt 分别编码，得到 context 与 context_null。
目标视频 latent 形状。target_shape = [z_dim, F_latent, H_latent, W_latent]，其中 F/H/W 被 vae_stride 压缩。这里的 latent 是整段视频，不是逐帧 token。
初始化随机噪声。源码用 torch.randn(target_shape) 生成初始 video latent。生成过程从纯噪声开始，而不是像 LLM 一样从 BOS token 开始。
构造 flow scheduler。根据 sample_solver 选择 FlowUniPCMultistepScheduler 或 FlowDPMSolverMultistepScheduler，并设置 timesteps。
每个 timestep 调 DiT。采样循环里把当前 latent、timestep、文本 context、seq_len 输入 WanModel，模型输出与 latent 同形状的 update / noise_pred。
CFG 合成。同一步会跑条件预测 noise_pred_cond 和无条件预测 noise_pred_uncond，再用 uncond + scale * (cond - uncond) 增强提示词服从度。
scheduler 更新 latent。sample_scheduler.step(...) 把当前 latent 更新到下一步，循环 40/50 步左右。
VAE 解码。采样结束后 self.vae.decode(x0) 把 clean video latent 解码成 [C,F,H,W] RGB 视频张量。
视频保存。generate.py 调 save_video()，按 cfg.sample_fps 写成 mp4。
// wan/text2video.py，核心逻辑简化
context      = text_encoder([prompt])
context_null = text_encoder([negative_prompt])
noise = torch.randn([z_dim, F_latent, H_latent, W_latent])
latents = [noise]

for t in timesteps:
    model = high_noise_model if t >= boundary else low_noise_model
    pred_c = model(latents, t=t, context=context, seq_len=seq_len)[0]
    pred_u = model(latents, t=t, context=context_null, seq_len=seq_len)[0]
    pred = pred_u + guide_scale * (pred_c - pred_u)
    latents = [scheduler.step(pred, t, latents[0])[0]]

video = vae.decode(latents)

3. WanModel 内部和 LLM Transformer 的关键差异

3D patch embedding

WanModel 用 nn.Conv3d(in_dim, dim, kernel_size=patch_size, stride=patch_size) 把 C/F/H/W 视频 latent 切成时空 patch token。LLM 的 token 来自 tokenizer；Wan 的 token 来自视频 latent patch。

F/H/W RoPE

rope_apply() 把 RoPE 频率拆给时间 F、高 H、宽 W。LLM 主要是一维文本位置；Wan 必须知道每个 token 的帧位置和空间位置。

timestep embedding

Wan 每一轮都显式输入扩散/flow timestep。time_embedding 和 time_projection 会调制每个 attention block。LLM 推理没有“噪声时间步”这个维度。

cross-attention 读取文本

视频 token 通过 WanCrossAttention 读取 T5 context。也就是说文本不是被继续生成的对象，而是控制视频 latent 去噪的条件。

head 输出连续 latent update

Head 输出的是 out_dim * prod(patch_size) 的连续值，再 unpatchify() 还原成 latent 张量。LLM head 输出的是词表 logits。

不是自回归

Wan 不是“上一帧/上一 token → 下一帧/下一 token”。它每一步整体更新同一个视频 latent；视频逐步变清晰，而不是按时间顺序逐帧吐出。

4. 图生视频 / 统一 TI2V 多出来的条件组件

如果是 I2V/TI2V，pipeline 会额外把图片塞进 latent 条件。WanI2V.generate() 里先把输入图 resize 到目标尺寸，把首帧和后续零帧拼成视频，再用 VAE encode 成 y，并拼上 mask。WanModel.forward() 收到 y 时，会把它和当前 noisy latent 沿 channel 维拼接。

// I2V 思路简化
img_video = concat(resized_first_frame, zeros_for_future_frames)
y = vae.encode([img_video])[0]
y = concat(mask, y)
model(latent, t, context=text_context, y=[y])

5. A14B high/low noise expert 是什么

T2V/I2V A14B 不是一个 DiT 从头跑到尾，而是加载 high_noise_model 和 low_noise_model 两个 checkpoint。_prepare_model_for_timestep() 用 boundary = cfg.boundary * num_train_timesteps 判断当前 timestep 应该用哪个模型。高噪声阶段负责从乱噪声里定大结构，低噪声阶段负责细化纹理和局部质量。

6. 和典型 LLM 对照

LLM 组件链

文本 -> tokenizer -> token ids
-> embedding + Transformer decoder
-> vocab logits -> sample next token
-> append token，循环
-> detokenize 成文本

Wan2.2 组件链

prompt/image/audio 条件
-> T5 / VAE / audio/pose encoder
-> 随机 video latent
-> scheduler timesteps
-> DiT 预测 latent 更新方向
-> CFG 合成
-> scheduler 更新整段 latent，循环
-> VAE decode 成 RGB 帧
-> save_video 成 mp4
最短记忆法：LLM 的核心资产是“离散文本 token 序列”；Wan2.2 的核心资产是“连续视频 latent 张量”。所以 Wan 的组件结构围绕压缩视频、控制噪声、建模时空位置、多步求解和像素解码展开；Transformer 只是其中的 denoiser 主干，不是整个系统。
