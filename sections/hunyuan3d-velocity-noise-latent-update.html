模型预测 velocity / noise 是什么，和 latent 更新是什么关系

严格讲，模型并不是每一步直接预测“最终 latent 长什么样”。它预测的是一个更新方向。这个方向可以参数化成 noise、score、velocity 等形式；Hunyuan3D-2.1 的训练配置里写的是 prediction: velocity。

一句话：latent 的迭代更新确实是先预测 velocity/noise 这类方向量，再由 scheduler 用这个方向量更新 latent。velocity 可以理解成“在 latent 空间里，从当前 noisy 状态朝 clean 3D 状态移动的速度/向量场”。

先区分三个量：

1. clean latent x1

真实 3D surface 经过 ShapeVAE encode 得到的目标 latent。训练时知道，推理时不知道。

2. noisy/current latent xt

训练时由 noise latent x0 和 clean latent x1 按时间 t 插值得到；推理时就是当前迭代中的 latents。

3. velocity / noise prediction

模型输出的不是 mesh，也不是一定直接输出 x1，而是一个与 latent 同形状的向量，告诉 scheduler 当前 xt 应该怎么动。

4. scheduler step

scheduler 根据当前 sigma/timestep，把模型输出转成下一步 latent。源码里 FlowMatch Euler 形式是 prev_sample = sample + (sigma_next - sigma) * model_output。

velocity 到底是什么？看 Hunyuan3D-2.1 的线性路径：

路径：xt = t * x1 + (1 - t) * x0
其中：
x0 = 纯噪声 latent
x1 = clean 3D shape latent
t  = 当前时间，越接近 1 越接近 x1

对 t 求导：
velocity = d xt / d t = x1 - x0

所以 velocity 不是速度单位的物理速度，
而是 latent 空间中“从噪声点指向数据点”的方向场。
训练时构造目标 velocity。path.plan(t, x0, x1) 返回 xt 和 ut。在线性路径里，ut 就是从噪声到数据的方向。
DiT 预测这个方向。model_output = model(xt, t, contexts)，如果是 velocity 模式，就用 MSE(model_output, ut) 训练。
推理时没有目标，只能预测。从随机 latent 开始，模型根据图片条件判断当前 latent 应该往哪个方向动。
scheduler 真正修改 latent。模型只给方向，scheduler 决定步长和公式。Hunyuan3D 推理里每一步 latents = outputs.prev_sample。

为什么不直接预测 clean latent

可以设计成预测 clean sample，但扩散/flow 模型常用 noise/velocity/score 参数化，因为在不同噪声水平下学习“局部方向”更稳定，也更适合 ODE/SDE solver 多步积分。

noise 和 velocity 有什么关系

noise 参数化是让模型预测噪声成分；velocity 参数化是让模型预测从噪声分布到数据分布的向量场。源码的 path.py 里也提供 get_noise_from_velocity()、get_score_from_velocity() 这类转换。

所以模型预测 latent 吗

不是直接预测最终 latent；但它预测的是 latent 空间里的向量，scheduler 用这个向量更新 latent。因此最终 latent 是一步步积分出来的。

noise_pred 变量名会不会误导

会。推理代码里变量叫 noise_pred，但在 flow matching / velocity 模式下，它更准确地说是 model_output / velocity-like update。变量名沿用了 diffusion 习惯。

推理更新关系：
latents 当前值 = sample
model_output = DiT(sample, timestep, image_condition)
prev_sample = sample + step_size * model_output
latents = prev_sample

多步重复后：
random latent -> clean shape latent -> mesh
最短总结：velocity 是 latent 空间里的移动方向，不是最终答案。模型预测 velocity/noise，scheduler 按步长更新 latent；最终 clean latent 是多步更新累计出来的。
