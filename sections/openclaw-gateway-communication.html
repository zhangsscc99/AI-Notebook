OpenClaw 的通信方式

OpenClaw 的通信不是一条简单 HTTP 请求。源码里可以分成四层：SDK / CLI 到 Gateway 的 RPC 通信、Gateway 事件流、Channel 插件到 agent turn 的路由、最终回复的 durable delivery。

一句话：Gateway 是控制面和协议路由器；Channel 是外部平台适配器；EventHub 是异步事件总线；sessionKey / agentId 是把消息送回正确会话的地址。

1. SDK ↔ Gateway：WebSocket RPC

packages/sdk/src/transport.ts 里的 GatewayClientTransport 会包装 src/gateway/client.ts。客户端调用 request(method, params)，底层通过 WebSocket 发请求帧。

常见 method 包括 agent、agent.wait、sessions.create、sessions.send、sessions.abort、tasks.list/get/cancel、tools.catalog/effective/invoke。

2. Gateway → SDK：事件流

packages/sdk/src/event-hub.ts 提供 EventHub.publish() 和 EventHub.stream(filter, { replay: true })。Gateway 收到 agent 运行中的状态变化后，会以事件形式推给客户端。

事件类型包括 agent.started、assistant.message、agent.completed、session.created/updated/compacted、task.updated 等。

3. Channels：把外部消息变成 agent turn

Telegram、iMessage、Slack、Discord 等入口不是直接调用模型，而是通过 channel 插件把外部平台消息标准化，然后交给 src/channels/turn/kernel.ts 创建一次 reply pipeline。

channel routing 会根据平台、账号、peer、thread 等信息映射到 agentId 和 sessionKey，确保同一个群、私聊或 thread 能持续进入同一条会话线。

4. Outbound：结果怎么发回去

src/channels/message/send.ts、reply-pipeline.ts、durable-delivery.ts 负责最终回复、流式 preview、工具进度 preview 和失败重试。

lastRoute 记录“这条 session 的回复应该回到哪里”。这让 agent 运行完成后，不需要重新猜应该发到哪个 Telegram chat 或哪个 iMessage thread。

典型链路可以这样讲：

用户在 Telegram / CLI / Web UI 发消息。
入口层把消息转换成 Gateway request 或 channel inbound event。
Gateway / channel routing 解析 agentId、sessionKey、附件、幂等 key、权限上下文。
OpenClaw agent runtime 执行模型推理、工具调用、memory search、artifact 生成。
运行状态通过 EventHub / Gateway stream 发给客户端；最终回复进入 reply pipeline。
durable delivery 根据 lastRoute 把消息发回原平台，失败时可以重试或记录状态。
CLI / SDK
  → GatewayClientTransport.request("agent", params)
  → Gateway WebSocket method dispatch
  → agent runtime
  → EventHub: agent.started / assistant.message / agent.completed
  → SDK stream receives events

Telegram / iMessage
  → channel plugin inbound
  → channel turn kernel
  → session routing: agentId + sessionKey
  → agent runtime
  → reply pipeline / durable delivery
  → original chat/thread
记忆方式：RPC 负责“发命令”，Event 负责“看过程”，Channel 负责“接外部平台”，sessionKey 负责“找到会话”，lastRoute 负责“把结果送回去”。
