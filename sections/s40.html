哪些索引方式能索引 session transcript

这里要分清两个层次：session transcript 这个数据源和底层检索索引方式。OpenClaw 里 transcript 的 source 是 sessions；只要这个 source 被启用，它可以进入 builtin SQLite 的 FTS / vector / hybrid 索引，也可以进入 QMD 的 sessions collection。

1. builtin SQLite：FTS 文本索引

如果没有可用 embedding，或者配置走 FTS-only，session transcript 会被 buildSessionEntry() 转成纯文本 chunk，写入 chunks 和 chunks_fts。这种方式按关键词 / BM25 类文本匹配召回。

适合：无需 embedding provider、成本低、部署简单。缺点是语义召回弱，换一种说法可能搜不到。

2. builtin SQLite：vector 语义索引

如果 embedding provider 和 sqlite-vec 可用，session chunks 会被算 embedding，写入 chunks_vec。检索时可以按语义相似度召回历史对话。

适合：用户问“上次那个方案”“我之前说的偏好”这类语义模糊问题。缺点是依赖 embedding 模型、索引成本更高。

3. builtin SQLite：hybrid 混合索引

OpenClaw 的 builtin backend 可以同时保留 FTS 和 vector。session transcript 作为 source="sessions" 参与同一套 chunk / score / citation 流程。

适合：既要精确词命中，又要语义召回。实际工程里这是更稳的选择。

4. QMD backend：导出 sessions collection 后索引

QMD 不是直接用 builtin 的定向 sessionFiles 机制。启用 memory.qmd.sessions.enabled 后，QMD manager 会把 JSONL transcript 导出成清洗后的 User/Assistant Markdown 文本，放到 ~/.openclaw/agents/<id>/qmd/sessions/，再由 QMD collection 建索引。

注意：QMD 的 sync(sessionFiles) 会忽略“只刷某个 transcript”的 hint，改为跑常规 update。

怎么搜到 session transcript？memory_search 支持 corpus="sessions"，这会把搜索 source 限制到 session transcripts；corpus="memory" 会排除 sessions；不指定时取决于当前配置 sources。
// tools.ts 里的意图：按 corpus 限制 memory source
const searchSources = requestedCorpus === "sessions"
  ? ["sessions"]
  : requestedCorpus === "memory"
    ? ["memory"]
    : undefined;

容易混淆：session transcript vs session-memory Markdown

sessions 是原始会话 JSONL 清洗后的索引源；MEMORY.md / memory/*.md 是长期记忆文件。后者属于 source="memory"，不是 transcript 本身。

容易混淆：dreaming session corpus

memory/.dreams/session-corpus/ 是 dream / promotion 机制生成的派生语料。它如果被 memory 文件索引扫到，走的是 memory 文件路径，不等于 builtin 直接索引 source="sessions" 的 transcript。

最短答案：能索引 session transcript 的主路径有两条：builtin 直接索引 source="sessions"；QMD 先导出 sessions collection 再索引。builtin 内部又可以是 FTS-only、vector-only/semantic、FTS+vector hybrid。
