记忆一共有哪些，除了 RAG

如果把 RAG 理解成“搜索索引，然后把相关片段取回上下文”，那 OpenClaw 的 memory 体系里还有几类不是单纯 RAG 的记忆。

Bootstrap Memory

启动新会话时，系统会把 MEMORY.md 和最近几天的 daily memory 以受限预算注入上下文。这不是搜索，而是启动时的基础记忆。

Exact Read Memory

memory_get 按文件和行号读取原文。它不是语义检索，而是精确回读。

Session Memory

可选地把历史 session transcript 建索引，让后续能搜索以前的对话。它属于会话历史召回。

Memory Flush

compaction 前自动提醒模型把重要内容写进 memory/YYYY-MM-DD.md，这是防止上下文压缩丢信息的写入机制。

Dreaming / Promotion

后台整理短期信号，把高价值内容候选提升到长期记忆，并把审阅信息写到 DREAMS.md。

Memory Wiki

memory-wiki 把 durable memory 编译成更像知识库的结构，有 claims、evidence、dashboard、wiki_search、wiki_get。

换句话说，OpenClaw 的记忆不是只有“RAG 搜索”。它至少包括：

  • 启动注入型记忆：直接进入 prompt。
  • 检索型记忆：memory_search。
  • 精确读取型记忆：memory_get。
  • 会话历史型记忆：session transcript indexing。
  • 自动写入型记忆：memory flush。
  • 整理晋升型记忆：dreaming / promotion。
  • 知识库型记忆：memory-wiki。
  • 外部补充语料：registered corpus supplements。
RAG 是 recall 的一部分，但 OpenClaw 的 memory 更像一个“写入、启动注入、搜索、精读、整理、晋升、知识库化”的完整生命周期。
