skills vs agentic RL：这两者各自优势是什么，agentic RL 能补 skills 什么短板

skills 强在快、便宜、可控、可解释；agentic RL 强在把“会不会做”真正内化到 policy 里。 两者不是互斥关系，更像两层：skills 是应用层行为塑形，agentic RL 是训练层能力塑形。

skills 的优势

  • 上线快：写一个 skill 就能改 agent 行为，不需要重新训练模型。
  • 便宜：主要成本是 prompt、流程和工具设计，不需要大规模 rollout / reward / update。
  • 可控：你可以明确规定步骤、边界、禁区、工具顺序和输出格式。
  • 可解释：agent 为什么这么做，通常能直接从 skill 文本和工具流程里读出来。
  • 适合长尾场景：某个垂类任务、某个平台接入、某个操作手册，优先用 skill 很划算。

skills 的瓶颈

  • 本质仍是外部脚手架：能力更多是“被提示出来”，不是“长进模型里”。
  • 迁移性有限：换一个相邻任务、换一种输入分布，skill 往往要重写或补丁式叠加。
  • 上下文依赖重：很多表现来自 prompt、例子、流程约束，一旦上下文变形，行为会漂。
  • 难以持续自我改进：做完一次任务后，模型参数没变，下次还得靠同样脚手架重新扶着走。
  • 组合复杂度会上升：skill 越多，交叉覆盖、冲突、维护成本会越来越高。

agentic RL 的优势

  • 把行为写进 policy：不是每次提醒模型怎么做，而是通过 reward 和 update 让它逐步学会怎么做。
  • 更适合多步决策：尤其是 rollout 后能看到任务结果、环境反馈、工具后果的场景。
  • 可利用结果信号持续优化：答对/答错、成败、效率、可执行性，都能变成 reward。
  • 能减少对外部脚手架的依赖：学进模型后的能力，理论上更稳，不必事事靠长 prompt 扶着。

agentic RL 能补 skills 哪些短板

  • 补“只会照说明做、不会真正长本事”：skills 像训练手册，RL 才是在训练能力本身。
  • 补“泛化差”：如果 reward 设计得好，模型能学到比单个 skill 更抽象的决策模式。
  • 补“每次都要重新扶”：参数更新后，下一次 rollout 天然带着上一次学到的改进。
  • 补“行为不能闭环优化”：skills 能规定流程，但不能自动根据结果改 policy；RL 可以。
  • 补“复杂多步任务靠 prompt 很脆”：当任务真的是 sequential decision making，RL 比纯 skill 更像正解。
skills
  = runtime scaffolding
  = prompt / workflow / tool routine / guardrails
  = 快、便宜、可控
  = 但能力主要在外面

agentic RL
  = rollout -> reward -> update
  = 能力通过训练写进 policy
  = 慢、贵、复杂
  = 但能持续改进并弥补 skills 的外部脚手架瓶颈
最短总结：skills 解决“先把 agent 做得像会做”；agentic RL 解决“让 agent 真的越来越会做”。
