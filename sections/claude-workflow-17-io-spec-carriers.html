简述 Claude Code 工作流的输入输出规范，核心数据载体有哪些？

Claude Code 不是简单 string in / string out。它是多层数据载体：用户输入变成 Message，工具调用变成 tool_use/tool_result，运行时事件变成 Attachment/Progress/StreamEvent，最终由 QueryEngine 规范化成 SDKMessage 或 UI 输出。

1. 用户输入

prompt: string | ContentBlockParam[]，可包含文本、图片、paste、IDE selection、slash command。

2. Message[]

内部核心载体，包括 user、assistant、system、attachment、progress、tombstone、tool_use_summary，是 query、transcript、resume、compact 的共同基础。

3. 工具协议

assistant 里有 tool_use，运行时必须回填对应 tool_result。工具定义 input schema、output schema、permission、render、result mapping。

4. ToolUseContext

携带 messages、tools、MCP、permission context、abortController、readFileState、skill discovery、setAppState 等运行时能力。

5. 系统上下文

systemPrompt、userContext、systemContext、agent definitions、MCP tools、skills/plugins 决定模型看到什么和能调用什么。

6. Attachment / Task

queued commands、task notification、memory prefetch、skill discovery、edited file attachment、task state、mailbox、output file 承载运行时和异步结果。

7. SDK 输出

QueryEngine 输出 assistant、user replay、system compact/api_retry、stream_event、tool_use_summary、result success/error 等 SDKMessage。

8. 最终 result

包含 result text、duration、turn count、stop_reason、session_id、cost、usage、modelUsage、permission_denials、structured_output、error subtype。

User prompt / ContentBlockParam[]
  -> processUserInput()
  -> Message[]
  -> query(QueryParams + ToolUseContext + Tools/MCP/Agents)
  -> assistant tool_use
  -> Tool.call()
  -> user tool_result
  -> Attachment / Progress / StreamEvent
  -> QueryEngine normalize
  -> SDKMessage / UI message / result
关键规范：tool_use 必须和 tool_result 配对，Message[] 必须可持久化和恢复，Attachment 必须能规范化成模型可读上下文，最终 result 必须能被 SDK/CLI 稳定消费。
