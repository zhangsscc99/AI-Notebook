千问强化学习：整个训练 pipeline

qwen_rlhf 已克隆到 /root/OpenClaw/src/qwen_rlhf，与 /root/OpenClaw/src/memory 平级。这个项目的核心不是 UI，而是一条完整的代码编辑模型训练流水线：准备底座模型 → 构造半合成编辑数据 → SFT 监督微调 → 离线生成与评测 → 可选 GRPO/RLHF 强化优化。

一句话：它把 Qwen2.5-Coder-3B-Instruct 训练成一个“代码 patch 合并器”：输入原始 Python 文件和 SEARCH/REPLACE 更新块，输出合并后的完整代码，并包在 <updated>...</updated> 中。
下载/检查底座模型。用 scripts/download_model.py 下载 Qwen2.5-Coder-3B-Instruct，优先 ModelScope，失败时可走 Hugging Face；再用 check_model_ready.py 检查 tokenizer、config、safetensors shard 是否齐全。
构造训练数据。scripts/build_semisynth_dataset.py 读取 configs/dataset_semisynth.yaml，从 CommitPackFT 流式读取提交样本，只保留单文件 Python、小范围、许可证允许、非 merge/revert/chore/lint 的修改。
把 before/after 转成 patch 任务。src/qwen_edit/patching.py 用 difflib.SequenceMatcher 生成 PatchHunk(search, replace)，再用 apply_hunks() 反向校验：search 必须唯一命中，替换后必须精确等于 after。
写出 JSONL 数据集。合格样本会写到 data/processed/semisynth_train.jsonl 和 semisynth_valid.jsonl。每条样本包含 instruction、before_code、after_code、source、input_patch、target_updated、target_patch、metadata。
渲染 SFT prompt。src/qwen_edit/sft_dataset.py 把样本变成 chat：system 说明模型是代码更新合并助手；user 给 Source Code 和 Update Patch；target 是 <updated>最终代码</updated>。
LoRA SFT 训练。scripts/train_sft.py 加载 Qwen，按 configs/sft_lora.yaml 启用 LoRA；target modules 覆盖 q/k/v/o projection 和 gate/up/down projection；可选 4bit NF4 量化、bf16、gradient checkpointing。
生成预测。训练后用 scripts/generate_predictions.py 加载 SFT 模型，对验证集逐条生成 <updated> 结果，写出 predictions JSONL。
离线评测。scripts/eval_offline.py 调用 src/qwen_edit/eval.py，统计 parse_ok、exact_match、syntax_ok、minimality：既看格式是否正确，也看最终代码是否精确匹配、语法是否通过、改动是否足够小。
可选 GRPO/RLHF。scripts/train_grpo.py 使用 trl.GRPOTrainer，把 SFT 模型作为起点，用 reward 函数继续优化输出格式、patch 可应用性、语法正确性和最小改动。

为什么先 SFT

SFT 先让模型学会固定任务格式：读源码、读 patch、输出完整更新代码。如果没有这个阶段，RL 的 reward 很容易只惩罚错误，却无法稳定教会基本行为。

RLHF 优化什么

GRPO 阶段不是重新定义任务，而是在 SFT 基础上强化四件事：输出可解析、patch 可应用、应用后语法正确、改动规模接近 gold。

数据质量关键点

项目严格过滤提交，并要求生成的 hunk 能唯一匹配和精确还原 after。这样训练数据不是“看起来像 diff”，而是真正可执行、可校验的编辑任务。

当前成熟度

README 明确说 GRPO 先是骨架，真正开训前还要对齐硬件和 reward 细节。因此当前最完整的是数据构建、SFT、生成预测、离线评测链路。

最重要的理解：这个项目训练的不是“会聊天的 Qwen”，而是“能可靠执行代码编辑合并的 Qwen”。SFT 负责学会任务，GRPO/RLHF 负责把输出变得更可解析、更可应用、更正确、更少乱改。
