Claude Code 的 reflection 怎么做

结论要先说清：从源码看，Claude Code 不像 Reflexion 论文那样有一个独立、统一、每轮必跑的 ReflectionTool / ReflectionEngine。它更像是把 reflection 拆散到了多个工程闭环里：工具失败回填、stop hook 反馈、plan/todo 状态、compact summary、多 agent 任务状态。

一句话：Claude Code 的 reflection 不是一个单独模块，而是“把错误、反馈、计划和摘要重新放回下一轮模型上下文”，让模型在下一轮自己修正。

1. 工具结果自纠错

query.ts 收到 tool_use 后执行工具；失败时并不直接崩溃，而是把错误包装成 is_error: true 的 tool_result。下一轮模型读到错误原因后，重新选择参数、工具或方案。

这就是最常见的“反思”：模型不是事后写一篇 reflection，而是在下一轮看到失败证据后调整行为。

2. Stop hook 反馈循环

query/stopHooks.ts 和 src/utils/hooks.ts 支持 Stop hooks。hook 可以在模型准备停止时返回 blocking feedback，让主循环继续，而不是直接结束。

例如项目规定“停止前必须跑测试”，Stop hook 发现没测试，就把反馈塞回上下文，模型下一轮会继续补测试。

3. Plan / Todo / TaskList 是显式状态

Plan mode、TodoWrite、TaskList 让模型把当前目标、子任务、完成状态外显出来。外显状态本身会进入后续上下文，模型可以对照“计划还剩什么”来修正下一步。

这属于工作流层面的 reflection：不是重新训练模型，而是让状态可见、可更新、可检查。

4. Compact summary 保存经验教训

services/compact/* 会在上下文压缩时总结用户意图、已改文件、关键错误、剩余任务。压缩后的 summary 会替代旧长上下文，继续指导后续回合。

这可以看作“长程 reflection”：把过去执行过程提炼成可继续执行的状态摘要。

一个失败后自修正的流程：

模型计划编辑文件，发出 Edit tool_use。
运行时发现 old_string 不唯一或文件没读过，返回错误 tool_result。
错误结果被追加进 messages，进入下一轮模型调用。
模型阅读错误，先调用 Read 或扩大上下文，再重新发出更精确的 Edit。
如果模型想停止，Stop hook 还可以做最后检查；不满足则反馈继续。
不是：
runTask → runReflectionEngine → writeReflection → retry

更接近：
assistant tool_use
  → tool_result(error / success)
  → append to messages
  → next model turn reads evidence
  → revised tool_use or final answer
  → stop hooks may block and feed feedback
  → compact summary preserves useful state
所以讲 Claude Code 的 reflection，应该说它是协议级反思：把失败、权限拒绝、hook 反馈、计划状态、压缩摘要都变成下一轮模型可读输入。不要误讲成源码里有一个统一的“反思大脑”。
