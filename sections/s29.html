memory 测试入口

如果要改 OpenClaw memory，测试入口要按风险分层选。不要只跑一个 happy path，因为 memory 的失败模式通常在 provider、SQLite、FTS、vector、QMD fallback、session visibility 上。

工具层测试

看 tools.test.ts、tools.citations.test.ts、tools.recall-tracking.test.ts。验证 memory_search / memory_get 返回格式、引用、错误降级。

manager 搜索测试

看 manager-search.test.ts、manager-search-preflight.test.ts、hybrid.test.ts、mmr.test.ts。

sync / reindex 测试

看 manager.atomic-reindex.test.ts、manager-targeted-sync.test.ts、manager.session-reindex.test.ts、manager.sync-errors-do-not-crash.test.ts。

QMD / provider 测试

看 qmd-manager.test.ts、qmd-compat.test.ts、manager.mistral-provider.test.ts、manager-embedding-policy.test.ts。

推荐改动后的最小验证顺序：

pnpm test extensions/memory-core/src/memory/hybrid.test.ts
pnpm test extensions/memory-core/src/memory/manager-search-preflight.test.ts
pnpm test extensions/memory-core/src/tools.test.ts
pnpm test extensions/memory-core/src/memory/qmd-manager.test.ts
如果改了 schema、chunking、embedding model、source visibility 或 QMD fallback，必须扩展测试，不要只修快照或只跑 CLI。
参考：extensions/memory-core/src/**/*.test.ts、packages/memory-host-sdk/src/host/*.test.ts
