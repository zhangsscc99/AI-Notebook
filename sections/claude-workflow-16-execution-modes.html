C16

Claude Code 支持哪几种工作流执行模式？各自的适用场景是什么？

Claude Code 的执行模式可以按入口、agent 形态、权限/隔离和并发方式理解。底层大多复用同一套 query/tool/task 机制。

1. 交互式 REPL

适合人机协作、看 diff、逐步确认、处理权限弹窗。入口：src/screens/REPL.tsx。

2. Headless / SDK / print

适合脚本、CI、服务端集成、非交互自动化。入口：src/QueryEngine.ts、src/cli/print.ts。

3. 单 agent ReAct 循环

默认模式，适合大多数读代码、改代码、跑测试任务。核心：src/query.ts。

4. Plan-gated 模式

适合复杂修改前先探索、写计划、审批后实现。核心是 permission mode + plan file + Enter/ExitPlanMode。

5. 同步 subagent

父 agent 等子 agent 完成，结果直接作为 tool_result 返回。适合短研究、短规划、一次性检查。

6. 异步 background agent/task

父 agent 启动后台任务后继续工作，后续通过 task notification 或 output file 获取结果。适合长搜索、长测试、并行探索。

7. Coordinator / Team swarm

用 TeamCreate、Agent(name)、SendMessage、TaskList 组织多个 worker。适合大项目拆分和并行研发。

8. Worktree / remote isolation

让 agent 在独立工作区或远端环境里跑，适合实验性修改、多 agent 并行和避免污染主工作区。

小任务 -> 单 agent
复杂需审批 -> plan-gated
短研究 -> 同步 subagent
长任务/并行探索 -> background agent
大项目并行 -> Team swarm
担心污染工作区 -> worktree isolation
CI/API -> Headless/SDK
