工具太多怎么办：Claude Code 如何找工具并控制 token

Claude Code 并不是把一个固定工具列表硬编码进循环，也不是让模型直接“搜索工具名称”。它先把当前会话允许的工具整理成模型可理解的 schema 集合，交给模型选择；模型返回 tool_use 后，再由本地 registry、权限层和执行器完成路由。

一句话：工具路由由模型根据 schema 决定，真正的控制点有三层：工具发现与过滤、单次结果的 token 预算、历史上下文的 microcompact / autocompact。

1. 先过滤，再展示

buildToolPool() 与权限上下文先过滤当前模式不允许的工具。请求中以 tools 传递工具定义，toolChoice 保持 undefined，让模型自行决定是否调用以及调用哪一个。

2. 调用结果不能无限膨胀

Tool.ts 为每个工具声明 maxResultSizeChars。调用前通过 applyToolResultBudget() 对历史工具结果执行预算，超限内容会被持久化并替换成摘要或预览。

3. 旧结果会被压缩

microcompact 优先清理较早的工具输出，同时保留最近上下文；autocompact 在接近模型窗口时再生成会话摘要。这样工具结果不会永久占用每一轮请求。

4. MCP 工具动态刷新

循环在工具批次结束后刷新 tool context，使新连接的 MCP server 从下一轮开始可用。每次请求仍只携带当前有效的工具集合，而不是整个安装过的工具目录。

从模型响应到真实工具

模型读取 schema
工具名称、描述和输入 schema 一起进入请求上下文。
返回 tool_use
模型输出工具名与结构化参数；循环检查实际内容块，而不是只依赖 stop_reason。
本地 registry 路由
findToolByName() 查找实现，随后执行参数校验和权限检查。
结果预算与回填
结果以 tool_result 回到消息历史；大结果在进入下一轮前被限制或持久化。

并发不等于重复发送上下文

连续且 isConcurrencySafe() 为真的只读调用可以并行执行，默认上限来自 CLAUDE_CODE_MAX_TOOL_USE_CONCURRENCY，未设置时为 10。并发优化的是等待时间；它不会让同一批工具 schema 在请求里重复出现。
