OpenClaw 记忆系统的更新和遗忘

OpenClaw 的记忆更新不是“模型脑子里自动长出一条记忆”，而是文件源 → watcher / sync → chunk → index → search 的工程链路。长期记忆的真实源头通常是 workspace 里的 MEMORY.md、memory/*.md、extraPaths，以及可选的 session transcript。

一句话：OpenClaw 的“更新”主要是源文件变化后重新索引；“遗忘”主要是源文件删除/修改后清理索引、旧记忆分数衰减、预算压缩时丢弃自动晋升片段。默认不是让 LLM 自己随意删除记忆。

1. 更新从文件变化开始

MemoryManagerSyncOps.ensureWatcher() 会监听 MEMORY.md、memory/ 和 extra paths。文件 add/change/unlink/unlinkDir 后会标 dirty，并触发延迟 sync。

sync 时会重新列出 memory files，读取 path、mtime、size、hash、content。hash 没变的文件跳过；新文件或内容变化的文件才重新切块、embedding、写入索引。

2. 索引层怎么替换旧内容

每个 memory 文件会形成 file entry 和 chunks。文件内容变了以后，旧 chunks 会被替换；文件不再存在时，syncMemoryFiles() 会把 stale rows 从 files、chunks、vector table、FTS table 里删掉。

所以索引不是永久累积垃圾。真正的 source of truth 是 Markdown / transcript；索引只是为了检索加速和排序。

3. 会话记忆是增量进入的

session transcript 更新会触发 onSessionTranscriptUpdate()，经过 debounce 和 delta 阈值后再同步。源码里会避免每写一行 JSONL 都立即重建索引。

.jsonl.reset.*、.jsonl.deleted.* 这类归档文件会作为一次性 dirty event 处理，用于让 session memory 搜索知道会话被 reset / delete 过。

4. 忘记不是神秘能力

OpenClaw 的“忘记”首先是可审计的文件操作：你删除某个 Markdown 文件，或者删掉里面一段内容，下一次 sync 后对应 chunks 会从索引里消失。

这比“让模型自己决定遗忘”更工程化，因为你能在 Git / 文件系统里看到到底删除了什么。

可以按这个流程记：

用户、hook、session-memory 或人工编辑写入 MEMORY.md / memory/*.md。
chokidar watcher 捕获 add/change/unlink，标记 memory dirty。
syncMemoryFiles() 列文件、算 hash，只处理新增或变化文件。
indexFile() 把 Markdown 切成 chunks，写 SQLite / vector / FTS 或 QMD 后端。
文件被删除或不再属于 active paths 时，旧 file/chunk/vector/FTS 行被 prune。
之后 memory_search 只能召回当前索引里仍然存在、仍然得分够高的内容。

时间衰减：降低旧 dated memory 权重

temporal-decay.ts 负责按半衰期降低旧记忆分数，默认半衰期约 30 天，而且默认可关闭。重要点：evergreen 路径，例如 MEMORY.md 或非日期 memory 文件，不会像 daily memory 那样自然衰减。

预算压缩：只裁自动晋升区

memory-budget.ts 做 bounded MEMORY.md compaction。它主要删除最老的 Promoted From Short-Term Memory 自动晋升段，尽量保留用户手写内容。

短期到长期：靠召回统计晋升

short-term-promotion.ts 会记录 recallCount、dailyCount、groundedCount、query hashes、concept tags 等。达到阈值后，频繁被用到的短期片段才会晋升进长期 Markdown。

session-memory hook：reset 时落一份摘要

内置 session-memory hook 会在 /new 或 /reset 时，把最近若干轮对话保存到 workspace/memory/YYYY-MM-DD-HHMM.md，作为可索引的长期材料。

修改 memory/idea.md
  → watcher 标 dirty
  → syncMemoryFiles()
  → hash 变化，重建该文件 chunks
  → search 命中新内容

删除 memory/old.md
  → watcher 标 dirty
  → active paths 里没有 old.md
  → prune stale file/chunks/vector/FTS
  → search 不再召回 old.md
核心结论：OpenClaw 记忆系统的可信点在于“文件可编辑、索引可重建、删除可追踪”。更新和遗忘不是黑盒模型行为，而是围绕 Markdown source、session transcript、索引同步、时间衰减和预算压缩组成的生命周期。
