OpenClaw 的 session transcript 到底何时被索引

先把结论说清楚：session transcript 不是每发一条消息就立刻被索引。OpenClaw 先把会话写进本地 JSONL transcript；只有在 session memory 被启用、并且触发 sync 条件后，才会把 transcript 转成可检索文本，再写入 memory index。

核心判断：builtin backend 里最终由 shouldSyncSessionsForReindex() 决定本轮 sync 是否处理 source="sessions"。如果没有启用 sessions source，直接不索引 transcript。
1消息落盘
用户/助手消息先追加到 session JSONL transcript。它是原始会话日志，不是 Markdown 记忆。
2事件聚合
onSessionTranscriptUpdate 触发后进入 sessionPendingFiles，默认等 5 秒 debounce。
3阈值判断
检查累计新增 bytes / messages 是否达到 sync.sessions.deltaBytes 或 deltaMessages。
4sync
达到阈值后标记 sessionsDirty，调用 sync({ reason: "session-delta" })。
5构建索引文本
buildSessionEntry() 解析 JSONL，只保留 user/assistant 可检索文本。
6写入索引
调用 indexFile(entry, { source: "sessions" })，进入 FTS / vector / hybrid 索引。

什么时候会索引 transcript

第一类：首次搜索兜底。如果第一次 memory_search 时索引为空，search 会触发 sync({ reason: "search", force: true })。force 会让 sessions 进入本轮 sync，前提是 sources 包含 sessions。

第二类：session 增量变化。transcript 被追加后，不是马上建索引，而是 5 秒 debounce，再看 deltaBytes / deltaMessages 阈值，达标才 session-delta sync。

第三类：全量重建。配置 sources、embedding provider、chunk 参数、FTS/vector 状态等变化导致 full reindex 时，sessions 会一起重建。

第四类：定向 session sync。builtin backend 如果收到 sessionFiles 参数，会只刷新目标 transcript，而不是扫描所有 session。

什么时候不会普通索引 transcript

不是每轮对话后立即索引。源码用 debounce + 阈值控制成本，否则长对话每条消息都 reindex 会很重。

watch 不负责 transcript。文件 watcher 主要盯 MEMORY.md、memory/、extraPaths；reason="watch" 被明确排除 session sync。

session-start 也不是普通 transcript 建索引。它更多是预热入口；在 builtin 判断里，除非 force / full reindex / 定向 sessionFiles，否则 session-start 不会处理 sessions。

没有开启 sessions source 就完全不会走。配置层需要启用 session memory，并把 sources 加上 "sessions"。

QMD backend 的时机单独记：如果使用 memory.backend="qmd" 且 memory.qmd.sessions.enabled=true，transcript 会在 QMD 的 boot / interval / embed-interval / manual update 周期里先 export 成 sessions collection，再被 QMD 索引。QMD 收到 sessionFiles hint 时不会做 builtin 那种“只刷这个 JSONL”，源码里是忽略 hint、跑 regular update。
export function shouldSyncSessionsForReindex(params) {
  if (!params.hasSessionSource) return false;
  if (params.sync?.sessionFiles?.some((f) => f.trim().length > 0)) return true;
  if (params.sync?.force) return true;
  if (params.needsFullReindex) return true;
  const reason = params.sync?.reason;
  if (reason === "session-start" || reason === "watch") return false;
  return params.sessionsDirty && params.dirtySessionFileCount > 0;
}
所以你可以这样记：transcript 先作为 JSONL 被写下来；OpenClaw 再按“首次搜索兜底 / 增量阈值 / 全量重建 / 定向刷新 / QMD 更新周期”把它变成可检索索引。
