沙箱到底怎么隔离：Terminal Backend 和 Docker bind mount 是什么

先把概念拆开：沙箱隔离不是一个魔法开关，而是“命令在哪里跑、文件系统看到哪里、网络/进程/资源怎么被限制”的组合。Hermes 自己负责统一调度；真正的隔离能力来自它选择的 terminal backend，比如 Docker、Modal、Daytona、SSH、Singularity。

最短答案：Terminal Backend 就是 Hermes 执行 shell 命令的后端环境；Docker bind mount 就是把宿主机某个目录“挂进”容器里，让容器看到并修改这个目录。隔离的意义是控制 agent 的破坏范围，同时让工程任务可以复现、并行、迁移和训练。

1. Terminal Backend 是什么

你可以把 Terminal Backend 理解成：Hermes 收到 terminal("npm test")、terminal("pip install ...") 这种命令后，决定把命令发到哪里执行的执行器。

same agent command:
  terminal("pytest")

different backend:
  local       -> 在宿主机直接跑 pytest
  docker      -> 在 Docker 容器里跑 pytest
  modal       -> 在 Modal 云沙箱里跑 pytest
  daytona     -> 在 Daytona workspace 里跑 pytest
  ssh         -> 在远端服务器里跑 pytest

所以 Terminal Backend 不是“终端 UI”，而是 agent 的执行环境抽象。Hermes 的文件工具、后台进程、execute_code 都要尽量跟这个 backend 对齐，避免命令在容器里跑、文件却在宿主机改。

2. 沙箱隔离到底隔离什么

隔离主要隔离四类东西：

  • 文件系统：容器默认只能看到容器里的文件，看不到宿主机全部磁盘。
  • 进程空间：容器里启动的进程主要活在容器 namespace 里，不直接混进宿主进程环境。
  • 依赖环境：agent 在容器里装包、改 Python/Node 依赖，不会直接污染宿主机环境。
  • 资源边界：Docker / 云沙箱可以限制 CPU、内存、磁盘，避免一个任务吃掉整台机器。

但注意：隔离不是绝对安全。你如果把宿主目录、Docker socket、SSH key、API key 全挂进去，沙箱边界就会被你主动打开。

3. Docker bind mount 是什么

bind mount 是 Docker 的一种目录挂载：把宿主机目录映射到容器里的某个路径。容器看到的是容器路径，但背后真实文件在宿主机。

host:
  /root/myapp

docker container:
  /workspace

bind mount:
  /root/myapp  ->  /workspace

结果是：容器里改 /workspace/src/a.py，其实就是在改宿主机的 /root/myapp/src/a.py。这不是复制；这是同一批文件的两个视角。

4. bind mount 和复制项目的区别

如果是复制项目，流程是：先把宿主项目拷一份进容器，容器改自己的副本，最后你还要把改动拷回来或 git push。

如果是bind mount，流程是：容器直接看到宿主目录，改动立刻落到宿主文件。没有“最后拷回来”这个步骤。

copy mode:
  host project -> copy into container
  container edits copy
  need copy back / git push

bind mount mode:
  host project is mounted as /workspace
  container edits /workspace
  host project changes immediately

5. Hermes 为什么默认不随便 mount

Hermes 配置里 docker_mount_cwd_to_workspace 是显式选项。原因很直接：一旦 mount，agent 在容器里就能改你的宿主项目目录。

默认不挂载更安全：容器里乱删文件，影响主要在容器内部。你确认要让 agent 修改真实项目时，再打开 mount，把当前目录映射到 /workspace。

6. 一个真实例子：让 agent 修项目

假设你要让 Hermes 修 /root/myapp 里的 bug，并跑测试。你有两种选择：

  • local backend：最快，直接改宿主项目；风险是命令也直接影响宿主环境。
  • docker + bind mount：命令在容器里跑，依赖装在容器里；但代码目录通过 /workspace 挂进来，文件改动会回到宿主项目。

第二种适合真实开发：代码能保留，依赖污染和危险命令被更多地限制在容器里。

用户发任务。例如“修这个 repo 的测试失败”。
Hermes 看 backend。如果是 local，就在宿主执行；如果是 Docker，就创建/复用容器；如果是 Modal/Daytona，就连接云沙箱。
决定文件可见性。Docker 不 mount 时看不到宿主项目；打开 bind mount 后，宿主项目在容器里变成 /workspace。
agent 执行工具。read/search/patch/terminal 都围绕同一个 backend 的路径工作。
改动产生。local 是直接改宿主；bind mount 是通过容器视图改宿主；云沙箱是改远端环境，需要 clone/upload/sync/push 才能回到外部。
清理或保留。临时容器可以销毁；持久云沙箱可以休眠；宿主项目改动用 git diff / commit 管理。
Isolation mental model

Terminal Backend = where commands run

local:
  isolation: weak
  files: host files
  meaning: fast, but agent can affect host directly

docker without bind mount:
  isolation: stronger
  files: container files
  meaning: safer, but project changes do not automatically come back

docker with bind mount:
  isolation: medium
  files: host project exposed as /workspace
  meaning: dependencies/processes isolated, project files intentionally shared

modal/daytona:
  isolation: remote cloud sandbox
  files: remote sandbox filesystem
  meaning: good for long-running, remote, parallel, RL/benchmark tasks
为什么这对 agent 特别重要：普通程序员知道自己在敲什么命令，但 agent 会自动试错、装依赖、跑脚本、改很多文件。沙箱的价值就是给这种自动化行为加边界：允许它干活，但不要让它无限制碰宿主机、污染环境、破坏别的任务。
