Agent Team 里不同 agent 通信时，TaskList、Mailbox、SendMessage 的区别是什么？

在 Claude Code 的 Agent Team 里，TaskList、Mailbox、SendMessage 不是三套重复通信系统，而是三个层级不同的协作组件：TaskList 管“工作状态”，Mailbox 管“消息存储/投递”，SendMessage 是“模型可调用的发消息工具入口”。

一句话：SendMessage 是动作，Mailbox 是通道/收件箱，TaskList 是共享任务板。发一句话用 SendMessage，经 Mailbox 投递；分配和追踪工作用 TaskList。

1. TaskList：不是聊天，是共享任务板

TaskList 解决的是“团队现在有哪些工作、谁负责、做到什么状态、哪些任务被阻塞”。它不是用来传一句自然语言消息的，而是用来把项目拆成可追踪任务。

  • TaskCreate：创建任务。
  • TaskList：查看任务列表。
  • TaskUpdate：更新 owner、status、blockedBy 等。
  • TaskGet：读取某个任务详情。

源码里 Team 和 TaskList 是 1:1：TeamCreate 创建 team 时，也会创建对应任务目录，类似 ~/.claude/tasks/{team}/。

2. Mailbox：不是模型工具，是底层消息队列/收件箱

Mailbox 是文件级消息存储。每个 agent name 有自己的 inbox 文件：

~/.claude/teams/{team_name}/inboxes/{agent_name}.json

writeToMailbox() 把消息写进去，readMailbox() 读出来，markMessageAsReadByIndex() 标记已读。为了防止多个 agent 同时写入冲突，它还用了 lockfile。

所以 Mailbox 更像“底层消息中间件/队列”，模型通常不会直接调用它，而是通过工具或运行时逻辑间接使用。

3. SendMessage：模型可调用的发消息工具

SendMessage 是 agent 在对话里真正调用的通信工具。模型想给另一个 teammate 说话时，应该调用：

SendMessage({
  to: "tester",
  summary: "Ask test status",
  message: "你现在测试进度如何？需要我提供哪些文件？"
})

SendMessage 的实现会根据目标类型路由：如果是 team teammate，就写入对方 Mailbox；如果是 in-process local agent，就可能写入 pendingUserMessages；如果是 broadcast，就给多个收件人写 mailbox。

4. 三者的关系：工具入口、消息通道、任务状态

可以这样理解：

  • SendMessage：“我要发一条消息”这个动作。
  • Mailbox：“这条消息放在哪里、怎么被对方取走”。
  • TaskList：“这件事是否成为团队长期跟踪的工作项”。

如果只是问 tester 一句话，用 SendMessage；如果要把“补充登录测试”正式分配给 tester，用 TaskCreate/TaskUpdate；SendMessage 发出的消息底层通常落到 Mailbox。

5. 具体案例：leader 分配测试任务

假设 leader 想让 tester 测登录模块，合理流程是：

TaskCreate({
  subject: "测试登录模块",
  description: "覆盖正常登录、密码错误、token 过期三种场景"
})

TaskUpdate({
  taskId: "3",
  owner: "tester",
  status: "pending"
})

SendMessage({
  to: "tester",
  summary: "Assigned login tests",
  message: "我把 task #3 分给你了，请先看 TaskList，然后开始测试登录模块。"
})

这里 TaskList 负责“任务事实”，SendMessage 负责“提醒/说明”，Mailbox 负责“把提醒投递给 tester”。

6. 具体案例：tester 完成后汇报

tester 完成测试后，不应该只发一句“我好了”。更规范的做法是：

TaskUpdate({
  taskId: "3",
  status: "completed"
})

SendMessage({
  to: "team-lead",
  summary: "Login tests passed",
  message: "task #3 已完成。正常登录、密码错误、token 过期都通过；发现一个日志文案问题，已记录在 task #5。"
})

TaskUpdate 让团队状态可追踪；SendMessage 让 leader 立即知道结果；Mailbox 让这条消息异步进入 leader 的上下文。

7. 什么时候不用 TaskList，只用 SendMessage

如果只是短消息、澄清、状态问询、代码位置提示，不需要创建任务。例如：

  • “你正在改哪个文件？”
  • “我准备动 src/auth，你别同时改这个目录。”
  • “这个错误日志你见过吗？”

这些是即时通信，用 SendMessage 就够了。它们不需要进入长期任务板。

8. 什么时候必须用 TaskList

如果事情需要分配、排优先级、标记完成、表达依赖关系，就应该用 TaskList。例如：

  • 一个大功能拆成 frontend/backend/test/docs。
  • 任务 B 必须等任务 A 完成。
  • leader 需要知道谁负责什么。
  • teammate idle 后需要自动找下一个可领取任务。

TaskList 的价值是让团队协作不依赖“大家记得聊天内容”，而是有结构化状态。

9. Mailbox 为什么不能直接替代 TaskList

Mailbox 只保存消息，它不知道任务是否完成、owner 是谁、blockedBy 是什么。你当然可以在消息里写“你负责登录测试”，但系统无法稳定查询、排序、领取、更新这个状态。

TaskList 是结构化协作状态；Mailbox 是非结构化消息通道。二者解决的问题不同。

10. SendMessage 为什么不能直接等同于 Mailbox

SendMessage 是工具层 API，负责校验 input、处理 summary、广播、结构化消息、in-process agent 路由、bridge/UDS 路由等。Mailbox 只是其中一种落地通道。

所以准确说：SendMessage 调用后，很多 team 消息会写入 Mailbox；但 SendMessage 本身不是 Mailbox。

三者关系心智模型：

SendMessage = 发消息动作
  输入：to / summary / message
  作用：把模型意图路由成通信事件
  底层：可能写 mailbox，也可能写 in-process pending queue

Mailbox = 消息投递/收件箱
  存储：~/.claude/teams/{team}/inboxes/{agent}.json
  作用：异步保存 teammate 消息
  输出：被读出后变成  注入上下文

TaskList = 团队任务状态板
  存储：~/.claude/tasks/{team}/
  作用：记录 task、owner、status、blockedBy
  用途：任务拆分、领取、追踪、完成、阻塞管理

最佳实践：
  分配工作：TaskCreate/TaskUpdate + SendMessage 通知
  追踪状态：TaskList/TaskGet
  即时沟通：SendMessage
  底层投递：Mailbox
最关键的区别：TaskList 管“事”，SendMessage 管“说话”，Mailbox 管“消息怎么送到”。 一个成熟的 Agent Team 工作流通常三者都用：任务状态进 TaskList，沟通提醒走 SendMessage，异步投递由 Mailbox 承担。
