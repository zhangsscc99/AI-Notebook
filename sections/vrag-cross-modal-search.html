VRAG 可以文搜图、图搜文、图搜图吗

要分清模型能力和当前 API 实现。VRAG 使用的多模态 embedding 模型理论上可以把文本、图片、视频放进同一向量空间；但当前 SearchEngine.search() 暴露出来的查询入口主要是文本 query。

文搜图：支持

这是当前 demo 的主路径。用户问题或模型生成的搜索词是文本，search() 把文本 query 编成向量；如果 corpus 里是图片，就能返回图片记录。VRAG demo 正是用文本 <search> 召回图片。

文搜视频 / 文搜文本：也支持

build_index() 能把 .mp4 作为 type='video'，把 .txt/.md/.json 作为 type='text'。只要这些数据已入库，文本 query 可以搜到对应 modality 的记录。

图搜图：模型层可做，当前 API 没直接开放

Qwen3VLEmbedder.process() 支持 image 输入，GVE 的 processor 也能处理 image/video。但当前 SearchEngine.search() 对 Qwen3-VL 分支写的是 query_inputs = [{'text': query}]，对 GVE 分支也把 query 包成 text content。

图搜文：同理，当前未封装

如果你改造 search 接口，让它接收 image path/base64 并用同一 embedding 模型编码成 query vector，那么可以在同一个 FAISS index 里搜文本/图片/视频记录。但仓库当前 FastAPI /search 只读取 queries 字符串列表。

当前源码的查询路径：
POST /search {"queries": ["文本查询"], "top_k": 3}
  -> SearchEngine.search(queries, top_k)
  -> query_inputs = [{'text': query}]
  -> FAISS search
  -> 返回图片/文本/视频 metadata

如果要图搜图/图搜文，需要新增类似：
query_vec = embedder.process([{'image': image_path}], normalize=True)
index.search(query_vec, top_k)
结论：当前开箱即用是文搜多模态，尤其是文搜图。图搜图、图搜文在 embedding 模型层面有基础，但当前 search API 和 demo 没把 image query 作为入口封装出来。
