视觉 RAG 的切块怎么切，检索的时候怎么裁剪

视觉 RAG 的切块不能直接照搬文本 RAG。文本切的是 token/句子/段落；视觉 RAG 切的是页面、图片、视频片段、帧、局部区域。在 Alibaba VRAG 这个仓库里，默认工程做法比较清晰：索引阶段先按“视觉文件/页面/视频片段”作为召回单元；推理阶段再由模型输出 bbox，对召回图像做动态裁剪。

一句话：视觉 RAG 一般先做粗粒度视觉 chunk 用来检索，比如 PDF 每页一张图、视频每 60 秒一段、图片一张一个节点；检索回来后，如果细节太小，再让 VLM 预测 bbox 坐标，裁剪局部区域重新喂给模型看。

1. PDF 怎么切

VRAG 的 search_engine/corpus/pdf2images.py 做法很直接：把 PDF 每一页转成一张 JPEG，保存到 search_engine/corpus/image/。

也就是说，PDF 的第一层视觉 chunk 是“页”。这比提取文本更保真，因为图表、版式、截图、扫描件、公式、PPT 风格页面都还在图片里。

2. 图片怎么切

源码里 SearchEngine.build_index() 遍历输入目录，遇到 .jpg、.png、.jpeg 就作为一条 type='image' 的索引记录。

所以默认图片不是预先切成很多 patch，而是整图先入库。局部切割放到检索后的 agent 推理阶段处理。

3. 视频怎么切

search_engine/corpus/splitVideo.sh 用 ffmpeg/ffprobe 把长视频切成固定时长 chunk，默认 CHUNK_DURATION=60 秒。

构建索引时，视频条目会带 fps=1.0、max_frames=8、min_frames=32、max_pixels=200*28*28 等参数，让 embedding 模型以抽帧方式表达这个视频片段。

4. 检索单元是什么

检索时，query 先被编码成视觉/文本查询向量。FAISS 在索引里找 topK，返回的是页面图、整图、视频片段或文本记录，而不是直接返回某个小 bbox。

search_engine/search_engine.py 的 search() 对 GVE / Qwen3-VL embedding 都是先算 query vector，再 _index.search(..., top_k)。

VRAG 的裁剪发生在 agent 运行阶段，而不是 FAISS 检索阶段：

模型输出 <search> query </search>，demo/vrag_agent.py 调 POST /search 拿 top3 图片路径。
代码打开返回的图片，把原图保存到 self.image_raw，再通过 process_image() 缩放成 VLM 输入图，保存到 self.image_input。
VLM 看过图后，如果觉得局部太小或需要更清楚，会输出 <bbox>[x1, y1, x2, y2]</bbox>。
代码读取当前输入图尺寸 input_w/input_h 和原图尺寸 raw_w/raw_h，把模型给出的输入图坐标映射回原图坐标。
裁剪前额外加 pad_size = 56 像素边距，防止 bbox 太紧丢掉上下文。
用 PIL 的 crop() 得到局部图，再重新 process_image() 成 base64 image_url，作为新的 user message 喂给 VLM。
# demo/vrag_agent.py 的核心裁剪逻辑
bbox = json.loads(content)
input_w, input_h = self.image_input[-1].size
raw_w, raw_h = self.image_raw[-1].size

# 输入图坐标 -> 原图坐标
crop_region_bbox = (
    bbox[0] * raw_w / input_w,
    bbox[1] * raw_h / input_h,
    bbox[2] * raw_w / input_w,
    bbox[3] * raw_h / input_h,
)

# 加边距，裁剪，重新送给模型
pad_size = 56
crop_region_bbox = [
    max(crop_region_bbox[0] - pad_size, 0),
    max(crop_region_bbox[1] - pad_size, 0),
    min(crop_region_bbox[2] + pad_size, raw_w),
    min(crop_region_bbox[3] + pad_size, raw_h),
]
crop_region = self.image_raw[-1].crop(crop_region_bbox)

为什么不一开始就切很多 patch

预切很多 patch 会让索引量暴涨，而且 patch 脱离全局页面后容易失去语境。比如一个图表局部没有标题和坐标轴，模型可能看不懂。

为什么要动态裁剪

动态裁剪让模型先看全局，再按需要 zoom-in。它符合人类看视觉文档的方式：先定位页面，再放大表格、数字、图例或小字。

视觉 chunk 常见粒度

PDF：页、版面区域、图表区域；图片：整图、检测框、OCR block；视频：固定时长片段、镜头切分、关键帧、时间戳片段。

VRAG 当前源码的取舍

这个仓库默认更偏“粗检索 + 动态裁剪”：先召回页面/整图/视频片段，再由 VLM 用 bbox 做局部放大。它没有在入库前把每张图切成 dense patches 后逐 patch 检索。

最短总结：视觉 RAG 的第一层 chunk 是可检索视觉单元，第二层 chunk 是推理时动态裁剪出来的局部视野。在 VRAG 里，PDF 先切成页图，视频先切成固定时长片段，图片整图入库；检索后模型用 bbox 指挥裁剪，实现 coarse-to-fine 的视觉证据获取。
