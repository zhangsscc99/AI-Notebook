UML 类图入门题：老师 · 学生 · 课程

最经典的类图入门题，笔试也常拿它热身："画出老师、学生、课程的类图。"它看着简单，却能考出关联、多重性（重数）、继承、关联类四个知识点，以及"为什么不画聚合/组合"这类追问。下面分两步画：先 3 个类，再扩到 5 个。

先背一句：多重性的数字写在"对面"那一端。Teacher 1 ——— 0..* Course 读作"一个老师教 0..* 门课；一门课由 1 个老师教"。

Q：画出老师、学生、课程的类图，并说明关系

第一步：3 个类，只用关联 + 多重性

符号笔记：

  • 关联线可以不带箭头：不带箭头表示双向都能找到对方（老师能查自己的课，课也能查任课老师）。带箭头 A ——> B 表示只有 A 持有 B 的引用。拿不准就先画不带箭头的实线。
  • 多重性写法：1 恰好一个，0..1 零或一个，0..*（也可写 *）任意多个，1..* 至少一个。数字写在"被计数的那个类"旁边。
  • 怎么读：站在一个类上，看对面的数字。站在 Teacher 看 Course 那头写 0..*，意思是"一个老师对应 0 到多门课"；站在 Course 看 Teacher 那头写 1，意思是"一门课对应 1 个老师"。

第二步：5 个类，加上继承和关联类

两个自然的扩展：老师和学生都有姓名、编号，可以抽出父类 Person；"成绩"既不属于学生也不属于课程，它属于"某个学生选了某门课"这件事，要画成关联类 Enrollment。

新增符号：

  • 继承 = 实线 + 空心三角，三角指向父类：Teacher 和 Student 都"是一种" Person。公共的 name、id 上提到父类。
  • 抽象类 = 类名斜体，可以再补一个 {abstract} 标注，手写时斜体不明显，加上更保险。Person 抽象是因为系统里不存在"既不是老师也不是学生的纯 Person"。
  • # = protected：父类字段用 #，子类能直接访问，外部不能。这是 # 最典型的用法。
  • 关联类 = 一个普通类框，用虚线连到关联线中间（虚线不带箭头）。它表示"这条关系本身带属性"：grade 属于"张三选了数据结构"这件事，单独放在学生或课程里都不对。

类图翻译成代码（帮你判断关系）

abstract class Person {               // 斜体 = 抽象类
    protected String name;            // # protected
    protected String id;
}
class Teacher extends Person {        // 继承：实线空心三角
    private String title;
    private List<Course> courses;     // Teacher 1 —— 0..* Course
}
class Student extends Person {
    private String studentNo;
    private List<Enrollment> enrollments;
}
class Course {
    private Teacher teacher;          // 每门课恰好 1 个老师
    private List<Enrollment> enrollments;
}
class Enrollment {                    // 关联类 → 代码里落成"中间对象"
    private Student student;
    private Course course;
    private int grade;
}

对照一下就能发现：字段是 List 的那头，多重性就是 0..*；字段是单个对象的那头，就是 1（或 0..1）。多对多在代码里一般都会落成一个中间对象，和数据库里的选课表是同一个道理。

常见追问

面试官问答法要点
老师和课程为什么不画组合或聚合？两者生命周期独立：老师离职了课程还在（换人教），课程停开了老师还在。谁也不"拥有"谁，所以是普通关联。
学生和课程能画聚合吗？不建议。多对多、双方都能独立存在，没有"整体—部分"的含义。硬画聚合，面试官会追问"谁是整体"，很难答圆。
什么时候必须用关联类？当某个属性只属于"关系本身"时，比如成绩、选课学期。它放进 Student 或 Course 都会出问题：一个学生有很多门课的成绩，一门课有很多学生的成绩。
哪里会出现组合？比如再加一个"课时/章节"：Course ◆—— 1..* Lesson。课程删了，章节就没有意义了，同生共死，所以是组合。
一个人既是老师又是学生怎么办？（在职读博、助教）继承在这里会僵住：一个对象不能同时是 Teacher 和 Student。可以改成 Person 持有角色列表（Person 1 —— 0..* Role，Role 有 TeacherRole、StudentRole 两种实现）。这就是"组合优于继承"，是这题的进阶加分点。

默画自检清单

先画 3 个类框：每个只写 1–2 个关键字段，字段用 -，方法用 +。
连关联线并标多重性：老师—课程 1 对 0..*，学生—课程 0..* 对 0..*。检查数字是不是写在了"对面"那头。
加父类 Person：类名斜体，空心三角指向它，公共字段改成 # 后上提。
加关联类 Enrollment：虚线连到"学生—课程"那条线的中间，里面放 grade。
准备一句进阶："如果一个人既是老师又是学生，我会把继承改成角色组合。"
