怎么用 LangGraph 实现类似 Claude Code 的工作流编排

如果用 LangGraph 复刻 Claude Code 的工作流，不要把它设计成“一个大 agent prompt”。更稳的设计是把 Claude Code 里的隐式循环显式拆成一张有状态图：主会话状态、模型决策节点、工具执行节点、权限/hook 节点、子代理调度节点、压缩/恢复节点、最终汇总节点。

核心映射：Claude Code 的 QueryEngine + query loop + tool orchestration + AgentTool + coordinator，在 LangGraph 里可以映射成 StateGraph、conditional edges、tool executor node、checkpoint、interrupt/human approval、Send/Command 式并行分支和 supervisor/worker 子图。

1. State 是 QueryEngine

用一个 TypedDict/Pydantic state 保存 messages、cwd、工具权限、任务列表、worker 状态、transcript、token/预算、是否需要 compact、最后一次 tool_calls、错误和中断信号。LangGraph 的 checkpoint 用来替代 Claude Code transcript/resume 的一部分能力。

2. LLM node 是 query() 的模型调用

call_model 节点读取 state.messages 和 system context，调用带工具绑定的模型。如果返回 tool_calls，就走工具分支；如果没有 tool_calls，就进入 stop-hook/verification/final 分支。

3. Tool node 是 toolOrchestration

execute_tools 节点负责 schema 校验、权限判断、hook、真正执行工具、把 tool_result 追加回 messages。读类工具可以并行，写类工具按资源锁串行。

4. Supervisor 是 coordinator

复杂任务不要让一个 agent 顺序做完，而是让 supervisor 节点先拆任务，给 research / implementation / verification worker 子图发任务，再综合结果决定继续、重试、停止还是汇报。

一张比较接近 Claude Code 的 LangGraph 图可以这样设计：

START
  -> ingest_user_input
  -> load_context_and_memory
  -> maybe_compact
  -> supervisor_or_call_model
      -> if normal single-agent turn: call_model
      -> if complex task: plan_and_dispatch_workers

call_model
  -> if tool_calls: permission_and_hooks
  -> if final_answer: stop_hooks_or_finish

permission_and_hooks
  -> execute_tools
  -> append_tool_results
  -> maybe_compact
  -> call_model

plan_and_dispatch_workers
  -> research_worker(s) in parallel
  -> synthesize_findings
  -> implementation_worker
  -> verification_worker
  -> final_report

设计时最关键的是把“节点职责”切干净：

ingest_user_input：解析用户输入、slash command、文件附件、环境信息，写入 state.messages。
load_context_and_memory：加载项目说明、rules、memory、git status、MCP/tool registry，形成 system/user context。
maybe_compact：检查 token 预算；如果超限，调用 summary/compact 节点，把旧消息压缩成 compact boundary。
call_model：让模型决定下一步：回答、调用工具、请求子代理、进入 plan mode、或要求用户确认。
permission_and_hooks：对 tool call 做 schema 校验、policy 判断、pre-hook、人类审批 interrupt、输入改写。
execute_tools：按工具并发安全性执行；读操作可 fan-out，写操作按文件路径加锁。
worker_subgraph：每个 worker 是一个独立子图，有自己的 messages、tools、cwd、权限和 checkpoint。
synthesize/final：supervisor 综合 worker 输出，生成下一轮 worker prompt 或最终给用户的报告。

伪代码可以长这样：

from typing import TypedDict, Annotated
from langgraph.graph import StateGraph, START, END
from langgraph.graph.message import add_messages
from langgraph.types import Command, Send, interrupt

class AgentState(TypedDict):
    messages: Annotated[list, add_messages]
    cwd: str
    permission_mode: str
    tool_calls: list
    worker_results: list
    todos: list
    compact_needed: bool
    final: str | None

async def call_model(state: AgentState):
    response = await model_with_tools.ainvoke(state["messages"])
    return {"messages": [response], "tool_calls": response.tool_calls}

def route_after_model(state: AgentState):
    if state.get("tool_calls"):
        return "permission_and_hooks"
    return "stop_hooks_or_finish"

async def permission_and_hooks(state: AgentState):
    for call in state["tool_calls"]:
        if is_risky(call):
            decision = interrupt({"kind": "permission", "tool_call": call})
            if decision["action"] != "allow":
                return {"messages": [make_denial_result(call)]}
    return {}

async def execute_tools(state: AgentState):
    results = await run_read_tools_parallel_write_tools_serial(state["tool_calls"])
    return {"messages": results, "tool_calls": []}

def dispatch_workers(state: AgentState):
    tasks = decompose_task(state["messages"])
    return [Send("worker_subgraph", {"messages": [task.prompt], "cwd": state["cwd"]}) for task in tasks]

graph = StateGraph(AgentState)
graph.add_node("call_model", call_model)
graph.add_node("permission_and_hooks", permission_and_hooks)
graph.add_node("execute_tools", execute_tools)
graph.add_node("worker_subgraph", worker_graph)
graph.add_node("synthesize", synthesize_worker_results)

graph.add_edge(START, "call_model")
graph.add_conditional_edges("call_model", route_after_model)
graph.add_edge("permission_and_hooks", "execute_tools")
graph.add_edge("execute_tools", "call_model")
graph.add_edge("synthesize", END)
app = graph.compile(checkpointer=checkpointer)

权限怎么做

Claude Code 的权限系统在工具执行前。LangGraph 里应单独建 permission_and_hooks 节点：先走 policy/allowlist，再用 interrupt() 做 human-in-the-loop 审批，批准后把可能被用户修改的 input 写回 state。

并发怎么做

Claude Code 会并发跑 concurrency-safe 工具。LangGraph 里可以把只读工具拆成多个 Send 分支，或者在一个 executor 节点内部用 asyncio 并发；写工具则按 file_path / resource key 加锁串行。

子代理怎么做

每个 worker 用一个子图：自己的 state、system prompt、tool pool、checkpoint namespace。Supervisor 只拿 worker summary，不把所有原始工具输出塞回主上下文，避免污染主 agent。

恢复怎么做

用 checkpointer 保存每个 turn 的 state；长任务、worker、人工审批都可以恢复。对于工具副作用，要额外记录 tool_call_id、幂等键、文件快照或 patch，避免 resume 后重复执行危险写操作。

设计原则：LangGraph 负责“可控状态机”，LLM 只负责“决策下一步”。把权限、并发、子代理、压缩、恢复都放进显式节点，不要藏在 prompt 里；这样才接近 Claude Code 那种可恢复、可审计、可并行、可人工接管的工作流编排。
