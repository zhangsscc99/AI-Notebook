混元3D 是怎么确保生成的 3D 模型每个视角都一致的

这个问题的关键是：混元3D 不是从一张 2D 图分别生成正面图、侧面图、背面图，再把这些图硬拼成 3D。它先生成一个统一的 3D shape latent，再解码成一个真实 mesh。只要最后是同一个 mesh，从不同角度看天然就是同一个几何体。

一句话：几何一致性靠“单一 3D latent → 单一 mesh”保证；纹理一致性靠“同一个 mesh 渲染多视角 normal/position 条件 → 多视角纹理扩散 → bake 回同一个 UV texture”保证。2D 输入只提供可见面条件，不可见面由模型学到的 3D 先验补全。

先把“每个视角一致”拆成两个层面：

1. 几何一致性

几何一致性指从前、后、左、右看，模型的形状是同一个 3D 物体：头、身体、轮廓、厚度、拓扑不能互相矛盾。混元3D 通过 shape latent 和 ShapeVAE 生成统一 mesh，而不是逐视角生成多张深度图。

2. 纹理一致性

纹理一致性指颜色、图案、材质在不同视角接缝处不要乱跳。混元3D-Paint 不是把六张图直接贴上去，而是把多视角生成结果投影、加权、融合到一个 UV texture 上。

几何阶段为什么能从 2D 图变成相对一致的 3D？源码链路是：

输入图片只是条件。prepare_image() 预处理图片，encode_cond() 用 conditioner 把图片编码成条件向量。图片不是输出空间本身，而是控制 shape latent 采样的条件。
初始化一个 3D shape latent。prepare_latents() 用 self.vae.latent_shape 创建随机 latent。这个 latent 是整个 3D 形状的隐空间表示，不是某一个视角。
DiT 在 latent 空间整体去噪。Hunyuan3DDiTFlowMatchingPipeline.__call__() 逐 timestep 调 self.model(latent_model_input, timestep, cond)，再由 scheduler 更新同一个 latents。
ShapeVAE 解码成统一空间场。ShapeVAE 里的 latents2mesh() 先做 volume decoding 得到 grid_logits，再做 surface extraction 提取表面。
最终输出一个 mesh。mesh 是一个顶点/面片集合。你从任何角度看，看的都是同一套顶点和面，所以几何不会出现“正面一个物体、侧面另一个物体”的逐图矛盾。
几何一致性核心链路：
2D image
  -> conditioner 编码成条件
  -> DiT/flow matching 生成一个 shape latent
  -> ShapeVAE volume decoding
  -> surface extraction / marching cubes
  -> single mesh
  -> 任意视角渲染都来自同一个 mesh

纹理阶段为什么也尽量保持多视角一致？源码链路是：

先固定 mesh。Hunyuan3DPaintPipeline.__call__() 先对已经生成的 mesh 做 mesh_uv_wrap(mesh)，然后 self.render.load_mesh(mesh)。也就是说纹理阶段不再改变几何主体。
从同一个 mesh 渲染多视角结构条件。源码固定候选相机角度：0、90、180、270、顶视、底视，然后渲染 normal_maps 和 position_maps。这些图来自同一个 mesh，因此天然共享同一套 3D 坐标。
多视角纹理模型一起生成视角图。multiview_model 接收参考图片、normal/position 条件、camera_info，生成多个视角的纹理图。UNet 模块里有 attn_multiview 和 attn_refview，用于视角之间和参考图之间的信息交互。
投影回统一 UV。bake_from_multiview() 把每个视角的生成图通过 render.back_project() 投回 UV 空间，再按视角权重和 cos map 做融合。
补洞和保存。投影后没覆盖到的位置用 texture_inpaint() 做 UV inpaint，最后 self.render.set_texture(texture) 写回 mesh。

为什么 normal / position map 有用

normal map 告诉纹理模型这个视角下表面朝向，position map 告诉它像素对应的 3D 位置。这样模型生成侧面/背面纹理时，不是凭空画 2D 图，而是在同一个 3D 结构约束下画。

为什么要 bake 回 UV

如果只保留多张视角图，切换视角时可能接不上。bake 的意义是把多个视角的颜色融合成一张统一 UV 纹理；渲染时无论从哪个相机看，都从同一张贴图采样。

多视角 attention 解决什么

attn_multiview 让多个生成视角之间的信息能互相看见，减少“正面衣服是红色，侧面突然变蓝色”这类不一致；attn_refview 则把输入参考图的外观信息传给生成视角。

相机权重为什么不一样

配置里正面权重更高，侧面/背面/上下视角权重更低。直观理解：输入图通常更可靠地描述正面，背面和底部更多依赖模型先验，所以融合时不能让不可靠视角过度污染整体贴图。

但必须说清楚：单张 2D 图不可能数学上唯一确定 3D。比如一张正面玩偶图，背面长什么样、尾巴是否存在、衣服后面有没有图案，图片里没有信息。混元3D 的做法不是“知道真相”，而是用训练中学到的 3D 资产先验做合理补全。

它能保证什么

它能保证输出是一个统一 mesh，纹理也尽量合并到统一 UV；因此从任意视角渲染出来不会是彼此独立的几张图，而是同一个 3D 对象的不同投影。

它不能保证什么

它不能保证不可见背面一定和真实物体完全一致。对于单图不可见区域，模型只能根据类别、形状先验、对称性和参考图风格去猜。输入越遮挡、越非典型，背面幻觉风险越高。

最短记忆：一致性不是因为 2D 图包含所有视角，而是因为输出被约束成“同一个 3D 对象”。形状阶段输出单一 mesh；纹理阶段多视角生成只是中间步骤，最终仍 bake 到同一个 UV texture。
