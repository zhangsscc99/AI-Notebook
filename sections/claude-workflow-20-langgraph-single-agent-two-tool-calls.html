用 LangGraph 方式讲清楚 Claude Code 单 agent 模式：两到三轮思考、两次工具调用、GraphState、节点流转和条件边怎么走？

这个案例可以把 Claude Code 的 query.ts 主循环理解成一个 LangGraph 风格的循环图。核心是：模型节点每轮输出 assistant message；如果 assistant message 里有 tool_use，就走工具节点并回到模型节点；如果没有 tool_use，就进入收尾并结束。

先纠正一个关键点：你记得的“tool_use 作为循环终止条件”需要精确说：在 Claude Code 里，tool_use 是模型流式输出阶段的停止信号，也是agent 主循环继续的条件；真正让整个 agent 循环终止的是“本轮没有 tool_use”。源码注释也说不要完全相信 API 的 stop_reason === 'tool_use'，而是看流式过程中是否收集到了 toolUseBlocks。
START：用户输入进入 messages。
prepare_context 节点：做 compact / microcompact / systemPrompt / tools / MCP / skill 上下文准备。
model 节点第 1 轮：Claude 思考后输出第一个 tool_use，例如 Read。
条件边 has_tool_use=true：进入 tools 节点。
tools 节点第 1 次：执行 Read，生成对应 tool_result，追加到 messages。
回到 prepare_context / model 第 2 轮：模型看到 Read 结果，再输出第二个 tool_use，例如 Grep 或 Edit。
tools 节点第 2 次：执行第二个工具，生成第二个 tool_result。
model 第 3 轮：模型看到两次工具结果，输出最终回答；这次没有 tool_use。
条件边 has_tool_use=false：进入 stop_hooks / finalize，返回 completed。

1. 如果用 LangGraph 定义 GraphState

Claude Code 源码里的 State 大致可以映射成 LangGraph 的 GraphState：

type GraphState = {
  messages: Message[]
  toolUseContext: ToolUseContext
  assistantMessages: AssistantMessage[]
  toolUseBlocks: ToolUseBlock[]
  toolResults: UserMessage[]
  turnCount: number
  autoCompactTracking?: AutoCompactTrackingState
  maxOutputTokensRecoveryCount: number
  hasAttemptedReactiveCompact: boolean
  stopHookActive?: boolean
  transition?: { reason: string }
}

Claude Code 的真实 State 没有把 assistantMessages/toolUseBlocks/toolResults 长期存在 state 里，而是在每轮循环中作为局部变量收集；但用 LangGraph 讲解时，把它们放进 GraphState 更直观。

2. LangGraph 节点怎么拆

可以拆成这些节点：

  • accept_input：接收用户输入，形成 user message。
  • prepare_context：做 compact、snip、microcompact、system prompt、tool context。
  • call_model：调用 Claude，收集 assistant message 和 tool_use blocks。
  • run_tools：执行本轮所有 tool_use，产出 tool_result。
  • inject_runtime_attachments：注入 task notification、memory、skill discovery、file change 等。
  • finalize：stop hooks、usage、result、transcript 收尾。

Claude Code 的实现不是显式图框架，而是在 query.ts 的 while(true) 里按这个顺序手写状态机。

3. 条件边的核心：has_tool_use

最重要的条件边是：

call_model -> if toolUseBlocks.length > 0:
                run_tools
              else:
                finalize

Claude Code 源码里明确说：stop_reason === 'tool_use' 不可靠，所以真正判断本轮是否要进工具执行，是流式过程中是否收集到了 toolUseBlocks。这就是你说的“tool_use 控制循环”的准确版本。

4. 工具节点执行后为什么一定回到模型节点

工具调用本身不等于任务完成。工具只是给模型补充外部信息或执行动作。Claude Code 在工具执行后会把 assistantMessages + toolResults 追加回 messages，构造新的 next: State，然后 continue 回到 while 循环顶部。

LangGraph 里就是：

run_tools -> inject_runtime_attachments -> prepare_context -> call_model

所以两次工具调用如果分别发生在不同轮次里，本质就是这条循环边走了两次。

第 1 轮：模型决定先读文件

messages = [User("解释 auth bug 并修复")]

call_model 输出：
Assistant([
  Text("我先看相关文件"),
  ToolUse(id="toolu_1", name="Read", input={file_path:"src/auth.ts"})
])

toolUseBlocks.length = 1
条件边：call_model -> run_tools

这里 assistant 的 tool_use 让 API 这一轮生成停在工具调用处；但对 agent 图来说，它不是结束，而是进入工具节点。

第 1 次工具执行：Read 结果回填

run_tools 执行 Read
生成：
User([
  ToolResult(tool_use_id="toolu_1", content="auth.ts 文件内容...")
])

messages 变成：
[User任务, Assistant含Read工具调用, User含Read结果]

条件边：run_tools -> prepare_context -> call_model

注意 tool_result 必须和 tool_use_id 对齐。Claude Code 非常重视这个闭合，否则 Anthropic API 的消息结构会不合法。

第 2 轮：模型基于 Read 结果再调用工具

call_model 看到 auth.ts 内容后输出：
Assistant([
  Text("我发现 token 校验在 helper 里，再搜调用点"),
  ToolUse(id="toolu_2", name="Grep", input={pattern:"validateToken"})
])

toolUseBlocks.length = 1
条件边：call_model -> run_tools

这就是“两次工具调用分别在不同轮次里”的关键：第二次 tool_use 不是和第一次同批执行，而是在第一次 tool_result 回到上下文后，由模型重新判断出来的。

第 2 次工具执行：Grep 结果回填

run_tools 执行 Grep
生成：
User([
  ToolResult(tool_use_id="toolu_2", content="validateToken 出现在 login.ts 和 session.ts")
])

messages 追加第二个工具结果
turnCount++
继续下一轮模型调用

源码里这个继续动作对应 const next: State = { messages: [...messagesForQuery, ...assistantMessages, ...toolResults], turnCount: nextTurnCount, transition: { reason: 'next_turn' } }。

第 3 轮：没有 tool_use，循环结束

call_model 输出：
Assistant([
  Text("问题原因是 login.ts 使用旧 token 校验路径。修复建议如下...")
])

toolUseBlocks.length = 0
条件边：call_model -> finalize -> END

这时才是 agent 主循环完成。也就是说，Claude Code 的循环终止条件更准确地说是：模型这一轮没有产生 tool_use，并且 stop hooks / recovery / budget 检查没有要求继续。

对应的 LangGraph 伪代码

graph.addNode("prepare_context", prepareContext)
graph.addNode("call_model", callModel)
graph.addNode("run_tools", runTools)
graph.addNode("inject_attachments", injectAttachments)
graph.addNode("finalize", finalize)

graph.addEdge(START, "prepare_context")
graph.addEdge("prepare_context", "call_model")
graph.addConditionalEdges("call_model", state => {
  if (state.abort) return "finalize"
  if (state.toolUseBlocks.length > 0) return "run_tools"
  return "finalize"
})
graph.addEdge("run_tools", "inject_attachments")
graph.addConditionalEdges("inject_attachments", state => {
  if (state.maxTurnsExceeded) return "finalize"
  return "prepare_context"
})
graph.addEdge("finalize", END)
完整案例流转：

START
  -> accept_input
  -> prepare_context
  -> call_model round 1
       assistant emits Read tool_use
  -> has_tool_use=true
  -> run_tools round 1
       Read tool_result
  -> inject_runtime_attachments
  -> prepare_context
  -> call_model round 2
       assistant emits Grep tool_use
  -> has_tool_use=true
  -> run_tools round 2
       Grep tool_result
  -> inject_runtime_attachments
  -> prepare_context
  -> call_model round 3
       assistant emits final text, no tool_use
  -> has_tool_use=false
  -> stop_hooks / finalize
  -> END completed
最重要的心智模型：Claude Code 的单 agent 工作流不是“模型一次想完再执行”，而是“模型每轮只决定下一步；tool_use 触发工具节点；tool_result 回填后再让模型重新判断；直到某轮没有 tool_use 才结束”。 用 LangGraph 表达，就是一个围绕 has_tool_use 条件边反复回到 call_model 的循环图。
