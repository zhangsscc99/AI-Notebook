Claude Code 权限控制怎么做

Claude Code 的权限控制不是单个弹窗。它是一条工具执行前的闸门链路：schema 校验 → 工具 validateInput → PreToolUse hooks → hook permission decision → 工具 checkPermissions → 通用 allow/deny/ask 规则 → 交互/SDK/远程/多 agent 权限处理器 → tool.call。

一句话：模型只能提出 tool_use；真正能不能执行，由 Claude Code 本地权限系统、hooks、sandbox、用户确认和多 agent leader 共同决定。

1. 入口在 runToolUse

src/services/tools/toolExecution.ts 先按工具名查找工具，再执行 tool.inputSchema.safeParse()。参数结构错了，直接返回错误 tool_result，不会进入权限或真实执行。

schema 过了以后，才进入 checkPermissionsAndCallTool()。

2. Hooks 可以先拦截

PreToolUse hook 可以 block、修改 input，或返回 permission decision。resolveHookPermissionDecision() 会把 hook 决策并入权限判断。

这让团队可以配置“某些命令永远要问”“某些路径禁止写”“某些工具调用前先跑审计脚本”。

3. 工具有自己的权限逻辑

每个工具可以实现 checkPermissions()。Bash / PowerShell 权限尤其细，会分析子命令、路径、危险模式、是否适合沙箱，以及 allow/deny/ask 规则。

文件编辑工具也可以根据路径、是否已读、是否写到工作区外等条件做约束。

4. 通用权限规则决定 allow / deny / ask

src/utils/permissions/permissions.ts 处理通用 allow/deny/ask。显式 deny 通常优先于 allow；需要询问时，会交给 UI、SDK host、remote coordinator 或 swarm leader。

非交互/headless 场景通常更偏 fail-closed：不能问用户时，不会默默执行高风险动作。

一次 Bash 权限判断可以这样理解：

模型发出 Bash({ command: "rm -rf build" })。
runToolUse() 校验 JSON schema 和工具输入。
PreToolUse hooks 根据 Bash(rm *) 等 matcher 先检查或阻断。
BashTool.checkPermissions() 分析命令、路径、是否命中 deny/ask/allow、是否可沙箱执行。
如果需要 ask，interactive / SDK / coordinator / swarm worker handler 把请求交给人或 leader。
allow 才执行 tool.call()；deny 则返回错误 tool_result 给模型修正。

Permission mode

PermissionMode.ts 里能看到不同模式：默认模式、accept edits / plan 相关行为、auto mode、dontAsk 转 deny、bypass permissions 等。模式会改变 ask/allow/deny 的策略。

危险跳过不是无条件开放

--dangerously-skip-permissions 仍会被 setup 检查约束。源码里会避免在不安全环境里让用户随便绕过权限，例如非沙箱、联网、root/sudo 等组合。

沙箱会改变 Bash 的风险模型

如果命令会在 sandbox 内跑，并且没有显式 deny/ask 规则，sandbox.autoAllowBashIfSandboxed 可以减少弹窗。含义是允许命令执行，但把文件系统和网络边界交给 sandbox 限制。

多 agent 权限会转交 leader

Agent Team / swarm worker 自己不应该随意批准高风险动作。coordinatorHandler、swarmWorkerHandler、mailbox/poller 相关代码会把权限请求转给 leader 或用户侧处理。

tool_use
  → inputSchema.safeParse
  → tool.validateInput
  → run PreToolUse hooks
  → resolve hook permission decision
  → tool.checkPermissions
  → allow/deny/ask rules
  → interactive / SDK / coordinator / swarm handler
  → allowed: tool.call
  → denied: error tool_result returned to model
关键心智模型：Claude Code 权限控制是执行前闸门，不是事后审计。它把模型意图转成可验证工具调用，再用规则、hook、人类确认、沙箱和多 agent 转交机制决定是否放行。
