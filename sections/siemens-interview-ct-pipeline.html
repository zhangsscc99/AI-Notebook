系统设计题：CT 扫描数据链路（采集 → 传输 → 重建 → 存储）

面经里出现过"设计工业物联网平台处理每秒百万传感器数据"。换到 SSME CT 软件岗，最可能的变体就是这题：CT 探测器每秒产生数百 MB 到 GB 级原始数据，设计一套从采集到 PACS 的软件链路。按笔试顺序来：先画类图，再画流程图，最后讲系统设计思路和追问。

一句话主线：物理采集不能停、数据不能丢、病人不能重扫。所有设计决策都从这句话推出来。它和秒杀最大的区别是：秒杀可以拒绝请求，CT 不能拒绝数据。

Q：设计 CT 扫描数据从采集到存储的软件系统，画出类设计和处理流程

第零步：先问清需求（30 秒，很加分）

  • 扫描模式：轴扫还是螺旋？是否双源（西门子特色，数据量翻倍）？
  • 规模：探测器排数 × 通道数、每圈投影数、转速，用来估算数据率
  • 时延：要不要实时预览？完整重建多久内出图？
  • 保留：原始数据存多久？要不要支持事后重建？
  • 对接：图像发 PACS 还是工作站？断网时怎么办？
  • 合规：软件安全等级（IEC 62304 Class B/C）、审计与可追溯要求

量级估算

900 通道 × 64 排 × 2000 投影/圈 ÷ 0.3 s/圈 × 2 B ≈ 770 MB/s。换成 128 排或双源就是 1.5 GB/s 以上，一次 10 秒螺旋扫描会产生约 8–15 GB 原始数据（这是示意量级，不是某个具体型号的参数）。

这组数字直接决定架构：千兆网卡只有约 120 MB/s，扛不住，所以采集到重建要走专用高速链路；内存能缓冲一次扫描，但必须边收边处理，再用本地高速盘兜底。

第一部分：类图（分三块，每块不超过 5 个类）

按数据流切成三块：采集与缓冲 → 处理与重建 → 输出与连接。笔试时可以画在一张图上，这里拆开是为了逐块学符号。

① 采集与缓冲：生产者-消费者

符号笔记：

  • ScanController → AcquisitionSource（实线箭头 = 关联）：字段 - source 长期持有，而且持有的是接口。这就是依赖倒置：测试时换成 SimulatedSource 回放录制数据，不用真开 X 射线。
  • DetectorDAS ⇢▷ AcquisitionSource（虚线空心三角 = 实现）：三角指向接口。
  • RawDataBuffer ◇— ProjectionFrame（空心菱形 = 聚合）：缓冲只是暂存帧，帧被消费者取走后还会继续存在（落盘、重建），两者不是同生共死，所以不画组合。
  • AcquisitionSource ⇢ ProjectionFrame（虚线箭头 = 依赖）：ProjectionFrame 只出现在 readFrame() 的返回值里，不是字段。

② 处理与重建：管道 + 策略

符号笔记：

  • ReconPipeline → CorrectionStep，目标端标 1..*：一个管道持有多个有序的校正步骤（偏移/暗电流、增益/空气校准、射束硬化……）。加一种校正就是加一个实现类插进列表，现有代码不用改，符合开闭原则。这是管道/责任链模式。
  • Reconstructor 是策略接口：FBP（滤波反投影，快）和迭代重建（降噪、可降剂量、算力大）按扫描协议切换，这是策略模式。
  • 追问"steps 为什么不画组合"：校正步骤对象通常无状态，可以被多个管道复用，不跟某一个管道同生共死，所以画关联更准确。

③ 输出与连接管理：DICOM 关联

符号笔记：

  • ImageExporter ⇢ ImageVolume（虚线箭头 = 依赖）：volume 只是 export() 的参数，导出完就不再持有。
  • DicomStoreExporter ◆— DicomAssociation（实心菱形 = 组合）：连接由 exporter 创建、管理和销毁，exporter 没了连接也必须释放，两者同生共死。
  • DicomAssociation 的四个方法正好对应"连接建立与中断"这个考点：open（A-ASSOCIATE 协商建连）→ cStore（传图）→ release（A-RELEASE 正常释放），出异常时走 abort（A-ABORT 立即中断）。
  • ImageExporter 做成接口：以后要加云端归档或本地刻盘，加一个实现类就行。

第二部分：流程图（UML 活动图 · 泳道）

四条泳道对应四个部署单元。活动图符号：● 开始，◉ 结束，圆角矩形是动作，◇ 是判断（出边写 [条件]），粗横条是分叉/汇合，表示并行。

这张图里必须讲出来的三点：

链路异常就立即中止曝光（fail-safe）：数据已经收不住了，继续曝光只会让病人白白多吃剂量。这是医疗软件和互联网软件最本质的区别。
分叉后两路并行：原始数据落盘和重建流水线互不阻塞。原始数据留着，事后可以用不同卷积核或层厚重新重建，不用再扫一次病人。
收到 PACS 存储确认（Storage Commitment）才释放本地副本：失败就本地暂存加退避重试（store-and-forward），断网也不丢图。

第三部分：系统设计思路（8 个关键决策）

分层：采集层（C/C++，实时）→ 传输层（滑环 + 专用高速链路）→ 处理层（GPU 重建）→ 存储分发层（本地图像库 + DICOM/PACS）。层与层之间只通过缓冲或队列交互，每层可以单独扩展、单独测试。
生产者-消费者 + 环形缓冲：采集线程只做"收帧 → 拷进预分配槽位"，绝不做重计算。内存一次性预分配并复用，避免运行期 malloc 或 GC 停顿导致丢帧，这也是采集侧用 C/C++ 的原因。
流控不能靠"拒绝"：探测器不会因为下游慢就慢下来，所以要三层保护。(a) 扫描前做准入检查：磁盘空间、缓冲容量、重建机健康状态不达标就不允许开始曝光，把流控前移；(b) 扫描中做水位告警，缓冲快满时溢出到本地 NVMe；(c) 重建可以慢，采集不能丢。
并行：流水线并行（采集、校正、重建同时进行）加数据并行（按投影角度或切片分块，分给多块 GPU）。
双路径出图：实时预览走低分辨率快速重建，让技师马上确认定位和扫描质量；完整重建出高质量图像，可以用迭代重建。
可靠性：每帧带 CRC 和序号，能检测损坏和丢帧；看门狗监控各进程；链路异常时 fail-safe 停止曝光；关键状态持久化，崩溃后能从原始数据恢复重建。
连接与幂等：管理 DICOM 关联的生命周期（超时、C-ECHO 探活、异常时 A-ABORT）。每张图像的 SOP Instance UID 全局唯一，重发可以按 UID 去重，所以重试天然幂等。
可测试与合规：采集源做成接口，就能用录制数据回放做回归测试，再和 golden image 比对。医疗软件要遵循 IEC 62304（软件生命周期）和 ISO 14971（风险管理），需求、设计、测试要能互相追溯，正好呼应 JD 里的 "Siemens medical R&D process"。

和秒杀系统对比（面试时用来串联）

维度秒杀系统CT 数据链路
流量来源用户请求，难预测物理采集，速率由扫描协议决定，可提前算出
过载时限流、拒绝、排队，用户可以重试不能拒绝也不能丢，只能缓冲 + 落盘兜底
失败代价少卖或超卖，是钱的问题病人重扫要多吃辐射剂量，是安全问题
削峰手段Redis 预减 + MQ环形缓冲 + 本地高速盘 + 流水线
一致性关注点库存最终一致原始数据完整（CRC/序号），图像可追溯
主力语言Java（GC 停顿可接受）采集侧 C/C++（避免 GC 停顿）

串联话术："两道题都是'洪峰流量 vs 有限处理能力'。区别是秒杀可以说'不'，CT 不能，所以 CT 的流控要前移到扫描开始之前。"

追问预案

面试官追问答法要点
重建机挂了怎么办？原始数据已经落盘，采集不受影响；重建机恢复后从原始数据补做重建；预览可以降级到备用路径。
缓冲满了怎么办？先溢出到本地 NVMe；准入检查保证正常情况下不会满；真满了就告警，并按安全策略中止曝光，绝不静默丢帧。
为什么不用 Kafka？单机内 GB/s 级吞吐、毫秒级时延，进程内或共享内存的环形缓冲更合适；跨院区分发图像时才考虑消息系统。
PACS 断网三小时？store-and-forward：本地暂存 + 指数退避重试，本地磁盘设水位告警；网络恢复后补发，按 UID 去重。
这个系统怎么测？校正和重建算法做单元测试，和 golden image 比对；用 SimulatedSource 回放录制数据做集成测试；做故障注入（拔线、慢 PACS、磁盘写满）。
怎么扩展到光子计数 CT？数据多了能量维度，数据率更高。加一个 AcquisitionSource 新实现、几个新校正步骤和新的重建策略，上层编排代码不改。类图里留的接口就是为这种扩展准备的。

重要术语速查

术语一句话解释
DAS（Data Acquisition System）把探测器的模拟信号数字化的采集电子系统
滑环（Slip Ring）旋转机架和静止部分之间传电、传数据的部件
投影 / 正弦图（Sinogram）某个角度下所有探测器的读数叫一个投影；按角度堆起来就是正弦图，也就是重建的输入
预处理校正偏移（暗电流）、增益（空气校准）、对数变换、射束硬化校正等
FBP滤波反投影，经典的解析重建方法，速度快
迭代重建反复做"前投影 → 比较 → 修正"，降噪、可降剂量，但计算量大（西门子的 ADMIRE 属于这一类）
卷积核（Kernel）重建用的滤波参数，决定软组织窗、骨窗等不同观感；换 kernel 需要用原始数据重新重建
DICOM医学影像的文件格式和网络协议标准；C-STORE 传图，C-ECHO 测连通
PACS医院的影像归档与通信系统，图像最终存放的地方
Storage CommitmentPACS 确认"图像已安全归档"，之后设备端才能删除本地副本
IEC 62304医疗器械软件生命周期标准，按安全等级 A/B/C 要求不同的严格程度

现场答题顺序

澄清需求 + 量级估算（1–2 分钟）：先算出 GB/s 这个数，后面的设计都有依据。
画三块类图：先画接口，再连关系，字段只写有设计含义的。
画泳道流程图：重点标出 fail-safe、分叉并行、存储确认与重试。
主动讲 3 个关键决策：流控前移、保留原始数据、连接幂等。
收尾串联秒杀："两题本质相同，区别在于能不能说'不'。"
西门子相关加分点：西门子 CT 的双源（Dual Source）和光子计数（NAEOTOM Alpha）都意味着更高的数据率和更严的可靠性要求。被问"为什么选择西门子医疗"时可以接上这一点：想做数据量和可靠性要求都最高的那一类软件。
