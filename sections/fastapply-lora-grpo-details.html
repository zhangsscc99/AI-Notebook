LoRA 插在哪个架构之间，GRPO 训练精髓是什么

这次 FastApply 训练里，LoRA 不是“额外插一层大模型”，而是挂在 Qwen3 4B Transformer 里的关键线性投影上；GRPO 也不是普通监督学习，而是让同一个 prompt 采样出一组候选，用 reward 排出组内相对好坏，再更新模型概率。

LoRA 到底插在哪里

直观讲，LoRA 插在每个目标 Linear 的原始权重旁边，形成一条低秩旁路：

原始 Linear: y = W x
LoRA 后:    y = W x + scale · B(Ax)

所以它不是夹在两个 Transformer block 中间，而是嵌进 block 内部的投影层。

  • Attention 内部：通常对应 q_proj / k_proj / v_proj / o_proj。
  • MLP 内部：通常对应 gate_proj / up_proj / down_proj。
  • 输出层：本次 MinT 参数 train_unembed=True，所以输出到词表的 unembed / lm head 也参与 LoRA 更新。

本次对应的 MinT 配置

training_client = service_client.create_lora_training_client(
    base_model="Qwen/Qwen3-4B-Instruct-2507",
    rank=16,
    train_mlp=True,
    train_attn=True,
    train_unembed=True,
)

含义是：冻结 Qwen3 4B 大部分原始权重，只训练 rank=16 的低秩增量。这样显存、通信和优化状态都小很多，但仍能改变 attention 路由、MLP 变换和最终 token 分布。

采样。先把当前 LoRA 权重保存成 sampler，对同一个 source + patch prompt 采样一组候选更新代码。
打分。FastApply verifier 检查输出是否只有 <updated>、代码是否等于 gold、语法是否可解析、有没有多余文本。
组内归一。同组 reward 做中心化：advantage = reward - mean_reward。不是看绝对分，而是看这一组里谁更好。
更新概率。高 advantage 的轨迹提高概率，低 advantage 的轨迹降低概率；MinT 用 loss_fn="importance_sampling" 执行这一步。

GRPO 一轮采样几个

  • 常规建议：每个 prompt 一个 group，group size 通常 4–16，常见先用 4 或 8。
  • 样本越多，组内相对优势越稳定，但采样和训练成本越高。
  • 本次 tiny smoke 为了省时间：1 个 policy sample + 1 个 oracle rollout，最后形成 2 个 GRPO datums。
  • 之前试过 2 个 policy samples + oracle，Qwen3 4B 远程训练耗时明显变长，所以 smoke 版压缩了 group。

Datum 里最关键的字段

  • target_tokens：下一 token teacher-forcing 目标。
  • weights：prompt 部分为 0，只训练 response token。
  • logprobs：采样时旧策略给出的 token logprob，用于 importance ratio。
  • advantages：同一个 response 的 advantage 复制到它的每个生成 token 上。
loss_fn_inputs = {
  "target_tokens": full[1:],
  "weights": [0]*prompt + [1]*response,
  "logprobs": old_policy_logprobs,
  "advantages": centered_advantages,
}
训练精髓一句话：LoRA 决定“改哪些小参数”，GRPO 决定“哪些生成轨迹值得被提高概率”。 对 FastApply 来说，reward 不奖励会聊天，而奖励严格、可解析、无多余文本、能正确合并 patch 的代码输出。
