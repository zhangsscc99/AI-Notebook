Markdown memory 文件到底干啥

不是。Markdown memory 文件不只是 RAG 之后用来验证全文。它们是 OpenClaw memory 的源数据 / source of truth。RAG index、FTS、vector、QMD collection 都是从这些文件派生出来的缓存或检索结构。

1. 长期记忆的真实载体

MEMORY.md 存 curated long-term memory：稳定事实、偏好、长期决策、短摘要。memory/YYYY-MM-DD.md 存 daily notes：当天上下文、观察、会议/任务记录、较详细的临时知识。

2. 启动上下文来源

MEMORY.md 会作为主长期记忆在主私聊 session 启动时进入上下文，受 bootstrap budget 限制。daily memory 更适合按需检索，避免把所有日志都塞进每次 prompt。

3. 搜索索引的原材料

sync 会扫描这些 Markdown 文件，切成 chunks，写入 SQLite chunks、chunks_fts、可选 chunks_vec；如果用 QMD，就创建/更新 QMD collection。

4. memory_get 的原文来源

memory_search 返回的是片段和行号，memory_get 再按 path/from/lines 回到 Markdown 文件读原文。这确实用于核对 RAG 结果，但只是它的其中一个用途。

5. flush 的写入目标

compaction 前的 memory flush 会要求模型把重要信息追加到 memory/YYYY-MM-DD.md，不是写到向量库本身。向量库之后可以由 sync 重建。

6. 人类可审计和可编辑

因为是普通 Markdown，你可以直接打开、编辑、review、删掉错误记忆。索引只是服务检索；真正该信任和维护的是文件内容。

所以正确关系是：

Markdown memory files
  = durable source of truth
  -> sync/chunk
  -> FTS/vector/QMD index
  -> memory_search returns snippets
  -> memory_get reads original Markdown lines
  -> model answers with verified context
结论：Markdown 文件不是“RAG 后的全文验证附件”。它们是 OpenClaw 记忆的正本。RAG index 是从正本生成的检索视图；memory_get 是回到正本核对和读取更多上下文。
