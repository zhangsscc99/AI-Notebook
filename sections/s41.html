OpenClaw 记忆里的 QMD 到底是什么：技术、存储方式，还是云端服务

QMD 不是一个单纯的文件格式，也不是云端数据库。在 OpenClaw 里，QMD 是一个可选的 local-first search sidecar / memory backend：一个独立的本地搜索引擎二进制程序，OpenClaw 通过子进程调用它，让它负责建索引、embedding、BM25 / vector / rerank / query expansion 等高级检索能力。

一句话：builtin backend 是 OpenClaw 自己用 SQLite + FTS/vector 做记忆索引；QMD backend 是 OpenClaw 把记忆文件、额外目录、session transcript 交给本地 qmd 搜索引擎来索引和检索。

1. QMD 是一种“技术/组件”

它是独立项目和命令行程序，配置里默认命令是 qmd。OpenClaw 通过 spawn 跑 qmd update、qmd embed、qmd search / qmd query。所以它更像“本地搜索 sidecar”，不是 OpenClaw 内部一个普通函数。

2. QMD 也是一种“记忆后端”

OpenClaw 的 memory backend 有 builtin 和 qmd。当配置 memory.backend="qmd" 时，OpenClaw 创建 QmdMemoryManager，把 memory search 的索引和查询交给 QMD 这条链路。

3. QMD 也是本地索引存储方式

QMD 会维护自己的本地 index。OpenClaw 为每个 agent 建隔离目录：~/.openclaw/agents/<agentId>/qmd/，并设置 XDG_CONFIG_HOME、XDG_CACHE_HOME。源码里 index 路径是 xdg-cache/qmd/index.sqlite。

4. QMD 默认不是云端服务

文档明确把它称为 local-first。搜索、索引、rerank/query expansion 默认在本机 QMD 进程里做；模型可以是本地 GGUF，并由 QMD 运行时管理。首次使用可能需要下载模型，但这不等于把你的记忆发到云端检索。

QMD 在 OpenClaw 里的工作流可以按这个顺序理解：

配置启用。用户设置 memory.backend="qmd"，可选配置 memory.qmd.paths、memory.qmd.sessions.enabled、searchMode 等。
创建本地 QMD home。OpenClaw 在 agent 目录下创建 qmd/xdg-config、qmd/xdg-cache、qmd/sessions 等隔离路径。
注册 collections。QMD collection 可以对应 MEMORY.md、memory/、额外文档目录、导出的 session transcript。
更新索引。OpenClaw 在 boot / interval / watch / manual sync 时调用 qmd update；语义模式下还会调用 qmd embed。
执行检索。memory_search 进入 QMD manager，再按 searchMode 调 search、vsearch 或 query。
返回 OpenClaw 结果。QMD 返回 snippet、path、score，OpenClaw 再转换成统一的 MemorySearchResult 给 agent 使用。

QMD 比 builtin 强在哪

builtin 偏轻量：SQLite + FTS/vector。QMD 偏增强：BM25、vector search、reranking、query expansion、额外目录 collection、session transcript collection，并且可以用 MCP / mcporter 方式调用更完整的查询工具。

QMD 的 searchMode 是什么

默认 search 是 BM25/lexical 搜索，快；vsearch 是 vector 搜索；query 是更完整的 hybrid 路径，源码里会构造 lex + vec + hyde 子查询，适合更强召回但更重。

它到底存什么

它不替代原始记忆文件。MEMORY.md、memory/*.md、额外路径文件仍然在原位置；QMD 存的是这些内容的本地搜索索引、collection 元数据、embedding / rerank 所需状态。

如果 QMD 挂了怎么办

OpenClaw 有 fallback 设计。QMD binary 不存在、依赖坏掉、搜索失败时，会尝试回退到 builtin memory engine，避免 agent 因为 QMD 不可用而完全失去记忆检索。

{
  memory: {
    backend: "qmd",
    qmd: {
      paths: [{ name: "docs", path: "~/notes", pattern: "**/*.md" }],
      sessions: { enabled: true },
      searchMode: "search" // search | vsearch | query
    }
  }
}
所以回答你的问题：QMD 是技术组件 + 本地搜索引擎 + OpenClaw memory backend + 本地索引存储方案。它不是云端服务；默认依靠本地 qmd 进程和本地索引工作。只有模型首次下载、或你自己配置了外部模型/服务时，才可能涉及网络依赖。
