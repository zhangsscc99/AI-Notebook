Data-Juicer 涉及哪些数据清洗技术：按重要程度排序

Data-Juicer 涉及的数据清洗技术非常多，不能只理解成“删脏词、去重复”。从源码和 docs/Operators.md 看，它把清洗技术做成了 8 类算子：formatter、mapper、filter、deduplicator、selector、grouper、aggregator、pipeline。如果按大模型数据生产的重要程度排序，可以这样记。

一句话：Data-Juicer 的核心技术栈是：格式规范化 → 基础清洗 → 质量过滤 → 去重 → 语义/模型打分 → 多模态清洗 → Agent/RAG 专项清洗 → 分布式执行与可观测。前面决定数据能不能用，后面决定数据能不能规模化、精细化。

按重要程度排序的技术清单

1. 数据加载、格式化、Schema 统一

这是第一优先级。没有统一格式，后面所有清洗都跑不稳。Data-Juicer 支持 JSON/JSONL、CSV、TSV、Parquet、Text、本地目录、HuggingFace 数据集、远程数据等。核心在 formatter、DatasetBuilder、NestedDataset。

对应技术：字段映射、嵌套字段访问、数据源统一、压缩 JSON 支持、S3 I/O、schema validation。

2. 文本基础规范化与噪声删除

这是最常见的清洗层。包括 HTML 清理、版权声明删除、链接/邮箱/IP 清理、Unicode 修复、空白符归一化、繁简转换、特殊字符处理、长词删除、重复句删除、表格文本删除、参考文献删除等。

代表算子：clean_html_mapper、clean_copyright_mapper、clean_email_mapper、clean_links_mapper、fix_unicode_mapper、whitespace_normalization_mapper。

3. PII / 隐私 / 安全清洗

生产级数据一定要做。Data-Juicer 对 Agent 数据和通用文本都提供 PII 脱敏：路径、邮箱、密钥、ID、手机号、身份证、OpenID、URL、IP 等；还提供 LLM 嫌疑复核。

代表算子：pii_redaction_mapper、pii_llm_suspect_mapper、图像/视频 NSFW、水印、人脸模糊等安全相关算子。

4. 规则型质量过滤

这是最便宜、最稳的一层。通过长度、词数、行长、字符重复率、词重复率、特殊字符比例、停用词比例、字母数字比例、后缀、指定字段值等规则过滤低质量样本。

代表算子：text_length_filter、words_num_filter、token_num_filter、character_repetition_filter、word_repetition_filter、special_characters_filter。

5. 语言识别与可读性/困惑度过滤

大规模语料经常混语言、乱码、机器翻译、模板页。Data-Juicer 提供语言识别分数、perplexity、LLM perplexity 等质量信号，用来识别不可读或分布异常文本。

代表算子：language_id_score_filter、perplexity_filter、llm_perplexity_filter。

6. 去重：exact / line / MinHash / SimHash / 图像视频去重

去重对预训练和 SFT 都很关键。Data-Juicer 有文档级精确去重、行级去重、MinHash LSH 近重复、SimHash、Ray 分布式去重，以及图像/视频去重。

代表算子：document_deduplicator、document_line_deduplicator、document_minhash_deduplicator、document_simhash_deduplicator、ray_bts_minhash_deduplicator、image_deduplicator、video_deduplicator。

7. 语义相似度与相关性过滤

规则只能看表面，embedding/模型相似度能判断语义层面的重复、跑题、图文不匹配。Data-Juicer 支持文本相似度、文本对相似度、图文相似度、视频帧-文本相似度、任务相关性等。

代表算子：text_embd_similarity_filter、text_pair_similarity_filter、image_text_similarity_filter、image_pair_similarity_filter、video_frames_text_similarity_filter、llm_task_relevance_filter。

8. LLM/VLM 质量打分与改写校准

这是更贵但更智能的一层。用 LLM/VLM 做质量评分、难度评分、任务相关性判断、QA 校准、query/response 优化、结构化抽取、caption、tagging、文本分析。

代表算子：llm_quality_score_filter、llm_analysis_filter、llm_difficulty_score_filter、calibrate_qa_mapper、optimize_qa_mapper、image_captioning_mapper、video_captioning_from_vlm_mapper。

9. 多模态质量过滤

图像/视频数据要看尺寸、比例、分辨率、时长、清晰度、美学、NSFW、水印、OCR 面积、运动分数、图文一致性等。Data-Juicer 覆盖图像、音频、视频、多模态。

代表算子：image_aesthetics_filter、image_aspect_ratio_filter、image_watermark_filter、video_duration_filter、video_resolution_filter、video_motion_score_filter、video_ocr_area_ratio_filter。

10. 多模态转换、抽帧、分割、姿态、深度等增强处理

这类不只是过滤，而是把原始图像/视频加工成更可训练的数据：抽帧、按场景切分、caption、对象分割、深度估计、人体/手部/全身姿态、相机标定、去畸变、resize、去水印等。

代表算子：video_extract_frames_mapper、video_split_by_scene_mapper、video_depth_estimation_mapper、video_object_segmenting_mapper、video_camera_pose_mapper、video_undistort_mapper。

11. Agent 轨迹清洗与工具调用质量分析

这是项目里比较新也很有价值的一类。它把 Agent messages/choices 规范化，再统计 token、工具成功率、工具类型、任务相关性、轨迹连贯性、对话质量，最后发现 badcase。

代表算子：agent_dialog_normalize_mapper、tool_success_tagger_mapper、usage_counter_mapper、agent_trace_coherence_mapper、agent_tool_relevance_mapper、agent_bad_case_signal_mapper。

12. RAG / 知识抽取 / 数据分析

用于把数据变成可检索、可分析、可建知识图谱的结构：分块、实体抽取、关系抽取、事件抽取、关键词抽取、实体属性聚合、meta tag 合并等。

代表算子：text_chunk_mapper、extract_entity_relation_mapper、extract_event_mapper、extract_keyword_mapper、entity_attribute_aggregator、meta_tags_aggregator。

13. 样本选择、排序、分组、聚合

清洗后还要决定保留哪些样本、怎么平衡分布。Data-Juicer 有 selector、grouper、aggregator：可以按字段频率、top-k 分数、key 分组、批量汇总等方式组织数据。

代表算子：topk_specified_field_selector、frequency_specified_field_selector、key_value_grouper、nested_aggregator。

14. 数据增强与合成

Data-Juicer 也能做数据生成和增强，例如句子增强、QA 生成、图像扩散、prompt2prompt、文本 tag、LLM 抽取等。这不是“删数据”，而是改善或扩充训练数据。

代表算子：sentence_augmentation_mapper、generate_qa_from_text_mapper、generate_qa_from_examples_mapper、image_diffusion_mapper、sdxl_prompt2prompt_mapper。

15. 可观测、追踪、缓存、断点续跑

这不是清洗规则本身，但决定清洗工程能不能迭代。项目有 tracer 追踪每个 OP 对样本的影响，monitor 记录资源，cache/checkpoint 支持复用和失败恢复。

相关源码：core/tracer、core/monitor.py、CheckpointManager、NestedDataset.process()。

16. 分布式执行与性能优化

大规模数据清洗必须分布式。Data-Juicer 支持 default、ray、ray_partitioned 三类 executor，支持 OP fusion、adaptive batch size、OP 级 runtime env、自动并行度、GPU/CUDA 算子。

相关源码：DefaultExecutor、RayExecutor、PartitionedRayExecutor、fuse_operators、OPEnvManager。

如果按“训练数据收益”再压缩成优先级

第一优先级：格式统一、基础清洗、PII/安全、规则质量过滤、去重
第二优先级：语言/困惑度、语义相关性、LLM/VLM 质量评分、多模态质量过滤
第三优先级：Agent/RAG 专项清洗、数据增强、聚合选择、可观测与分布式工程化
真正落地时不要一上来就堆 LLM 评估。应该先用便宜稳定的规则和去重把大部分垃圾清掉，再用 embedding/LLM/VLM 对剩下的灰区样本做精细判断。
