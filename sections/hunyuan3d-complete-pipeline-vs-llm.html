完整 pipeline 是什么，和 LLM 最不一样的地方在哪里

混元3D 的完整 pipeline 不是“模型直接吐出一个 3D 文件”。它更像一条多阶段生成流水线：先把 2D 图片变成条件特征，再在 3D shape latent 空间做 flow matching 采样，然后把 latent 解码成 mesh，最后可选做 UV 和纹理生成，导出 GLB。

一句话：LLM 的 pipeline 是“文本 token → 下一个 token → 拼接文本”；混元3D 是“图片条件 → 3D latent 迭代去噪 → ShapeVAE 解码 → volume/surface extraction → mesh → 多视角纹理 → UV bake → GLB”。核心差异是：LLM 输出离散 token，混元3D 输出连续 3D latent，并依赖后处理组件把 latent 变成真实 3D 资产。

完整推理 pipeline 可以按 9 步记：

输入图片。用户给一张 RGBA/RGB 物体图。demo 里如果是 RGB，会先用 BackgroundRemover 去背景，减少背景对 3D 主体的干扰。
图片预处理。image_processor / prepare_image() 把图片居中、缩放、转 tensor，得到模型能吃的 image 和 mask。
图片条件编码。conditioner 用 DINO/CLIP 这类 ViT-style image encoder 把 2D 图编码成 condition tokens。这里相当于“看懂输入图”，不是生成 3D。
初始化 3D shape latent 噪声。prepare_latents() 根据 ShapeVAE.latent_shape 创建随机 latent。这个 latent 是连续向量，不是文本 token，也不是 mesh 顶点。
DiT / flow matching 采样。Hunyuan3DDiTFlowMatchingPipeline 按 timesteps 循环：把 noisy latent、timestep、image condition 送入 Hunyuan3DDiT，模型预测 velocity/noise 更新方向。
Scheduler 更新 latent。每一步用 scheduler.step(noise_pred, t, latents) 更新整块 shape latent。采样结束后得到比较干净的 3D shape latent。
ShapeVAE 解码。_export() 里先做 self.vae(latents)，把 latent 变成几何 decoder 可用的隐表示。
volume decoder + surface extractor。latents2mesh() 先得到 volume grid logits，再通过 marching cubes / surface extractor 抽取三角面，输出 trimesh。
纹理阶段和导出。如果启用 Paint pipeline，会给 mesh 做 UV wrap，渲染多视角 normal/position，生成多视角纹理并 bake 回 UV，最后导出 demo.glb。
Hunyuan3D 推理主链路：
image
  -> image_processor / mask
  -> DINO or CLIP conditioner
  -> random shape latent
  -> Hunyuan3D-DiT + scheduler 多步 flow matching
  -> clean shape latent
  -> ShapeVAE
  -> volume decoder
  -> surface extractor / marching cubes
  -> mesh
  -> optional Paint: multiview texture + UV bake
  -> GLB

和 LLM 最不一样的地方，可以按这张对照表记：

LLM：离散 token 自回归

LLM 输入 token ids，Transformer 输出词表 logits。采样器从词表里选一个 token，再把这个 token 追加到上下文里，继续预测下一个 token。

tokens -> Transformer -> vocab logits -> sample next token
输出空间：离散词表
循环方式：一个 token 一个 token 往后接

混元3D：连续 latent 迭代去噪

混元3D 输入的是 noisy shape latent，不输出词表概率，而是输出同形状的连续向量，用来更新整个 3D latent。

noisy latent + timestep + image condition
  -> DiT -> velocity/noise prediction
  -> scheduler updates whole latent
输出空间：连续 3D shape latent
循环方式：整块 latent 多步 refinement

差异 1：输入不是纯文本上下文

LLM 的核心输入是文本 token 序列；混元3D 的核心输入是 2D 图片条件 + 当前 3D latent + timestep。图片 encoder 只是条件入口，真正生成发生在 shape latent 空间。

差异 2：模型输出不是最终资产

LLM 输出 token 后，人可以直接读；混元3D-DiT 输出的 latent 更新量不能直接打开。必须经过 scheduler、VAE、volume decoder、surface extractor 才能变成 mesh。

差异 3：没有“下一个顶点”生成

它不是 autoregressive 地生成第 1 个顶点、第 2 个顶点、第 3 个面片。它是在一个固定形状的 latent tensor 上反复去噪，最后一次性解码成完整 mesh。

差异 4：输出需要几何算法参与

LLM 后处理主要是 detokenize；混元3D 后处理包含 volume decoding、marching cubes / surface extraction、mesh simplification/cleanup、UV baking、纹理 inpaint，这些都是非 LLM 式的几何/图形组件。

源码上对应的关键组件：

Conditioner

hy3dgen/shapegen/models/conditioner.py 里的 CLIPImageEncoder / DinoImageEncoder 把输入图片转成 condition tokens。

Hunyuan3DDiT

hunyuan3ddit.py 里的 Hunyuan3DDiT.forward() 处理 latent、timestep、contexts，最后 final_layer 输出 latent 更新预测。

ShapeVAE

ShapeVAE 负责 3D latent 和几何表征之间的转换。它不是语言模型 head，而是 3D 几何 decoder 的入口。

Paint pipeline

Hunyuan3DPaintPipeline 对 mesh 做 UV、渲染多视角结构图、多视角纹理生成、back project 和 bake，最终给 mesh 贴图。

最短总结：混元3D 的完整 pipeline 是生成模型 + 几何解码器 + 图形渲染/纹理系统的组合。它和 LLM 最大不同不是“输入是不是图片”，而是输出机制：LLM 的输出头接词表；混元3D 的 DiT 输出连续 latent 更新量，最终 3D 文件由 VAE、surface extraction 和 texture baking 这些组件共同产出。
