每次记忆检索全流程

一次完整的“记忆检索”通常不是单个动作，而是 memory_search 和 memory_get 的组合。

工具可用性检查：memory-core 注册工具时，会确认当前 agent 配置里 memorySearch 没被禁用。
模型先调用 memory_search，传入自然语言 query，例如“之前我们怎么配置 QMD”。
系统拿到 active memory manager。如果 backend 是 QMD，就走 QMD manager；否则走 builtin SQLite manager。
如果索引为空，先强制 sync({ reason: "search", force: true })，把磁盘文件建成可搜索索引。
执行 preflight：空 query 或无索引内容直接停止，避免无意义 provider 初始化和查询。
如果可以搜索，初始化 embedding provider，然后并行/组合执行 FTS keyword search 和 vector search。
把 keyword 和 vector 结果做 hybrid merge，应用 minScore、maxResults、MMR、temporal decay 等策略。
工具返回候选片段，包括 path、startLine、endLine、score、snippet、source。
模型再用 memory_get 按 path/from/lines 读取原文，避免只凭 snippet 回答。

所以实际链路可以理解为：

user question
  -> memory_search(query)
  -> manager.search()
  -> sync if needed
  -> preflight
  -> FTS + vector retrieval
  -> hybrid merge
  -> search results
  -> memory_get(path, from, lines)
  -> exact excerpt
  -> answer with grounded context
RAG 通常对应第 2 到第 8 步；而 OpenClaw 还额外强调第 9 步，也就是用 memory_get 回读原文，降低只看片段摘要造成的误判。
