Alibaba VRAG 项目概览

VRAG 是 Alibaba-NLP 开源的视觉/多模态 RAG 项目，源码已 clone 到服务器：/root/VRAG。它不是传统“文本 chunk + 文本 embedding + LLM 回答”的 RAG，而是面向图片、PDF 页面、视频帧、视觉文档的多模态检索增强推理框架。

一句话：VRAG 要解决的是“答案藏在视觉材料里”的问题：先用视觉 embedding + FAISS 建多模态索引，再让 VLM 通过 search、bbox crop/zoom、多轮思考逐步获取证据；进一步的 VRAG-RL 用 GRPO/verl 训练模型学会这种多轮视觉检索与裁剪策略。

1. 项目包含三条主线

README.md 里同时介绍了 VimRAG、VRAG 和 VRAG-RL。VimRAG 是更新的多模态 memory graph / DAG 推理框架；VRAG 是纯视觉 RAG agent；VRAG-RL 是训练 VLM 学会多轮视觉检索、裁剪和回答的强化学习框架。

2. 检索层：视觉 embedding + FAISS

search_engine/search_engine.py 负责建库和搜索。它支持 Alibaba-NLP/GVE-3B、GVE-7B、Qwen3-VL-Embedding-2B/8B，也能接 bge-m3 做文本向量。

索引用 faiss.IndexFlatIP，文档、图片、视频会被编码成向量，元数据写入 *_file_data_list.jsonl，索引写入 *_faiss_index.bin。

3. 服务层：FastAPI search engine

search_engine/search_engine_api.py 启动 /search 接口。请求传 queries 和 top_k，服务调用 engine.search() 返回候选视觉/文本材料。

如果传 vrag_ret=true，接口会把检索结果整理成 VRAG demo 需要的图片路径列表，方便 agent 把图片送回 VLM。

4. Demo 层：VRAG Agent

demo/vrag_agent.py 是经典 VRAG demo。它调用 OpenAI-compatible VLM 服务，提示模型必须先输出 <think>，然后在 <search>、<bbox>、<answer> 三种动作里选择。

当模型输出 <search> query </search>，代码会调用 search API 拿图片；当输出 <bbox>[x1,y1,x2,y2]</bbox>，代码会把上一张图按坐标裁剪并再次喂给模型，实现视觉 zoom-in。

从源码看，VRAG 的运行链路可以按下面理解：

准备语料。图片直接放进 search_engine/corpus/image/；PDF 用 search_engine/corpus/pdf2images.py 转成页面图片；视频可用 splitVideo.sh 切片。
构建索引。SearchEngine.build_index() 读取图片/文本/视频，调用 GVE 或 Qwen3-VL embedding 模型生成向量，写入 FAISS。
启动检索服务。search_engine_api.py 加载 embedding 模型和索引目录，暴露 POST /search。
启动推理模型。VRAG demo 用本地 vLLM 部署 Qwen2.5-VL-7B-VRAG 或 Qwen2.5-VL-7B-Instruct，VimRAG demo 可走 DashScope 的 Qwen API。
Agent 多轮行动。模型先思考；缺信息时 search；看到图片后可以 bbox 裁剪；证据足够时 answer。
返回答案和轨迹。Streamlit demo 会展示搜索图片、裁剪区域、推理过程；VimRAG 还会展示 DAG / memory graph。

VimRAG：DAG + 多模态记忆

demo/vimrag_agent.py 维护 action_graph 和 multimodal_memory。模型通过 add_search_node 增加搜索节点，通过 summarize_and_memorize 把检索结果压缩成高密度记忆，再用 add_answer_node 输出最终答案。

demo/vimrag_prompt.py 明确规定每轮只能添加一个节点，search 节点必须有唯一 ID、parent_ids 和 query，搜索后必须总结和记忆。

VRAG-RL：训练模型学会视觉检索动作

VRAG-RL/vrag_agent/generation.py 的主循环是 run_llm_loop()：Generation → Parse Action → Observation → Check Termination。它会解析模型输出的 search、bbox、answer，把检索结果或裁剪图像重新塞回上下文。

train_grpo_qwen2_5_vl_7b.sh 使用 verl.trainer.main_ppo，配置 algorithm.adv_estimator=grpo，并通过 reward model 给轨迹打分。

它和普通 RAG 的差异

普通 RAG 多数是“文本切块 → 文本召回 → 文本生成”。VRAG 是“视觉材料 → 视觉 embedding 召回 → VLM 看图推理 → 必要时裁剪局部区域”。关键能力不只是找文档，而是让模型在视觉证据上多轮定位细节。

工程依赖和运行成本

VRAG demo 本地模型路径需要较强 GPU，README 里提到 7B VRAG 模型通常用 A100 80G 级别部署；VimRAG demo 推荐 DashScope API，启动成本低。检索层还需要 embedding 模型、FAISS 索引和 FastAPI search server。

最短总结：VRAG = 面向视觉文档/图片/视频的 Agentic RAG。它把检索对象从文本 chunk 扩展到视觉内容，把 agent 动作从“查文本”扩展到“查图、看图、裁剪局部、继续看”，再用 VRAG-RL 训练模型把这些动作学成稳定策略。
