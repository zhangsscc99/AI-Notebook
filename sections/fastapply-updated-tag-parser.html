updated 标签是由 LLM 解析出来，还是规则解析出来

updated 标签是模型生成的，但解析是规则解析，不是 LLM 解析。 也就是说，LLM 负责按 prompt 输出 <updated>...</updated>；项目代码用正则/规则把标签里的内容抽出来。

规则解析位置

  • fastapply_pipeline/patching.py：extract_updated_tag
  • rl_master/agent/evaluation/extractors.py：extract_tagged_content
m = re.search(r"<updated>...</updated>", output)
candidate = m.group(1) if m else None

LLM 在哪里参与

LLM 参与的是“生成”和“judge fallback”：

  • 生成阶段：LLM 根据 source + patch 输出 updated 标签包裹的代码。
  • reward 阶段：先规则抽取，再 exact/similarity/syntax。
  • judge 阶段：rule exact 失败时，才可能用 LLM 判断 candidate 和 reference 是否语义等价。
LLM 输出原文。
正则抽取 updated 标签。
抽取成功：candidate = 标签内部代码。
抽取失败：tag_format=0，reward 会扣分，必要时走 fallback。
结论：不要把 updated 当成“LLM 自己解析”。它是 LLM 按协议生成 + 程序规则抽取。这样更稳定、可控、便宜，也避免每次抽标签还要再调用一个 LLM。
