源码里 ReAct 和 Plan-Solve 到底怎么实现的

JoyAgent 里 ReAct 和 Plan-Solve 不是两个外部框架，而是同一套自研 Java agent runtime 上的两种 handler。共同底座是 BaseAgent.run() 的循环、ReActAgent.step() 的 think() / act() 模板、LLM.askTool() 的 function calling、以及 ToolCollection.execute() 的工具执行。

一句话：ReAct = 一个执行器自己循环“想 → 调工具 → 看结果 → 再想”；Plan-Solve = 先用 PlanningAgent 拆计划，再用 ExecutorAgent 执行任务，执行结果再反馈给 PlanningAgent，直到 planner 返回 finish。

1. 共同底座：BaseAgent.run()

所有 agent 都继承 BaseAgent。它维护 name、systemPrompt、nextStepPrompt、availableTools、memory、llm、context、state、maxSteps、currentStep。

核心循环在 run(query)：先把 query 作为 USER message 写入 memory，然后 while 循环调用 step()，直到达到 maxSteps 或 state 变成 FINISHED。

BaseAgent.run(query)
  -> updateMemory(USER, query)
  -> while currentStep < maxSteps and state != FINISHED:
       currentStep++
       step()
  -> return last step result

2. ReActAgent：固定 think / act 模板

ReActAgent 是抽象类，只规定两件事：

  • think()：让模型思考下一步，通常产生 tool calls。
  • act()：执行这些 tool calls，并把结果写回 memory。

它的 step() 很短：先 think()，如果应该行动就 act()。所以 JoyAgent 的 ReAct 不是玄学，就是一个模板方法。

ReActAgent.step()
  -> shouldAct = think()
  -> if !shouldAct: return
  -> return act()

3. ReactImplAgent.think() 怎么做

ReactImplAgent 构造时读取配置里的 react system prompt、next step prompt、react model name，并把 context.getToolCollection() 设为 availableTools。

think() 会把当前 productFiles 格式化进 prompt，然后调用：

llm.askTool(
  context,
  memory.messages,
  systemMessage(systemPrompt),
  availableTools,
  ToolChoice.AUTO,
  ...
)

askTool 会把 ToolCollection 里的工具转成 OpenAI/Claude function calling schema，模型返回 content + tool_calls。

4. ReactImplAgent.act() 怎么做

如果 toolCalls 为空，说明模型不再需要工具，agent 设置 FINISHED，并返回最后一条 assistant 内容。

如果有工具调用，它会调用 executeTools(toolCalls) 并发执行，然后把每个工具结果作为 TOOL message 写入 memory。下一轮 think() 就能看到工具结果，继续决策。

ReactImplAgent.act()
  if toolCalls empty:
    state = FINISHED
    return final answer

  results = executeTools(toolCalls)
  for each result:
    memory.add(toolMessage(result))
  return joined results

5. ReactHandlerImpl：ReAct 模式外壳

ReactHandlerImpl.handle() 很直接：

  1. 创建 ReactImplAgent。
  2. 创建 SummaryAgent。
  3. 执行 executor.run(request.getQuery())。
  4. 用 SummaryAgent 根据 executor memory 汇总任务。
  5. 把 taskSummary 和 fileList 通过 printer 发送。

所以 ReAct 模式是“一个 agent 自己一路工具循环到底，然后总结”。

6. Plan-Solve 模式入口

PlanSolveHandlerImpl.handle() 是 Plan-Solve 的总控。它先做 handleSopRecall()，把相似 SOP 召回内容注入 sopPrompt，然后创建三个角色：

  • PlanningAgent：负责计划。
  • ExecutorAgent：负责执行任务。
  • SummaryAgent：负责最终汇总。

7. PlanningAgent 怎么创建/更新计划

PlanningAgent 也是 ReActAgent 的子类，但它的 availableTools 只添加了一个特殊工具：PlanningTool。

PlanningTool 支持四个命令：

  • create：创建 plan。
  • update：更新 steps。
  • mark_step：标记步骤状态。
  • finish：把计划置为完成。

Plan 对象保存 title、steps、stepStatus、notes，并能返回当前 in_progress 的 step。

8. ExecutorAgent 怎么执行任务

ExecutorAgent 和 ReactImplAgent 很像，也是 think/act 工具循环。但它使用 executor 的 prompt 和 model，并且在 run(request) 前会调用 generateDigitalEmployee(request)，为当前 task 生成工具对应的“数字员工”角色提示。

当 ExecutorAgent 没有 tool calls 时，它会 FINISHED，并可根据配置清理工具消息上下文，返回任务完成描述或最后内容。

9. Plan-Solve 的循环怎么串起来

核心循环在 PlanSolveHandlerImpl：

planningResult = planning.run(query)

while stepIdx <= maxStepNum:
  tasks = planningResult.split("<sep>")
  executorResult = run executor on task(s)
  planningResult = planning.run(executorResult)

  if planningResult == "finish":
    summary.summaryTaskResult(...)
    send result
    break

也就是说，planner 第一次根据用户 query 出计划和当前任务；executor 执行任务；执行结果再变成 planner 的下一轮输入。

10. 并行子任务怎么实现

如果 planningResult 被 <sep> 拆成多个 task，代码会创建多个 ExecutorAgent 副本，用 ThreadUtil.execute() 并发跑，用 CountDownLatch 等待全部结束。

并发完成后，把每个 slave executor 从 memoryIndex 之后新增的 message 合并回主 executor memory。这就是它的 fan-out / fan-in。

Handler 选择。AgentHandlerFactory 根据 support() 选择 ReactHandlerImpl 或 PlanSolveHandlerImpl。
ReAct 路径。创建 ReactImplAgent，循环 think → act，直到没有工具调用。
Plan-Solve 路径。创建 PlanningAgent、ExecutorAgent、SummaryAgent。
规划。PlanningAgent 只通过 PlanningTool 创建/更新/完成计划。
执行。ExecutorAgent 用完整工具集合执行当前 task；多个 task 可并发。
总结。SummaryAgent 读取 executor memory 和 productFiles，生成 taskSummary + fileList。
Source-level comparison

REACT implementation:
  ReactHandlerImpl.handle()
    -> new ReactImplAgent(context)
    -> executor.run(query)
       -> BaseAgent.run()
          -> ReActAgent.step()
             -> ReactImplAgent.think()
                -> LLM.askTool(... ToolCollection ...)
             -> ReactImplAgent.act()
                -> executeTools(toolCalls)
                -> memory.add(tool result)
    -> SummaryAgent.summaryTaskResult(...)
    -> printer.send("result", ...)

PLAN_SOLVE implementation:
  PlanSolveHandlerImpl.handle()
    -> handleSopRecall()
    -> new PlanningAgent(context)
    -> new ExecutorAgent(context)
    -> new SummaryAgent(context)
    -> planning.run(query)
       -> PlanningAgent uses PlanningTool only
       -> returns current task(s) or finish
    -> executor.run(task)
       -> ExecutorAgent uses ToolCollection
    -> planning.run(executorResult)
    -> repeat until finish / max step / error
    -> SummaryAgent.summaryTaskResult(...)
    -> printer.send("result", ...)
源码级结论：ReAct 是单执行器工具循环；Plan-Solve 是规划器和执行器的外层循环。两者底层都复用 BaseAgent.run()、ReActAgent.step()、LLM.askTool()、ToolCollection.execute()。区别在于：ReAct 直接用完整工具集合解决问题；Plan-Solve 先用 PlanningTool 管计划，再把具体 task 派给 ExecutorAgent。
