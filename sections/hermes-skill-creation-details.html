H5

Hermes Agent 具体怎么创建新 skills：五次工具调用、判断逻辑、生成细节

这里最容易误解的一点是：Hermes 不是在代码里写了一个简单的 if tool_call_count > 5: create_skill()。它有两套机制叠在一起：一套是前台模型被 prompt/schema 引导，自己判断要不要调用 skill_manage；另一套是后台 self-improvement review 根据运行轮次触发，复盘整段对话后更新 skill 库。

准确说：“5+ calls”主要是写在 prompt / tool schema 里的启发式规则，告诉模型什么情况值得沉淀 skill；真正代码里的自动触发计数是 _iters_since_skill，默认按 skills.creation_nudge_interval = 10 个模型循环触发后台复盘，而且它数的是 agent loop iteration，不是严格的单个工具调用数。

1. 执行任务时，Hermes 怎么“知道”用了多少工具

每次模型返回工具调用时，OpenAI-style 消息里会有 assistant_message.tool_calls。Hermes 会把这条 assistant message 追加到 messages，然后逐个执行工具，再把每个结果作为 role="tool" 的消息追加回去。

assistant message
  tool_calls: [read_file, rg, terminal, edit_file, terminal]

Hermes runtime
  -> append assistant(tool_calls)
  -> execute each tool call
  -> append tool result messages
  -> next model call sees the transcript

所以“用了多少工具”并不是凭空猜的：工具调用历史就在对话 transcript 里。模型本身也能看到前面出现过哪些 tool_calls 和 tool results。

2. “大于五次”到底是谁判断的

有两层判断：

  • 前台判断：SKILLS_GUIDANCE 明确写着：完成复杂任务、5+ tool calls、修复棘手错误、发现非平凡 workflow 后，用 skill_manage 保存方法。这里主要是模型根据 transcript 自己判断。
  • 工具 schema 判断：SKILL_MANAGE_SCHEMA 的 description 也写着：complex task succeeded (5+ calls)、errors overcome、user-corrected approach worked 等情况可以 create。
  • 后台触发：代码里还有 _iters_since_skill，每轮模型 API loop 递增，达到 skills.creation_nudge_interval 后启动后台 skill review。

所以不要把“5+ calls”理解成硬编码阈值。它更像写给模型的判断标准：任务已经不是一两步临时回答，而是有可复用流程了。

3. 代码里的自动计数实际数什么

在 run_agent.py 的主循环里，每次准备调用模型前会执行：

if self._skill_nudge_interval > 0 and "skill_manage" in self.valid_tool_names:
    self._iters_since_skill += 1

默认 _skill_nudge_interval = 10，也可以通过 skills.creation_nudge_interval 配置。任务结束时如果：

_iters_since_skill >= _skill_nudge_interval
and "skill_manage" in valid_tool_names

就会触发后台 review。注意：这里数的是模型循环轮次 / agent iteration，不是严格意义上的“工具调用个数”。一次 iteration 里可以有多个 tool calls，也可能没有工具调用。

4. 什么时候计数会清零

只要当前 agent 真正调用了 skill_manage，Hermes 就会把 _iters_since_skill 清零。原因很简单：既然已经做过 skill 创建或更新，就不需要马上再 nudging 一次。

if function_name == "skill_manage":
    self._iters_since_skill = 0

所以它的实际语义更像：距离上一次 skill 更新已经跑了多少 agent loop，而不是“本任务精确执行了多少个工具”。

5. 形成 skill 的内容从哪里来

skill 不是由某个固定模板自动抽取字段生成的，而是由模型读完整对话后综合出来。它能看到：

  • 用户原始目标是什么。
  • 执行过程中用了哪些工具。
  • 哪些命令成功、哪些失败。
  • 失败后怎么修正。
  • 最后哪条路径验证成功。
  • 用户纠正了哪些风格、流程或输出要求。

然后模型把这些压缩成一个可复用的 SKILL.md：触发条件、步骤、命令、坑点、验证方式。也就是说，形成 skill 的核心是LLM 复盘总结 + 结构化写文件。

6. 创建 skill 的真实落盘流程

当前台 agent 或后台 review agent 决定创建 skill 时，会调用：

skill_manage(
  action="create",
  name="class-level-skill-name",
  category="optional-category",
  content="---\nname: ...\ndescription: ...\n---\n\n# ..."
)

skill_manager_tool.py 收到后做这些事：

  1. 校验 name 是否安全：小写、数字、点、下划线、短横线。
  2. 校验 category 是否安全。
  3. 校验 SKILL.md frontmatter，必须有 name 和 description。
  4. 检查内容大小，避免过大。
  5. 检查是否已有同名 skill。
  6. 创建 ~/.hermes/skills/<name>/ 或 ~/.hermes/skills/<category>/<name>/。
  7. 用 atomic write 写入 SKILL.md。
  8. 可选执行安全扫描。
  9. 清空 skills prompt cache，让后续 prompt 能看到新 skill。

7. 后台 review 是怎么工作的

当主任务已经给用户返回最终答案后，Hermes 才启动后台 self-improvement review，避免抢占用户任务上下文。它会 fork 一个新的 AIAgent，只启用 memory 和 skills toolset，然后把刚才的 messages_snapshot 作为历史，让 review agent 复盘：

main agent finishes response
  -> if skill nudge trigger fired
  -> _spawn_background_review(messages_snapshot, review_skills=True)
  -> review agent reads transcript
  -> skills_list / skill_view 查现有 skill
  -> skill_manage patch/create/write_file
  -> user only sees compact summary

这层不是训练模型，而是一个“复盘代理”在任务结束后整理经验，直接写入共享的 skill 存储。

8. 新 skill 为什么要求 class-level

后台 review prompt 明确要求优先更新“当前加载过的 skill”或“已有 umbrella skill”，最后才创建新 skill，而且新 skill 必须是 class-level，不应该叫 fix-error-123-today 这种一次性名字。

原因是如果每个会话都创建一个窄 skill，skill 库会变成垃圾堆；正确做法是把一次任务的细节归到一个更大的能力类别里，比如：

  • vercel-deployment-debugging
  • python-package-release
  • frontend-responsive-layout-fixes
  • agent-sandbox-integration
前台：system prompt 和 tool schema 持续提醒模型，复杂任务 / 5+ calls / 难错 / 新 workflow 要考虑写 skill。
运行中：每次工具调用都进入 transcript；模型能看到自己做过什么、失败过什么、成功路径是什么。
如果模型当场判断值得沉淀，就直接调用 skill_manage(create/patch)。
如果前台没写，后台 _iters_since_skill 达到阈值后启动 review agent 复盘。
review agent 优先 patch 现有 skill；没有合适 umbrella 才 create 新 class-level skill。
skill_manage 校验、落盘、清 cache、记录 provenance / usage，下一次 prompt 里就能被发现和加载。
不要理解成：
  if tool_call_count > 5:
      create_skill()

更准确是：
  prompt/schema 给模型一个规则：
    复杂任务、5+ calls、难错、新 workflow => 应考虑沉淀 skill

  runtime 给系统一个后台触发器：
    每个 agent loop: _iters_since_skill += 1
    如果达到 skills.creation_nudge_interval 默认 10:
        任务结束后 fork review agent
        review agent 复盘 transcript
        skill_manage(patch/create/write_file)

  skill_manage 负责真实写文件：
    validate name/frontmatter/size
    mkdir ~/.hermes/skills/...
    atomic write SKILL.md
    clear skills prompt cache
    update usage/provenance
所以 Hermes 创建新 skills 的本质是：不是硬规则自动抽取，而是 prompt 触发的 LLM 经验复盘 + runtime 的后台复盘触发器 + skill_manage 的安全落盘工具。 “5+ tool calls”是判断任务复杂度的启发式信号；真正生成 skill 内容的是模型对这次任务轨迹的总结。
