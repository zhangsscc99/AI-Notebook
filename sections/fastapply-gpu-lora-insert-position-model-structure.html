不用 Tinker、用显卡训练时 LoRA 层插在模型结构哪里

如果不用 Tinker 远程训练，而是在自己显卡上用 Hugging Face + PEFT 训练，LoRA 不是“在模型外面再接一个新模型”，也不是“插在两个 Transformer block 中间”。它是替换/包裹模型内部指定的 Linear 线性层：原始大权重冻结，只在这些 Linear 旁边加一条低秩可训练旁路。

一句话：本地 GPU LoRA 的插入点由 target_modules 决定。当前 qwen_rlhf 配置把 LoRA 插到每层 Transformer 的 attention 投影 q_proj/k_proj/v_proj/o_proj 和 MLP 投影 gate_proj/up_proj/down_proj 上。

1. 源码里怎么指定插入位置

/root/OpenClaw/src/qwen_rlhf/scripts/train_sft.py 里用 PEFT：

peft_cfg = LoraConfig(
    r=lora_cfg["r"],
    lora_alpha=lora_cfg["alpha"],
    lora_dropout=lora_cfg["dropout"],
    target_modules=lora_cfg["target_modules"],
    bias="none",
    task_type="CAUSAL_LM",
)
model = get_peft_model(model, peft_cfg)

get_peft_model() 会遍历模型模块名，命中 target_modules 的 Linear 层就包一层 LoRA adapter。

2. 当前配置 target_modules

configs/sft_lora.yaml 写得很明确：

target_modules:
  - q_proj
  - k_proj
  - v_proj
  - o_proj
  - gate_proj
  - up_proj
  - down_proj

所以本地显卡 LoRA 训练主要改的是 attention 如何取信息、混合信息，以及 MLP 如何做非线性特征变换。

放到 Qwen / LLaMA 类 decoder-only 模型结构里，大致是这样：

token ids
  → embed_tokens
  → TransformerDecoderLayer × N
      → input_layernorm
      → self_attn
          q_proj   ← LoRA 插这里
          k_proj   ← LoRA 插这里
          v_proj   ← LoRA 插这里
          o_proj   ← LoRA 插这里
      → residual add
      → post_attention_layernorm
      → mlp
          gate_proj ← LoRA 插这里
          up_proj   ← LoRA 插这里
          down_proj ← LoRA 插这里
      → residual add
  → final norm
  → lm_head / unembed
  → vocab logits

3. 插到 attention 层意味着什么

q_proj 决定当前 token 用什么 query 去找信息；k_proj 决定其他 token 暴露什么 key；v_proj 决定被取回的信息内容；o_proj 决定多头 attention 结果怎么合回 hidden state。

对 FastApply 这种任务，attention LoRA 会影响模型如何对齐 source 里的 SEARCH 片段、patch 里的 REPLACE 片段、以及输出位置。

4. 插到 MLP 层意味着什么

Qwen/LLaMA 类 MLP 常见结构是 gated MLP：gate_proj 和 up_proj 把 hidden state 升维并门控，down_proj 再降回 hidden size。

MLP LoRA 更像在改变“每个 token 自身的特征变换”。对代码编辑任务，它会影响模型如何把“这段旧代码要改成那段新代码”的模式写进中间表示。

LoRA 在线性层内部的数学结构是：

原始 Linear:
  y = W x

加 LoRA 后:
  y = W x + scale · B(Ax)

其中：
  W: 原始大模型权重，冻结不训练
  A: in_features → r 的低秩矩阵，可训练
  B: r → out_features 的低秩矩阵，可训练
  r: rank，例如当前配置 r=16
  scale: lora_alpha / r
加载基座模型。AutoModelForCausalLM.from_pretrained(...) 加载 Qwen2.5-Coder-3B-Instruct。
可选 4bit 量化。BitsAndBytesConfig(load_in_4bit=True) 可以让冻结的基座权重用 4bit 存，省显存。
PEFT 包装 Linear。get_peft_model() 在命中的 projection Linear 旁边加 LoRA A/B 矩阵。
训练时只更新 LoRA。原始 W 不动，optimizer 只维护 LoRA 参数，所以显存和优化状态小很多。
保存 adapter。trainer.save_model() 保存的是 LoRA adapter 权重和配置；推理时再挂回基座模型，或 merge 到基座权重里。

本地 PEFT 和 Tinker 的差别

Tinker/MinT 的 create_lora_training_client(... train_attn=True, train_mlp=True, train_unembed=True) 是服务端封装：你告诉它训练 attention、MLP、unembed，它内部决定具体模块。

本地 PEFT 更显式：你直接写 target_modules。当前本地配置没有写 lm_head，所以默认不训练输出词表头。

如果也想训输出层怎么办

理论上可以把 lm_head 加进 target_modules，或者用 PEFT 的 modules_to_save 保存特定非 LoRA 模块。但这会增加显存和训练不稳定风险，尤其词表头很大。

对 FastApply 这类格式明确的代码编辑任务，先训 attention + MLP 通常是性价比最高的起点；只有发现输出格式/词分布明显卡住，再考虑动 lm_head。

最短记忆：显卡训练 LoRA = 冻结 Qwen 大模型，在每层 Transformer 的 q/k/v/o attention Linear 和 gate/up/down MLP Linear 旁边加小的 A/B 低秩矩阵。它不是新增一层完整网络，而是给原有线性变换加可训练增量。
