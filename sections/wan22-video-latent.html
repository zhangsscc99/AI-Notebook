视频 latent 是什么

视频 latent 可以理解成“被 VAE 压缩过的视频表示”。它不是 RGB 像素帧，而是一个更小的四维张量：[C, F_latent, H_latent, W_latent]。Wan2.2 真正生成的不是一帧帧像素，而是在这个 latent 空间里从随机噪声逐步去噪，最后再由 VAE 解码回视频帧。

一句话：视频 latent 是视频的压缩工作空间。扩散模型/DiT 负责把随机 latent 修成有语义、有运动、有画面的 latent；VAE 负责把 latent 还原成肉眼能看的像素视频。
原始视频太大。如果直接在像素空间生成 720P、几十到上百帧视频，token/像素数量巨大，Transformer 和扩散采样成本会非常高。
VAE 先定义压缩空间。配置里的 vae_stride 决定压缩比例。T2V/I2V A14B 是 (4,8,8)，表示时间约压 4 倍，空间高宽各压 8 倍；TI2V-5B 是 (4,16,16)，空间压缩更强。
推理时先算 target_shape。WanT2V.generate() 用 self.vae.model.z_dim、帧数、分辨率和 vae_stride 算出 latent shape。
初始 latent 是随机噪声。源码用 torch.randn(target_shape...) 创建噪声。这个噪声不是“乱码视频文件”，而是 latent 空间里的随机点。
WanModel 多步修改 latent。每个 timestep，WanModel 根据文本条件和当前 noisy latent 预测去噪方向，scheduler 更新 latent。
最后 decode 成视频。采样结束得到 x0，调用 self.vae.decode(x0) 才变成 [C, N, H, W] 视频帧张量，再保存为 mp4。

latent 的形状怎么来的

T2V 源码里直接写了：target_shape = (z_dim, (F - 1) // stride_t + 1, H // stride_h, W // stride_w)。所以帧数、分辨率越大，latent 仍然越大；但相比像素空间已经压缩很多。

为什么 channel 不是 3

RGB 视频通道是 3，但 latent channel 是 VAE 学出来的特征维度。Wan2.2 的 Wan2_2_VAE 默认 z_dim=48；A14B 使用的 Wan2.1 VAE 也有自己的 latent channel 配置。这里的 channel 表示压缩特征，不是颜色通道。

latent 里有没有“画面语义”

有，但不是人类可读的文本语义。latent 是 VAE 学出来的连续特征空间，能保留颜色、纹理、局部形状、时序运动等足够重建视频的信息。扩散模型学的是如何在这个空间里移动，让 latent 更符合 prompt。

latent 和 token 的关系

WanModel 还会把 latent 继续做 Conv3d patch_embedding，切成时空 patch token 送入 Transformer。也就是：像素视频先压成 latent，latent 再 patchify 成 Transformer token。

以 T2V 为例：
输入：prompt + 目标分辨率 + 帧数
1. 根据 vae_stride 算 latent 的 F/H/W
2. torch.randn 初始化 latent 噪声
3. WanModel + scheduler 在 latent 空间迭代去噪
4. VAE decode(latent)
5. save_video 写 mp4
所以不要把视频 latent 理解成“缓存的视频文件”。它更像一张高维草稿纸：模型不直接画每个像素，而是在压缩空间里先画结构、运动和细节的隐式表示，最后由 VAE 翻译成真实视频。
