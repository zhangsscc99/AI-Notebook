JEPA3

JEPA 世界模型和多模态大模型区别在哪：不就是 LLM 拼接多模态吗

不是。你的理解里“多模态大模型”通常指 视觉/音频 encoder + projector + LLM：把图像、视频、音频变成一串 embedding，接到语言模型上下文里，让 LLM 输出文本、工具调用或结构化答案。JEPA 世界模型不是这个范式。JEPA 的核心是把观测编码成世界状态 latent，再学习这个 latent 如何随时间和动作演化，最后用 latent 距离做规划。

一句话：多模态 LLM 的目标是“看懂多模态输入后用语言回答”；JEPA 的目标是“预测世界状态怎么变，并用预测结果选择动作”。一个主要输出语言 token，一个主要输出未来 state embedding。
输入不同。多模态 LLM 把图片/视频当成 prompt 条件；JEPA 把图片/视频/环境观测当成世界状态观测。
中间表示不同。MLLM 的视觉 embedding 最终服务于 LLM 的文本上下文；JEPA 的 encoder latent 就是世界状态本身，后续 predictor 直接在这个 state latent 上预测未来。
训练目标不同。MLLM 常见目标是 next-token / instruction tuning / preference learning；JEPA 的训练是 prediction_loss(predicted_latent, target_latent) + anti-collapse regularizer。
输出不同。MLLM 输出文本 token 或工具调用；JEPA 输出未来 latent state。源码里的 JEPA.unroll() 返回的是 predicted_states，不是词表 logits。
用途不同。MLLM 擅长语义解释、问答、任务拆解；JEPA 擅长把动作序列放进世界模型里想象未来，再用 CEM / MPPI 选低 cost 动作。

多模态大模型：接到语言模型

典型结构是 image/video encoder 先抽视觉特征，projector 把特征映射到 LLM hidden size，然后和文本 token 一起送进 LLM。最终优化和输出大多围绕语言：回答问题、描述图片、执行指令、调用工具。

image/video -> vision encoder -> projector
text prompt -> tokenizer
视觉 embedding + 文本 token -> LLM -> text/tool output

JEPA：预测世界 latent

源码里 JEPAbase 只有三件核心东西：encoder、action_encoder、predictor。训练时先 state = self.encoder(observations)，再预测未来 state。

observation -> encoder -> state latent
action -> action encoder
state latent + action -> predictor -> future latent

MLLM 看图后“说出来”

比如给一张房间图，MLLM 可以回答“门在左边，目标在右上角”。这很有用，但它默认不会在 latent 空间里模拟“如果向右走两步、再向上走三步会到哪里”。

JEPA 看图后“往前推演”

在 ac_video_jepa 里，模型根据当前图像状态和动作预测下一状态 latent。planner 再采样很多动作序列，用 JEPA 预测后果，选择最接近 goal latent 的动作。

源码层面最硬的证据在 eb_jepa/jepa.py：训练和推理围绕 state latent，而不是语言 token。

# jepa.py 简化理解
state = self.encoder(observations)
actions_encoded = self.action_encoder(actions)
predicted_states = self.predictor(state, actions_encoded)
loss = self.predcost(state, predicted_states) + self.regularizer(state, actions)

规划层面也能看出区别。GCAgent.set_goal() 会把目标图像编码成 goal_state_enc；ReprTargetDistMPCObjective 用 MSE 计算 predicted encoding 和 goal encoding 的距离；CEMPlanner / MPPIPlanner 采样动作序列，找 cost 低的动作。

当前观测 obs -> encode -> current latent
候选动作序列 a[1:H]
  -> JEPA unroll -> predicted future latents
  -> cost = MSE(predicted_latent, goal_latent)
  -> planner 选择最低 cost 的动作序列

为什么 JEPA 更像世界模型

因为它显式学习状态转移：当前状态 + 动作会导致什么未来状态。这个能力可以直接接规划器。世界模型的重点不是“会描述世界”，而是“能预测世界怎么演化”。

为什么 MLLM 不等于世界模型

MLLM 可以有很强的世界知识和视觉理解，但它的主训练目标通常不是低层状态动力学。它可以说“往左走会靠近门”，但不一定有一个可微的 latent dynamics 模型给 planner 调用。

JEPA 不生成漂亮内容

JEPA 不是文生图、文生视频模型。它通常不负责把 latent decode 成高保真图片，而是让 latent 足够可预测、可规划。视觉质量不是它的第一目标。

两者可以互补

一个更完整的 agent 可以让 MLLM 做高层语义理解和任务拆解，让 JEPA 做低层世界状态预测和动作规划。它们不是同一种模型，只是都可能处理多模态输入。

所以最短回答是：JEPA 不是“LLM 拼多模态 encoder”。它可以用视觉 encoder，但这个 encoder 的输出不是拿去让 LLM 说话，而是作为世界状态 latent；predictor 学 latent dynamics；planner 用 predicted latent 和 goal latent 的能量/距离来选动作。
