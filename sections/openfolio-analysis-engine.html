01

我们的分析引擎是什么，分析了哪些方面，分别用了什么信息和 API

这里的“我们的分析引擎”指 Openfolio / Portfolio Manager 里的投资组合 AI 分析链路。它不是一个单独的量化回测引擎，而是一个后端数据聚合 + 规则指标计算 + 大模型报告生成 + 历史报告保存 + AI Assistant 记忆更新的组合式分析引擎。

一句话：Openfolio 的分析引擎先从数据库和行情 API 拿到实时持仓、价格、盈亏、资产分布，再把这些结构化数据塞进专业投资分析 prompt，调用阿里云 DashScope 兼容 OpenAI 的 Chat Completions 接口生成报告；如果 AI 网络失败，则回退到本地 offline analysis。

1. 入口是什么

报告生成接口。POST /api/ai-analysis/portfolio，代码在 backend/routes/ai-analysis.js。它先调用 assetService.getPortfolioAssets(portfolioId)，拿到和 Dashboard 同源的资产数据。
AI 分析服务。实际使用 backend/services/aiAnalysisService-improved.js，负责生成 prompt、调用大模型、解析报告、提取 summary。
历史保存和助手记忆。报告生成后会通过 aiAnalysisHistoryService.saveAnalysisReport() 保存到数据库，并通过 aiIntegrationService.storeAnalysisResult() 更新 AI Assistant 的上下文。
聊天助手接口。POST /api/ai-analysis/chat 每次对话前会调用 buildRealtimePortfolioContext() 重新读取实时 portfolio 数据，避免 AI 只凭旧上下文回答。

2. 用的 AI 引擎是什么

大模型层用的是阿里云 DashScope 的 OpenAI-compatible API。后端从环境变量读取：

DASHSCOPE_API_KEY 或 AI_ALIYUN_API_KEY
AI_ALIYUN_BASE_URL 默认 https://dashscope.aliyuncs.com/compatible-mode/v1/
AI_ALIYUN_MODEL 默认 qwen-turbo-latest
endpoint = baseUrl + "chat/completions"

请求格式是标准 chat completions：model、messages、temperature: 0.7、top_p: 0.9、max_tokens: 3000。失败时会重试 3 次；网络错误、超时或连接失败后会进入 offline analysis，不让页面直接崩掉。

3. 分析了哪些方面

资产配置分析

看各资产类型的金额、占比、数量，判断股票、ETF、crypto、cash、bond、commodity 是否过度集中或配置不足。数据来自 assetsByType、totalValue、每类 totalValue/count。

风险评估

分析市场风险、行业风险、个股风险、集中度风险、波动风险。summary 里的备用风险等级用股票和 crypto 占比估算：风险资产占比越高，风险等级越高。

表现分析

看每个持仓的当前价格、平均成本、当前市值、总盈亏、收益率，识别表现好和表现差的资产。字段包括 quantity、avg_cost、current_price、gainLoss、gainLossPercent。

市场展望和个股分析

prompt 要求 AI 对每只股票分析财务表现、业务基本面、竞争地位、新闻发展、行业前景、管理层、估值、技术动量、公司特定风险、短长期展望。这里主要依赖模型自身知识和输入的持仓/价格数据，不是后端逐项抓新闻。

优化建议

要求输出买、卖、再平衡、仓位大小、风险管理建议，并考虑税务影响。后端会从 AI 文本里的 Optimization / Recommendations 章节提取最多 5 条建议作为 summary。

投资策略和评分

要求给 3-6 个月短期、1-3 年长期策略、再平衡频率、关键监控指标，并强制输出 OVERALL PORTFOLIO SCORE: XX/100。如果 AI 没给分，后端用分散度和最大单类占比做备用评分。

4. 分别用了什么信息

核心输入来自 MySQL 的 assets 和 portfolios 表，再由后端服务加工成分析需要的结构：

  • 组合级信息：portfolioId、totalValue、totalAssets、现金、资产类型分布。
  • 持仓级信息：symbol、name、asset_type、quantity、avg_cost、current_price、currency、portfolio_id。
  • 计算字段：currentValue、gainLoss、gainLossPercent、dailyChange、changePercent、每类资产 totalValue / totalGainLoss / count。
  • 报告历史：AI 报告保存到历史服务，后续可以按 reportId 读取旧报告，避免每次都重新生成。
  • AI Assistant 上下文：最新分析结果会缓存并注入聊天助手；聊天时还会实时读取 portfolio，减少“AI 不知道我当前持仓”的问题。

5. 用了哪些外部 API

阿里云 DashScope / Qwen

用途：生成投资组合分析报告和 AI chat 回复。接口：/compatible-mode/v1/chat/completions。默认模型：qwen-turbo-latest。

Nasdaq API

用途：美股/ETF quote、market movers、部分行情列表。服务文件：backend/services/nasdaqService.js，基础地址 https://api.nasdaq.com/api。

Stooq 免费行情

用途：当 Yahoo/Nasdaq 在服务器环境不可用时，作为股票历史和 quote 兜底。服务文件：backend/services/yahooFinance.js 里的 Stooq fallback。

腾讯港股行情

用途：港股数字代码兜底，例如 3690 转成 hk03690 获取价格和涨跌。服务文件：getHongKongStockPriceFromTencent()。

CoinGecko

用途：crypto 价格、24h change、volume、market cap。接口：https://api.coingecko.com/api/v3/simple/price。

Alpha Vantage

用途：市场涨跌榜、活跃交易榜。接口：https://www.alphavantage.co/query?function=TOP_GAINERS_LOSERS，key 来自 ALPHA_VANTAGE_API_KEY 或 demo。

6. 哪些不是它现在真正做的

当前分析引擎不是完整的机构级风控/回测系统。它没有真正做多因子模型、历史回测、VaR 实盘级计算、逐新闻源抓取、财报实时解析或真实税务模拟。页面上的 AI 报告主要是：用实时组合数据和行情数据作为输入，让 Qwen 生成专业解释和建议，再用简单规则提取 summary。

结论：Openfolio 的分析引擎是“数据聚合 + AI 报告”的产品型分析引擎。可靠的部分是持仓、价格、盈亏、资产分布这些结构化输入；需要谨慎看的部分是市场展望、个股基本面和新闻判断，因为这部分主要来自大模型生成，而不是后端单独接了实时新闻/财报 API。
