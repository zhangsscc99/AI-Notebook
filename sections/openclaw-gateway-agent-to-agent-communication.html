OpenClaw 的 agent 之间是什么通信方式

OpenClaw 里的 agent 之间不是直接开一个 socket 互相聊天，也不是共享同一个模型上下文。源码里更准确的说法是：agent-to-agent 通信是基于 Gateway / session tools 的跨 session 消息路由。每个 agent 仍然有自己的 agentId、workspace、auth、session store；通信时通过 sessions_send、sessions_spawn、sessions_yield、subagents 这些工具把消息或任务交给另一个 session。

一句话：OpenClaw agent 之间的通信方式是“工具调用驱动的跨 session 消息传递 + Gateway 调度 + transcript / task registry 记录”，不是模型之间的私有内存共享，也不是 P2P 网络通信。

1. 多 agent 先是隔离对象

docs/concepts/multi-agent.md 里把 agent 定义成完整作用域：workspace、agentDir、auth profiles、model registry、session store。默认每个 agent 的会话历史在 ~/.openclaw/agents/<agentId>/sessions 下分开。

所以“agent 之间通信”不是天然共享上下文；必须通过显式 session 工具或 Gateway 路由发生。

2. 同级 agent：sessions_send

sessions_send 是最像“发消息给另一个 agent”的工具。调用方给出 sessionKey 或 label，运行时解析目标 session，然后通过 Gateway 启动目标 session 的一次 agent run。

接收方看到的不是普通用户消息，而是带 provenance 的 inter-session data，例如提示里会标成 [Inter-session message ...]，transcript 里也会记录来源工具。

3. 父子 agent：sessions_spawn

sessions_spawn 用于创建子 agent / sub-agent。它会返回 runId 和 childSessionKey，典型 key 类似 agent:main:subagent:<uuid>。

子 agent 在自己的 session 里跑，完成后通过 task completion / announce path 把结果交回请求者。父 agent 如果要等结果，应该用 sessions_yield 结束当前 turn，等完成事件回来，而不是轮询。

4. 运行时通信，不是共享记忆

跨 agent 消息会进入目标 session 的 transcript，并通过 Gateway / agent runtime 触发模型回合。它不是把 A agent 的完整上下文复制到 B agent，除非 spawn 时显式选择 context: "fork"。

默认子 agent 可以是 isolated clean session；需要继承当前对话时才 fork。

最典型的同级 agent 通信流程：

Agent A 的模型决定要咨询 Agent B，发出 sessions_send tool call。
sessions_send-tool.ts 校验 target、visibility、agent-to-agent policy 和 sandbox 限制。
运行时把消息包装成 inter-session prompt，设置 sourceTool: "sessions_send"、sourceSessionKey、目标 sessionKey。
Gateway 用 startAgentRun / agent 路径唤起 Agent B 的 session。
Agent B 生成回复；如果调用方设置等待，结果可以 inline 返回给 Agent A。
如果需要可见交付，runSessionsSendA2AFlow() 会做 bounded ping-pong，再让目标 agent 生成 announce message 发回 channel。
Agent A
  → tool_use: sessions_send({ sessionKey: "agent:reviewer:main", message: "请 review 这个设计" })
  → permission / visibility / A2A policy check
  → Gateway injects inter-session message into Agent B session
  → Agent B runs one turn and writes transcript
  → optional wait returns reply to Agent A
  → optional A2A ping-pong, max session.agentToAgent.maxPingPongTurns
  → announce delivery to visible channel if needed

A2A 权限开关

跨 agent 访问不默认无限开放。createAgentToAgentPolicy() 会看 tools.agentToAgent.enabled 和 tools.agentToAgent.allow。跨 agent send / history / status / list 都会受这个策略影响。

可见性范围

tools.sessions.visibility 支持 self、tree、agent、all。跨 agent 通常需要 all；默认是 tree，即当前 session 和它生成的子树。

沙箱会收紧范围

sandboxed session 的 session tools 会被 clamp 到更窄范围，默认只能看 spawned/tree 范围，避免沙箱里的 agent 借跨 session 工具越权访问其他 agent。

ping-pong 是有上限的

session.agentToAgent.maxPingPongTurns 控制 A2A 往返轮数，默认 5，源码上限 20。接收方也可以回复 REPLY_SKIP 停止继续互发。

父子 agent 通信要和同级通信区分开：

父 agent 需要并行研究
  → sessions_spawn({ task: "查 X", agentId: "researcher", context: "isolated" })
  → 返回 runId + childSessionKey，父 agent 不阻塞
  → 子 agent 独立跑，写自己的 transcript
  → 父 agent 调 sessions_yield 等完成事件
  → completion announce 把子结果作为运行时事件交回父会话
  → 父 agent 汇总后回复用户
最重要的判断：OpenClaw 的 agent 通信本质是 session 层通信。同级 agent 用 sessions_send；父子委派用 sessions_spawn + sessions_yield；状态管理用 task registry / transcript；跨 agent 可见性由 tools.sessions.visibility 和 tools.agentToAgent 控制。
