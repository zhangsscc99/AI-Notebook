memory 写入机制

OpenClaw 的 memory 写入分两类：一类是用户或模型把内容写进 durable memory 文件，另一类是索引器把文件内容写进搜索 index。这两件事不要混在一起。

durable 文件写入

真正长期保留的信息应该追加到 memory/YYYY-MM-DD.md 或维护在 MEMORY.md。memory flush 明确要求 append，不要覆盖。

pre-compaction flush

临近 compaction 时，OpenClaw 可运行 silent memory flush，让模型把本轮值得长期保存的信息写到当天 memory 文件；如果没东西保存则返回 silent token。

索引写入

sync 后 indexFile 会 chunk 文件、生成 embedding、写 chunks、chunks_fts、可选 chunks_vec。

后台整理写入

dreaming / promotion 会记录短期召回信号和 dream report，把可能有价值的信息整理成候选长期记忆。

判断“写 memory”是哪一种：如果写的是 markdown 文件，那是 durable memory；如果写的是 SQLite/QMD，那是检索索引，可以重建。
