C18

Claude Code subagent 和 Agent Team 里的通信方式有什么区别？

Claude Code 里 subagent 和 Agent Team / teammate 都是“多 agent”，但通信方式完全不同。subagent 更像父 agent 通过 Agent 工具派出去的一次性任务调用；Agent Team 更像多个长期成员通过 mailbox、TaskList 和 SendMessage 协作。

最短结论：subagent 通信是 tool_use / tool_result 风格的父子调用；Agent Team 通信是 mailbox + SendMessage + TaskList + idle notification 风格的团队协作协议。

1. subagent：父 agent 调工具，子 agent 返回结果

普通 subagent 的入口是 src/tools/AgentTool/AgentTool.tsx。父 agent 输出：

Agent({
  description: "Research auth",
  subagent_type: "Explore",
  prompt: "搜索登录链路并返回关键文件"
})

运行时执行 AgentTool.call()，再通过 runAgent() 启动另一个 query() loop。子 agent 完成后，结果被包装成父 agent 的 tool_result；如果是后台执行，则先返回 async_launched，完成后回一个 <task-notification>。

2. Agent Team：成员之间靠 mailbox 发消息

Agent Team 先由 TeamCreate 创建 team，再用 Agent({ name, team_name, prompt }) 创建 teammate。只要 AgentTool.call() 发现 teamName && name，就不走普通 subagent，而是走 spawnTeammate()。

teammate 的消息不是直接作为父 agent 的 tool_result 返回，而是写入对方 inbox 文件：

~/.claude/teams/{team_name}/inboxes/{agent_name}.json

收件方下一轮从 mailbox 读取消息，再把它格式化成 <teammate-message> 注入自己的模型上下文。

3. 生命周期差异：一次性 vs 长期在线

subagent 通常是一次性：接收 prompt → 跑自己的 query loop → 返回最终结果 → 结束。即使是 async subagent，也是一个 background task，核心是完成某个任务后通知父 agent。

teammate 是长期 worker：接收一个 prompt 跑一轮，完成后进入 idle，不退出；后续可以继续接收 SendMessage、领取 TaskList 里的任务、等待 shutdown request。

4. 通信拓扑差异：树状父子 vs 团队网状

subagent 的通信拓扑主要是父子结构：父 agent → AgentTool → child agent → tool_result/task-notification → 父 agent。

Agent Team 是 team 结构：leader 可以给任意 teammate 发消息，teammate 也可以给 leader 或其他 teammate 发消息，甚至可以广播。TaskList 是共享协调面，mailbox 是异步消息面。

5. 上下文可见性差异

subagent 的父 agent通常只看到子 agent 的最终总结、usage、agentId 或 task notification；不会天然看到子 agent 内部每一步完整思考和工具过程。

Agent Team 里，成员之间也不共享隐藏上下文。它们只共享显式消息、共享任务列表、共享项目文件，以及 team config。也就是说团队协作依赖“写出来的消息”，不是共享脑内状态。

6. 控制工具差异

subagent 后续控制主要靠 agentId、SendMessage、output file、TaskStop。

Agent Team 控制更丰富：SendMessage 用于 teammate 消息；TaskCreate/TaskList/TaskUpdate/TaskGet 用于任务板；plan_approval_response 用于计划审批；shutdown_request 用于优雅退出。

7. 承载方式差异

subagent 多数是在同一进程内由 runAgent() 再跑一个 query loop，也可以 background 化或 worktree/remote 隔离。

Agent Team 的 teammate 可以由不同 backend 承载：tmux split pane、iTerm2 pane、外部 tmux swarm session，或者 in-process backend。pane backend 更像独立 Claude Code 终端；in-process backend 则用 AsyncLocalStorage 做身份隔离。

8. 什么时候用哪个

用 subagent：你只需要一个专家短暂帮忙，比如搜索代码、生成方案、检查某个模块、并行跑一个一次性任务。

用 Agent Team：你需要多个长期角色协作，比如 researcher、implementer、tester 持续交换消息，共享任务板，分阶段完成一个大项目。

通信方式对比：

subagent
  父 agent
    -> Agent tool_use(prompt, subagent_type, run_in_background)
    -> AgentTool.call()
    -> runAgent() / child query loop
    -> completed tool_result
       或 async_launched + task-notification
    -> 父 agent 下一轮继续

Agent Team
  TeamCreate
    -> team config + task list
  Agent(name, team_name, prompt)
    -> spawnTeammate()
    -> backend 启动 teammate
    -> prompt 写入 mailbox
  teammates
    -> SendMessage 写 inbox
    -> mailbox 读消息
    ->  注入上下文
    -> TaskList/TaskUpdate 协同
    -> idle notification / shutdown_request
关键区别：subagent 是“父 agent 通过工具调用临时委托任务”；Agent Team 是“多个命名成员通过消息系统和任务板长期协作”。 前者结果回到父 agent 的工具结果链路，后者消息进入 mailbox 和 team workflow。
