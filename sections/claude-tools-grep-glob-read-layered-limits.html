Claude Code 的 Grep / Glob / Read 等工具具体有哪些，读取限制和分层读取怎么做

Claude Code 里跟“找文件、搜内容、读文件”最相关的工具主要是 Glob、Grep、Read，再加上辅助性的 Bash、LSP、NotebookEdit。源码设计很明确：先用轻量工具缩小范围，再用 Read 精确读取片段。它不是鼓励模型一上来把大文件全读进上下文。

一句话：Claude Code 的文件理解链路是 Glob 找文件 → Grep 搜内容 → Read 读命中片段 → Edit/Write 修改。读取有行数、字节、token、PDF 页数、图片 token 预算等多层限制；所谓“分层读取”主要是工具能力 + prompt 引导 + offset/limit 支持共同实现。

1. Glob：按文件名/路径模式找文件

源码：src/tools/GlobTool/GlobTool.ts。输入是 pattern 和可选 path，输出是匹配文件列表、耗时、数量、是否截断。

优化：默认最多返回 100 个结果；路径会转成相对 cwd，减少 token；路径不存在时返回 cwd suggestion，方便模型纠错。

2. Grep：按内容正则搜索

源码：src/tools/GrepTool/GrepTool.ts。底层包装 ripgrep，支持 pattern、path、glob、type、output_mode、上下文行、head_limit、offset、multiline。

优化：默认排除 .git/.svn/.hg/.bzr/.jj/.sl，限制 --max-columns 500，默认 head_limit=250，并先分页再做路径相对化，避免对会被丢弃的海量结果做多余处理。

3. Read：真正读文件内容

源码：src/tools/FileReadTool/FileReadTool.ts、src/utils/readFileInRange.ts。输入是绝对 file_path，可选 offset、limit、PDF pages。

优化：默认从头最多读 2000 行；提示里明确让模型对长文件使用 offset/limit。文本读取后会带行号，方便下一步 Edit 精确定位。

4. Bash / LSP 是补充，不是首选读取

Bash 可以跑 ls、cat、sed、rg，但系统提示更偏向专用工具：读文件用 Read，搜内容用 Grep，找文件用 Glob。LSPTool 则用于 definitions / references / symbols / hover 这类代码智能查询。

优化：专用工具有结构化 schema、权限、截断、相对路径、错误恢复；裸 Bash 输出更难控 token，所以不是默认首选。

它的“分层读取”可以按这个顺序理解：

先定位文件集合。不知道文件名时用 Glob，例如 **/*Tool.ts。
再定位内容命中。知道关键词/函数名时用 Grep，默认只返回文件名或有限内容，避免大面积读文件。
再读小片段。Grep 给出文件和行号后，用 Read({ offset, limit }) 读附近几十到几百行。
需要修改时先保证已读。Edit / Write 会检查 readFileState 和 mtime，没读过或文件变化过就拒绝，要求重新 Read。
特殊文件走专门路径。图片走压缩和 token budget；PDF 大文件走 pages；notebook 返回 cells，太大时提示用 jq 分段读。
典型源码阅读流程：
Glob({ pattern: "src/tools/**/*Tool.ts" })
  ↓ 找到候选文件
Grep({ pattern: "readFileInRange", path: "src", output_mode: "content", "-n": true, head_limit: 20 })
  ↓ 拿到具体文件和行号
Read({ file_path: "/repo/src/utils/readFileInRange.ts", offset: 1, limit: 180 })
  ↓ 理解实现
Read({ file_path: "/repo/src/tools/FileReadTool/FileReadTool.ts", offset: 1000, limit: 120 })
  ↓ 只读相关片段，不把整文件塞进上下文

Read 的行数限制

prompt.ts 里写了默认最多读取 MAX_LINES_TO_READ = 2000 行，从文件开头开始。用户或模型可以传 offset 和 limit 做分段读取。

Read 的字节限制

limits.ts 里默认 maxSizeBytes 走 MAX_OUTPUT_SIZE，注释说明默认大约 256 KB。注意它默认检查的是总文件大小；超了会报错，提示用 offset/limit 或 search，而不是直接塞 25K token。

Read 的 token 限制

默认 DEFAULT_MAX_OUTPUT_TOKENS = 25000。源码先粗略估算，接近阈值才调用 API count tokens；超过就抛 MaxFileReadTokenExceededError。

重复读取去重

Read 会把已读文件范围记录进 readFileState。如果同一文件同一范围未变化，再读时返回 file_unchanged stub，让模型引用之前的 Read 结果，减少重复上下文。

readFileInRange.ts 里还有一个很关键的底层优化：它确实有“分层/分路径读取”的实现。

// src/utils/readFileInRange.ts，简化理解
if (regular file && size < 10MB) {
  // fast path：一次 readFile，内存里按行切片
  read whole file → split lines → return [offset, offset + limit)
} else {
  // streaming path：大文件/管道/设备走流式扫描
  createReadStream → 手动找 \n → 只累积目标行范围
  // 范围外只计数 totalLines，不保存内容，避免读 100GB 文件爆内存
}

Fast path：小文件快读

普通文件小于 10MB 时，直接 readFile() 后按行切片。源码注释说这样比 stream 少 per-chunk async overhead，对常见源码文件大约更快。

Streaming path：大文件安全读

大文件、pipe、device 等走 createReadStream。它只累积 offset/limit 范围内的行，范围外丢弃，只统计 totalLines / bytes。这个就是防止大文件读取撑爆 RSS 的关键。

PDF 分页限制

PDF 支持 pages，格式如 1-5。大 PDF 超过阈值会要求指定页码；每次最多 PDF_MAX_PAGES_PER_READ，源码提示最大 20 页。

图片 token budget

图片不是按文本 maxSizeBytes 处理，而是读取一次后 resize / downsample；如果估算 token 超预算，再从同一 buffer 做更激进压缩，避免重复读文件。

Grep / Glob 本身也有结果限制：

Grep:
- output_mode 默认 files_with_matches
- content / count / files_with_matches 都支持 head_limit + offset
- head_limit 未指定默认 250；传 0 才是 unlimited
- --max-columns 500 防止 minified/base64 行污染输出
- files_with_matches 会按 mtime 新到旧排序，再 head_limit

Glob:
- 默认 maxResults = 100
- 返回 truncated=true 时提示缩小 path 或 pattern
- 只读、可并发、结果路径相对 cwd
回答你的问题：是的，读取有限制；也有分层读取。限制包括 Read 默认 2000 行、约 256KB 文件大小门槛、25000 token 输出门槛、PDF 20 页、Glob 100 结果、Grep 默认 250 结果。分层读取不是一个叫“LayeredReader”的单独模块，而是 Glob/Grep 先缩小范围 + Read offset/limit 分段 + readFileInRange fast/stream 双路径 + dedup/file_unchanged 共同组成的工程策略。
