Wan2.2 视频生成模型架构是什么，对比 LLM 多了什么组件

Wan2.2 和 LLM 都大量使用 Transformer，但任务范式完全不同：LLM 是自回归 next token prediction，输入文本 token，逐个输出文本 token；Wan2.2 是视频 latent diffusion / flow matching，输入 prompt 条件和随机视频 latent，通过多步 denoising 输出视频 latent，再解码成视频。

一句话：LLM 的核心循环是“前文 token → 下一个 token”；Wan2.2 的核心循环是“noisy video latent + 文本条件 + timestep → 更干净的视频 latent”。所以视频生成模型比 LLM 多了 VAE、视频 latent、scheduler/timestep、3D patch embedding、CFG、视频时空位置编码，以及 A14B 的高/低噪声 expert 切换。

从源码看，Wan2.2 文生视频的主架构可以拆成这几层：

T5 文本编码器。prompt 先进入 T5EncoderModel，变成 context。这相当于给视频模型提供语义条件，不是直接让视频 DiT 自己 tokenizer 文本。
VAE latent 空间。输出空间不是文本 token，而是 VAE 定义的视频 latent。配置里的 vae_stride 控制时间/空间压缩比例。
WanModel / Video DiT。wan/modules/model.py 的 WanModel 用 Conv3d 做 3D patch embedding，把 latent 视频切成时空 token，再用多层 WanAttentionBlock 做建模。
timestep embedding。扩散/flow matching 每一步都有噪声时间 t。WanModel 用 sinusoidal_embedding_1d、time_embedding、time_projection 把 timestep 注入网络。
文本 cross-attention。视频 token 在 Transformer block 中通过 cross-attention 读取文本 context，让画面主体、动作、风格跟 prompt 对齐。
Scheduler / solver。FlowUniPCMultistepScheduler 或 FlowDPMSolverMultistepScheduler 决定 timestep 序列和 latent 更新公式。LLM 通常没有这种外部采样 ODE/SDE solver。
CFG。每步同时跑正向 prompt 条件和负向/空条件，再用 uncond + scale * (cond - uncond) 放大提示词方向。
VAE decode。denoising 后的 latent 仍不是视频文件，必须由 VAE decoder 转成 RGB 帧，再保存成 mp4。

和 LLM 相同的地方

都有大规模参数、embedding、Transformer block、attention、FFN、归一化、位置编码思想。WanModel 里也有 token 序列，只是 token 来自视频 latent patch，而不是文本 tokenizer。

生成方式不同

LLM 一般按 token 顺序生成：第 1 个、第 2 个、第 3 个。Wan2.2 是全局 latent 反复迭代：同一个视频 latent 在 40/50 个 timestep 中被整体更新，逐步从噪声变清晰。

输入输出载体不同

LLM 的输入输出核心是离散文本 token；Wan2.2 的核心载体是连续视频 latent。文本只是条件，最终目标是连续的时空张量。

A14B 还有 expert 切换

T2V/I2V A14B 配置有 high_noise_checkpoint 和 low_noise_checkpoint。采样时根据 boundary 按 timestep 切换 expert：高噪声阶段偏整体结构，低噪声阶段偏细节。

如果用“LLM 对照表”记忆，差异会更清楚：

LLM：文本 token 管线

文本 → tokenizer → token embedding + position → Transformer decoder → logits → sampling → 下一个 token。循环终点是生成足够多文本 token。

Wan2.2：视频 latent 管线

prompt → T5 context；随机 latent → 3D patch token + timestep → Video DiT → scheduler 更新 latent → VAE decode → mp4。循环终点是 timestep 采样完成。

Wan2.2 比典型 LLM 多出来的关键组件：
1. T5 text encoder：单独编码 prompt
2. VAE encoder/decoder：像素视频和 latent 互转
3. video latent：连续时空生成空间
4. 3D patch embedding / unpatchify：把视频 latent 转成 Transformer token 再还原
5. timestep embedding：告诉模型当前噪声阶段
6. scheduler / solver：控制 denoising 轨迹
7. CFG：正向/负向条件组合，增强 prompt 对齐
8. video RoPE：按帧、高、宽建模时空位置
9. high/low noise experts：A14B 按去噪阶段切模型
最短总结：Wan2.2 不是“会输出视频的 LLM”，而是“文本条件控制的视频 latent 扩散系统”。Transformer 只是中间的主干网络；围绕它还必须有 VAE、scheduler、timestep、视频 patch、CFG 和多模态条件接口。
