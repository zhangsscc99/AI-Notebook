如果 reward 只拿 exact 做奖励会怎么样

如果只用 exact，reward 就会变成最硬的 0/1 判题：抽取出的 candidate 和 gold updated source 完全一致才给 1，否则给 0。这样很干净，但在 GRPO 里会有几个明显问题。

最大问题：奖励太稀疏

  • 早期模型大多数输出都不会完全一致，整个 group 可能全是 0。
  • 如果同组 reward 全一样，advantage = reward - mean 接近 0，GRPO 基本没有学习信号。
  • tiny 数据下尤其明显：模型差一点点也和完全错一样，训练会很不稳定。

还会惩罚“语义等价”

代码任务里，两个实现可能语义等价但文本不完全一样。只用 exact 会把这些都判 0，例如变量名不同、等价重排、无害空行/注释差异，都可能被过度惩罚。

只用 exact：最准确，但最稀疏。
加 similarity：让“接近正确”的样本也有一点梯度方向。
加 tag/no_extra：让模型学会机器可解析输出格式。
加 syntax/judge：减少语法坏掉或语义等价被误杀的问题。
结论：只拿 exact 做 reward 可以作为最终严格指标，但不适合作为唯一训练 reward。训练期更适合 exact 为主、similarity / tag_format / no_extra_prose / syntax / judge 辅助，避免 GRPO 没信号或过度脆弱。
