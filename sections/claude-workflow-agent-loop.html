什么是 Agent Loop？Claude Code 如何把一次提问变成多轮执行

Agent Loop（智能体循环）是 Agent 运行时最核心的控制循环。普通聊天通常只完成一次“用户输入 → 模型回复”，而 Agent Loop 会在模型要求调用工具后暂停本轮回答，真正执行工具，再把结果作为新的上下文交还给模型，让它继续判断下一步。

一句话：Agent Loop 是“模型决策 → 工具执行 → 结果回填 → 再次决策”的闭环；它让模型从生成文本，升级为能够观察环境、采取行动并根据结果修正行动的执行系统。

Claude Code 中对应的源码结构

源码里并没有一个名为 AgentLoop 的类。真正的实现位于 src/query.ts：公开入口 query() 调用内部异步生成器 queryLoop()，后者以 while (true) 持续运行。上层 QueryEngine.submitMessage() 负责一次对话的提交、会话状态和消息持久化，并消费 query() 产生的流式消息。

上层：会话生命周期

QueryEngine.ts 管理消息历史、权限拒绝、读取缓存、用量与中止信号。一个 QueryEngine 对应一段会话，每次 submitMessage() 开始用户视角的一轮。

内层：执行循环

query.ts 负责模型调用、流式响应、工具调用、工具结果回填、恢复策略和停止条件。一次 submitMessage() 内部可能经历很多次 Agent Loop 迭代。

一次循环实际做了什么

  1. 整理本轮上下文。循环从 State 读取消息、工具上下文、压缩状态、恢复计数、停止钩子状态和轮数；必要时先对超长工具结果、历史消息和上下文执行压缩或裁剪。
  2. 流式调用模型。deps.callModel() 接收系统提示、用户上下文、历史消息、工具定义和中止信号，并持续产出助手消息与流事件。
  3. 收集工具调用。Claude Code 会检查助手消息中的实际 tool_use 内容块，而不是只相信 API 的 stop_reason。源码注释明确指出，stop_reason === "tool_use" 并不总是可靠。
  4. 执行工具。没有启用流式工具执行时由 runTools() 调度；启用时由 StreamingToolExecutor 在模型仍在输出时提前执行已产生的工具调用。
  5. 生成工具结果。权限检查、参数校验和实际执行完成后，每个调用都会产生带相同 tool_use_id 的 tool_result。这一步把文件内容、Shell 输出、搜索结果或错误信息变成模型下一轮可读的观察结果。
  6. 决定继续还是结束。工具结果、上下文压缩、模型降级、输出 token 恢复、停止钩子、token 预算和最大轮数都可能影响控制流。只有不需要继续执行时，循环才返回终止原因。
  7. 构造下一轮状态。源码把本轮输入、助手消息和工具结果重新合并为 messages: [...messagesForQuery, ...assistantMessages, ...toolResults]，轮数加一，然后开始下一次 while 迭代。

最小伪代码

state.messages = initialMessages

while (true) {
  const response = await streamModel(state.messages, tools)

  if (response has no tool_use) {
    return finish(response)
  }

  const toolResults = await executeTools(response.tool_use, canUseTool)

  state.messages = [
    ...state.messages,
    response,
    ...toolResults,
  ]
  state.turnCount++
}

上面的代码只表达最小心智模型。Claude Code 的真实循环还处理流式降级、孤立的工具结果、权限拒绝、上下文压缩、记忆与技能预取、后台任务通知、停止钩子和预算控制。

工具并不是盲目并行执行

toolOrchestration.ts 会把工具调用分组成批次：通过 isConcurrencySafe() 判定为并发安全的连续调用可以并行执行，默认并发上限来自 CLAUDE_CODE_MAX_TOOL_USE_CONCURRENCY，未设置时为 10；非并发安全的调用则串行执行。这个设计既缩短只读搜索、读取等操作的等待时间，也避免修改文件等有副作用的工具互相破坏状态。

Agent Loop 与工作流编排是什么关系

Agent Loop 解决“下一步”

它关注单个执行单元内部的反馈闭环：模型看到当前上下文后决定调用什么工具，运行时执行工具并返回结果，模型再决定下一步。

工作流编排解决“谁来做、按什么顺序做”

它位于更高层，负责任务拆分、父子 Agent、依赖关系、并行/串行策略、结果汇总和失败恢复。每个子 Agent 通常会启动自己的 query() 循环，而父级负责协调多个循环。

因此可以把 Claude Code 的架构概括为：工作流编排协调多个任务或 Agent，Agent Loop 驱动单个 Agent 完成任务。父级不可能只靠一次模型请求就知道所有后续动作；循环的价值正是让每一轮工具结果改变下一轮决策。

循环如何终止

源码中的主要终止原因包括：正常完成 completed、达到最大轮数 max_turns、用户在模型流式输出或工具执行阶段中止、停止钩子阻止继续、模型或图片错误、上下文达到阻塞上限，以及提示词过长无法恢复。普通完成还必须经过停止钩子和 token 预算检查，因此“模型不再调用工具”并不总是立即结束。
