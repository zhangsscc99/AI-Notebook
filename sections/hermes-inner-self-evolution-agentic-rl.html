Hermes 的内层自进化 agentic RL 怎么做：源码链路和具体案例

这里的“内层自进化”要和前面说的 skills 分开看。skills 是运行时外层：把一次任务经验写成文件，下次 prompt 里加载。Hermes 的内层 agentic RL 是训练层：让当前策略模型自己进入工具环境完成任务，环境根据真实执行结果给 reward，trainer 把这些轨迹变成 advantage，再用 Tinker 更新 LoRA 权重，更新后的 sampler 立刻参与下一轮 rollout。

一句话：Hermes 把 agent 不是当成“单次回答器”训练，而是当成“会调用终端、文件、网页工具的行动策略”训练；每一轮自进化就是：自己行动 → verifier 打分 → 高分轨迹增强、低分轨迹压低 → LoRA 更新 → 新策略继续行动。

从源码看，这条链路分成三层：Hermes agent loop 负责行动，Hermes/Atropos environment 负责出题和打分，Tinker trainer 负责真正更新权重。

启动 RL 工作流。rl_cli.py 把 Hermes 切到 tinker-atropos 目录，并启用 terminal、web、rl 工具集，让 agent 能选择环境、改配置、启动训练、查看结果。
RL tool 管训练生命周期。tools/rl_training_tool.py 扫描环境、写配置、锁定基础设施参数，然后启动三类进程：Atropos API、Tinker trainer、environment server。
环境把模型放进 agent loop。HermesAgentBaseEnv.collect_trajectory() 给每条 rollout 创建独立 task_id，装配 system/user messages，然后调用 HermesAgentLoop.run()。
agent 多轮工具调用。environments/agent_loop.py 每轮请求模型，如果模型返回 tool_calls，就用 model_tools.handle_function_call() 执行，再把 tool result 写回 messages 继续下一轮。
reward 在同一个任务状态里计算。agent 做完后，环境构造 ToolContext(task_id)，把同一个 sandbox / terminal / browser 状态交给 compute_reward() 验证。
Atropos 收集成组轨迹。collect_trajectories() 会对同一个 item 采 group_size 条 rollout。每条都有 tokens、masks、logprobs、messages、score。
trainer 计算相对优势。TinkerAtroposTrainer.pad_data_to_good_offset() 对每组分数算 advantage = score - group_mean，prompt token advantage 置 0，只训练模型自己生成的 token。
Tinker 做 LoRA 更新。train_step() 调 forward_backward_async(..., loss_fn="importance_sampling") 和 optim_step_async(AdamParams(...))，更新的是 LoRA 训练客户端，不是直接全量改 base model。
新策略立刻回到 rollout。每一步后 trainer 调 save_weights_for_sampler(step_i) 和 create_sampling_client(model_path=new_path)，下一批环境 rollout 用的就是更新后的 sampling client。
Hermes inner self-evolution loop

dataset item
  -> HermesAgentBaseEnv.format_prompt()
  -> HermesAgentLoop.run(messages, tools)
       -> model decides
       -> tool call executes in sandbox
       -> tool result returns to messages
       -> repeat until final answer / max turns
  -> compute_reward(item, result, ToolContext(task_id))
  -> Atropos group batch
  -> advantage = reward - group_mean
  -> Tinker importance_sampling loss
  -> LoRA optimizer step
  -> save sampler weights
  -> next rollout uses updated sampler

为什么叫“内层”

因为它改的是模型策略本身。Hermes skills、memory、workflow 都是在 prompt / 工具 / 文件系统外层增强 agent；而这条 RL 链路会通过 Tinker 把高 reward 行为压进 LoRA 参数里。

为什么叫“自进化”

因为 rollout 由当前模型自己产生，reward 来自环境验证，更新后的模型又继续产生下一批 rollout。它不是人工写规则教模型每一步怎么做，而是用执行结果筛选自己的行动轨迹。

为什么是 agentic RL

训练样本不是纯文本问答，而是多轮消息、工具调用、工具结果、终端状态和最终验证构成的完整 trajectory。被优化的是“如何行动”的 token 分布。

源码里的保护边界

rl_training_tool.py 锁定了 tokenizer、rollout/model server、LoRA rank、learning rate、trainer token length 等基础设施参数，避免 agent 随意改训练底座。

拿 Hermes SWE 环境做一个具体例子最直观。environments/hermes_swe_env/hermes_swe_env.py 定义了一个软件工程任务环境：模型拿到 coding task，可以用 terminal、file、web 工具改代码；reward 函数在同一个 sandbox 里跑测试。

环境出题。数据集 item 里有 prompt，可能还有 test、test_code 或 tests。format_prompt() 把题目和测试说明拼成用户消息。
agent 开始修代码。system prompt 要求模型像软件工程师一样使用终端、文件工具和 web search，写干净代码并验证。默认最大 30 轮，工具集是 terminal、file、web。
工具状态被保留。如果模型创建文件、改文件、跑命令，这些状态都绑定到本条 rollout 的 task_id。后面的 verifier 会拿同一个 task_id 进入同一个环境。
reward 跑真实测试。compute_reward() 调 ctx.terminal('cd /workspace && python3 -c "..."')。测试 exit code 为 0 给 1.0；如果没通过但创建了新的 Python 文件，给 0.1；否则 0.0。
同题多条 rollout 互相比。默认 group_size=4。同一个 bugfix 任务会采四条 agent trajectory：有的先读测试再最小修复，有的乱改，有的忘记跑测试。
训练增强好策略。通过测试的 trajectory advantage 为正；失败或只拿部分分的 trajectory advantage 为负或较低。Tinker 的 importance-sampling loss 会把成功轨迹里的行动 token 概率推高。
案例：HumanEval 风格任务

prompt:
  implement function normalize_phone_number(s)
tests:
  assert normalize_phone_number("(650) 555-1212") == "6505551212"
  assert normalize_phone_number("+1 650 555 1212") == "16505551212"

rollout A:
  read_file /workspace/solution.py
  write_file /workspace/solution.py  # 用 regex 只保留数字
  terminal python3 -m pytest /workspace
  final: tests pass
  reward = 1.0

rollout B:
  write_file /workspace/solution.py  # 只去掉空格，没处理括号和 +
  terminal python3 -m pytest /workspace
  final: tests fail
  reward = 0.1  # 至少创建了 Python 文件

rollout C:
  只解释思路，没有改文件
  reward = 0.0

rollout D:
  改错函数名，测试找不到目标函数
  reward = 0.1

group_mean = (1.0 + 0.1 + 0.0 + 0.1) / 4 = 0.3
advantages:
  A = +0.7
  B = -0.2
  C = -0.3
  D = -0.2

A 轨迹学到什么

A 的正 advantage 会增强一串实际有用的决策：先看文件、写最小实现、用终端跑验证、最终回答完成。模型不是只学会 regex，而是学会一套“改代码前后要验证”的行动模式。

B / D 为什么被压低

B 和 D 不是完全没动作，所以有 0.1 partial reward；但它们低于组均值，advantage 仍是负的。训练会降低“没覆盖测试就结束”“改错接口名”这类轨迹 token 的相对概率。

C 为什么最差

C 没有真实改文件，只给解释。对 agentic coding 任务来说，这不是有效行动，所以 reward 0。它会把“只聊天不执行”的模式往下压。

下一轮怎么变强

trainer 保存新的 sampler weights 后，下一批 rollout 用的是更新过的 LoRA。于是模型更容易先检查文件、调用正确工具、跑测试，而不是只输出文字答案。

这就是 Hermes agentic RL 和普通 SFT/QA RL 的本质差别：奖励不只是答案字符串对不对，而是完整工作流有没有把外部世界改到正确状态。

普通问答 RL:
  prompt -> completion -> answer reward

Hermes agentic RL:
  prompt -> multi-turn tool actions -> environment state changes
         -> verifier runs in same task state
         -> trajectory reward
         -> token-level advantage update
所以“内层自进化”的准确理解是：Hermes 让模型在真实工具环境里反复试任务，用 verifier 奖励筛选自己的行动轨迹，再通过 Tinker-Atropos 把这些结果更新进 LoRA。skills 让 agent 下次“记得经验”，而 inner agentic RL 让模型下次“更自然地采取高 reward 行动”。
