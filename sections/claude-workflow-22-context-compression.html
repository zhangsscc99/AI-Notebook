Claude Code 怎么做上下文压缩

Claude Code 的上下文压缩不是简单“把历史消息删掉”。它是一套分层机制：小压缩先清理工具结果，大压缩再让模型生成会话摘要；压缩后还要重建能继续工作的上下文，包括最近消息、文件状态、plan mode、skills、MCP 指令、agent 列表、hooks 结果等。

一句话：Claude Code 压缩上下文的目标不是最小 token，而是“丢掉旧细节，但保留继续干活所需的任务状态、代码线索和运行时协议闭合”。

1. 压缩入口有三类

手动压缩：/compact 命令在 src/commands/compact/index.ts 注册，实际执行在 src/commands/compact/compact.ts。用户也可以附加自定义 summarization instructions。

自动压缩：query.ts 每轮模型调用前会跑 deps.autocompact()，也就是 autoCompactIfNeeded()。

失败后补救压缩：当 API 返回 prompt-too-long / 媒体过大等可恢复错误时，query.ts 会尝试 context collapse drain 或 reactive compact，再重试当前 turn。

2. 自动触发阈值怎么定

autoCompact.ts 先算有效上下文窗口：模型总 context window 减去给摘要输出预留的 token，最多预留 20,000 tokens。自动压缩阈值大致是 effectiveWindow - 13,000。

如果关闭 auto compact，则有 hard blocking limit，并额外给手动 /compact 预留 3,000 tokens，避免上下文满到连压缩命令都跑不了。

在真正调用模型前，Claude Code 的上下文管理顺序大概是：

getMessagesAfterCompactBoundary()：先从最近一次 compact boundary 之后的消息开始，旧压缩段不再原样进入模型。
applyToolResultBudget()：限制单条/累计工具结果的上下文占用，超大结果可替换成引用。
可选 snipCompact：对历史做更轻量的裁剪。
microcompactMessages()：先做微压缩，主要处理旧工具结果，而不是整段会话摘要。
可选 contextCollapse.applyCollapsesIfNeeded()：把可折叠的上下文投影成更小视图。
autoCompactIfNeeded()：如果 token 超阈值，进入真正的 conversation compact。
压缩成功后用 buildPostCompactMessages() 替换当前 messagesForQuery，然后继续本轮模型调用。
query.ts 每轮模型调用前：
messagesForQuery = getMessagesAfterCompactBoundary(messages)
messagesForQuery = applyToolResultBudget(messagesForQuery)
messagesForQuery = snipCompactIfNeeded(messagesForQuery)
messagesForQuery = microcompactMessages(messagesForQuery)
messagesForQuery = contextCollapse.applyCollapsesIfNeeded(messagesForQuery)
compactionResult = autoCompactIfNeeded(messagesForQuery)
if compactionResult:
  postCompactMessages = buildPostCompactMessages(compactionResult)
  messagesForQuery = postCompactMessages
callModel(messagesForQuery)

3. microcompact：先压工具结果

microCompact.ts 只关注一批 compactable tools：Read、shell、Grep、Glob、WebSearch、WebFetch、Edit、Write 等。

它有两种思路：cached microcompact 通过 API cache editing 删除旧 tool result 的缓存引用，尽量不改本地消息；time-based microcompact 在缓存已经冷掉时，把旧 tool_result 内容替换成 [Old tool result content cleared]，但保留最近 N 个工具结果。

4. compactConversation：真正生成摘要

compactConversation() 会跑一个 forked summarization agent，请模型生成详细摘要。摘要 prompt 在 services/compact/prompt.ts，明确要求保留用户意图、技术概念、文件和代码片段、错误与修复、待办、当前工作和下一步。

压缩模型被要求只输出文本，不允许调用工具，避免 summary turn 又触发工具调用。

5. 压缩前先清洗输入

压缩前会处理一些高风险上下文：图片和 document 会被替换成 [image] / [document]，避免摘要请求本身因为媒体过大失败；skill discovery / listing 这类后续会重新注入的 attachment 也会被剥掉，避免污染摘要。

6. 压缩后不是只留下 summary

buildPostCompactMessages() 的顺序是：boundaryMarker、summaryMessages、messagesToKeep、attachments、hookResults。也就是说摘要只是核心之一，后面还会恢复关键运行状态。

压缩后重建上下文时，Claude Code 会补回这些东西：

最近读过的文件

压缩前保存 readFileState，压缩后用 createPostCompactFileAttachments() 尽量恢复最多 5 个重要文件，总预算约 50k，每个文件约 5k。太大的文件会变成引用，提示需要时重新 Read。

Plan / Plan Mode

如果当前有 plan 文件或处在 plan mode，会生成 plan attachment / plan mode attachment，保证压缩后模型还知道自己不能直接执行实现，或者知道当前计划状态。

Skills / Tools / MCP

被调用过的 skills 会作为 attachment 保留；deferred tools、agent listing、MCP instructions 会重新做 delta announcement，因为旧的 attachment 可能已经被摘要吃掉。

Hooks 和 SessionStart

压缩前跑 PreCompact hooks，压缩后跑 SessionStart hooks 和 PostCompact hooks。用户或项目可以通过 hooks 注入“压缩时必须保留什么”。

7. Session Memory Compact：用外部会话记忆替代重新总结

如果 feature flag / env 打开，trySessionMemoryCompaction() 会优先使用已经抽取好的 session memory 内容，而不是重新把整个历史交给 summarizer。它会保留上次 summarized message 之后的 recent messages，并按配置保证至少约 10k tokens、至少 5 条文本消息，最多约 40k tokens。

这里还有关键安全处理：adjustIndexToPreserveAPIInvariants() 会把保留窗口往前扩，避免切断 tool_use/tool_result 对，或者切掉同一个 assistant message id 里的 thinking block。

8. Partial Compact：选一段压缩

partialCompactConversation() 支持按 pivot 做局部压缩：up_to 表示压缩前半段、保留后半段；from 表示保留前半段、压缩后半段。它会在 boundary 上标注 preserved segment，方便 transcript/resume 重新链接。

9. 失败恢复：压缩请求自己太长怎么办

如果 compact summarization 这个请求本身也 prompt-too-long，truncateHeadForPTLRetry() 会按 API round 分组，从最旧的组开始丢弃，最多重试 3 次，并插入 [earlier conversation truncated for compaction retry] 标记，避免用户卡死。

10. 自动压缩失败不会无限重试

autoCompactIfNeeded() 有 circuit breaker：连续失败达到 3 次后，本 session 后续会跳过无意义的自动压缩，避免每轮都浪费 API 调用。

一个具体例子：

你让 Claude Code 改一个大型项目：
1. 前 30 轮里 Read/Grep/Bash 产生大量 tool_result
2. microcompact 先清理旧工具结果，只保留最近关键结果
3. token 仍接近阈值，autoCompact 触发
4. compactConversation 让模型总结旧对话：
   - 用户到底要什么
   - 改了哪些文件
   - 关键 bug / 修复
   - 当前还剩什么任务
5. 压缩后上下文变成：
   compact boundary
   + 详细 summary
   + 最近未总结的消息
   + 最近重要文件 attachment
   + plan/skills/MCP/tool delta
6. 下一轮模型不再看到完整 30 轮历史，
   但能继续知道任务目标、代码状态和下一步。
最短总结：Claude Code 的上下文压缩是“摘要 + 保留最近窗口 + 恢复运行时附件 + 保护工具协议”的组合。 它不是粗暴截断；真正复杂的地方在于压缩后还要让 agent 能安全继续工作。
