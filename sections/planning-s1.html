OpenClaw 是怎么进行工作流编排的

OpenClaw 的工作流编排不是单一模块完成的，而是几层能力叠在一起：触发入口、session/queue、agent loop、tools、background tasks、Task Flow、cron、hooks。简单说：普通对话由 session queue 编排；长期/后台工作由 tasks 和 Task Flow 编排；定时和事件触发由 cron/hooks/webhook 编排。

触发。工作可以来自聊天消息、CLI、cron 定时任务、webhook、内部 hook，或者其他插件。
路由到 session。OpenClaw 根据 channel、account、peer、thread、agentId 等信息找到或创建 session，保证同一条对话线有稳定上下文。
排队。如果当前 session 已有 run 在执行，新消息会进入 queue，按配置决定等待、合并、steer 当前 run，或者作为后续 follow-up。
agent loop 执行。模型读取上下文、形成计划、调用工具、等待工具结果、继续推理，直到生成最终回复或进入后台任务。
工具层执行具体动作。例如 browser、exec、memory、message、sessions、cron、llm-task、lobster 等工具负责实际 I/O。
后台任务。长耗时或 detached work 会落到 background task ledger，便于状态追踪、取消、恢复和审计。
Task Flow 编排多步骤。如果任务是 A→B→C 或有分支、等待、重试、审批，Task Flow 负责 durable flow state、revision tracking，并协调多个 background tasks。
结果交付。最终结果通过 channel send path、message 工具、cron delivery、hook messages 或 task/flow 状态返回给用户。

Session queue 管“同一对话怎么排队”

它解决的是并发问题：同一个 chat/thread 里同时来了多条消息，应该排队、合并、还是插入当前 run。这个层面偏实时对话编排。

Background Tasks 管“后台工作单元”

task 是 detached work 的最小持久记录。它适合单个后台操作，比如跑一次报告、执行一次维护、处理一次长任务。

Task Flow 管“多步骤流程”

Task Flow 在 tasks 之上，管理多步骤、可恢复、有状态的流程。它记录 flow state、revision，并能跨 gateway restart 继续追踪。

Cron / Hooks 管“什么时候触发”

cron 负责定时触发；hooks 负责事件触发，例如 /new、/reset、compaction 前后、gateway startup/shutdown、message received/sent。

一个典型定时工作流可以这样理解：

cron schedule
  -> create/send run into a session
  -> agent loop starts
  -> tool calls / deterministic checks
  -> background tasks for long-running steps
  -> Task Flow tracks A -> B -> C
  -> approval gate if needed
  -> message delivery / task status / flow status
一句话：OpenClaw 的 planning/workflow orchestration 是“session queue 处理实时对话，tasks 记录后台工作，Task Flow 管多步骤状态机，cron/hooks/webhook 负责触发，tools 负责执行”。
