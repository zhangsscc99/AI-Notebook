应用层：Wan2.2 怎么由提示词生成视频

从应用层看，用户只输入一句提示词，比如“两个穿拳击服的猫在舞台上打拳”，Wan2.2 最后输出一个 mp4。但中间不是 LLM 直接“写出视频”，而是提示词条件控制下的视频扩散/flow matching 采样过程：先把文字变成条件向量，再从随机噪声开始一步步去噪成视频 latent，最后用 VAE 解码成真实视频帧。

一句话：提示词不是直接变成像素；提示词先经 T5 编码成语义条件，WanModel 在每个 denoising timestep 用 cross-attention 读取这个条件，逐步把随机 latent 修正成符合提示词的视频，最后 VAE 把 latent 解码成 mp4。

最典型的文本生成视频命令是：

python generate.py \
  --task t2v-A14B \
  --size 1280*720 \
  --ckpt_dir ./Wan2.2-T2V-A14B \
  --prompt "Two anthropomorphic cats in comfy boxing gear fight on a stage"
命令行收参数。generate.py 读取 --task、--size、--prompt、--ckpt_dir、--sample_steps、--sample_guide_scale 等参数。_validate_args() 会补默认采样步数、shift、CFG scale、帧数。
可选扩写提示词。如果开 --use_prompt_extend，会用 DashScope 或本地 Qwen 把短 prompt 扩写成更细的影视描述。扩写失败则回退原 prompt。
创建任务 pipeline。对于 t2v-A14B，generate.py 创建 wan.WanT2V。这个对象加载 T5 文本编码器、VAE、high-noise model、low-noise model。
文本条件编码。WanT2V.generate() 用 self.text_encoder([input_prompt]) 编码正向提示词，同时用 negative prompt 编码 context_null，后面用于 classifier-free guidance。
初始化视频 latent 噪声。代码根据帧数、分辨率、VAE stride 计算 target_shape，再用 torch.randn(...) 生成初始噪声。这个噪声就是视频生成的起点。
设置采样时间步。根据 sample_solver 选择 FlowUniPCMultistepScheduler 或 FlowDPMSolverMultistepScheduler，生成一串 timesteps。
循环去噪。每个 timestep 都把当前 latent 送入 WanModel。模型分别跑有 prompt 条件的 noise_pred_cond 和无条件/负向条件的 noise_pred_uncond。
CFG 加强提示词控制。源码用 noise_pred_uncond + guide_scale * (noise_pred_cond - noise_pred_uncond)。直观理解：把“符合提示词的方向”放大，让视频更贴近 prompt。
更新 latent。sample_scheduler.step() 根据模型预测结果和当前 timestep，把 latent 从更噪的状态推进到更干净、更像视频的状态。
VAE 解码并保存。采样结束后，self.vae.decode(x0) 把 latent 解码成视频帧；save_video() 把 tensor 转成 uint8 frame，用 imageio/libx264 写成 mp4。

提示词到底控制了什么

提示词经 T5 变成 context。在 WanModel 里，每个 Transformer block 都有 text cross-attention，视频 latent token 会 attend 到文本 token。这样“猫、拳击、舞台、灯光、动作”等语义会影响每一步去噪方向。

为什么同一句提示词可生成不同视频

因为生成起点是随机噪声。base_seed 控制 torch.Generator 的随机种子；同 prompt + 同 seed + 同参数通常更可复现，不同 seed 会产生不同构图和运动。

negative prompt 是干什么的

配置里的 sample_neg_prompt 包含“低质量、模糊、畸形、多余手指、字幕”等负面描述。它参与无条件分支，CFG 会把结果从这些负面方向推开。

采样步数影响什么

sample_steps 越多，去噪迭代越细，通常质量更稳但更慢。A14B 默认 40 步，TI2V-5B 默认 50 步，Animate 默认 20 步。

如果是图生视频、文图生视频、语音生视频，本质链路类似，只是条件更多：

I2V：图片作为额外条件

generate.py 读取 --image 成 PIL image，然后创建 WanI2V。生成时会把输入图像编码成条件视频 latent，让输出视频延续原图主体、构图和风格。

TI2V：一套模型兼容文生/图生

WanTI2V.generate() 判断 img is not None：有图走 i2v，没有图走 t2v。应用层表现就是同一个 5B 模型既能输入纯 prompt，也能输入 prompt + image。

S2V：音频驱动视频

WanS2V 除了 T5 和 VAE，还加载 AudioEncoder / wav2vec。应用层输入 reference image + audio，生成视频后还会调用 merge_video_audio() 把音频合回 mp4。

Animate：预处理材料驱动

Animate 不是只靠一句 prompt。它需要先预处理输入视频和人物参考图，得到 pose、face、mask、background 等材料，再用 WanAnimate.generate() 生成角色动画或人物替换视频。

应用层可记成这 6 步：
1. prompt / image / audio 进入 generate.py
2. prompt 可选扩写
3. T5 把 prompt 编成条件向量
4. 初始化随机视频 latent
5. WanModel 多步去噪，CFG 强化提示词方向
6. VAE 解码 latent，save_video 写成 mp4
最短总结：提示词生成视频 = 文本条件控制随机噪声逐步变成视频。用户看到的是“一句话生成 mp4”，源码里实际是 T5 编码 prompt、WanModel 按 timestep 多轮预测去噪方向、scheduler 更新 latent、VAE 解码视频帧。
