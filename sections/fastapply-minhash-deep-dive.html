详解 MinHash

MinHash 是用来估计两个集合 Jaccard 相似度的压缩签名方法。它特别适合代码数据去重：不需要逐对比较完整代码，只比较很短的 signature。

把代码变集合。 先规范化代码：去空白、变量名抽象成 ID、数字抽象成 NUM，再切 token shingles。
做多组 hash。 对每个 shingle 用很多个 hash 函数计算哈希值。
每组取最小值。 每个 hash 函数只保留最小 hash，这些最小值拼起来就是 MinHash signature。
估计相似度。 两个 signature 对应位置相等的比例，大约等于两个原集合的 Jaccard 相似度。

为什么适合代码去重

很多代码样本只是变量名、函数名、常量不同，结构几乎一样。MinHash 可以在“结构相似”层面发现近重复，比 exact hash 更强。

def add_user(x): return db.save(x)
def create_user(user): return db.save(user)
# exact 不同，但 token/AST 结构很像

它不是语义等价判断

MinHash 只看集合重叠，不懂程序语义。两个代码 token 很像但逻辑可能相反；两个代码 token 差异大也可能语义等价。所以它用于“候选去重”，不是最终 correctness reward。

参数影响

  • signature 越长，估计越稳定，但存储和计算更重。
  • shingle 越短，召回更高但误杀更多。
  • shingle 越长，更精确但漏掉轻微改写的重复。

在本项目里的位置

build/deduplicate.py 目前保留了 Signature 接口，用轻量 hash fallback 跑通；真实大数据时可以替换成 datasketch MinHash。

一句话：MinHash 是把“大代码集合相似度”压缩成“小签名相似度”的办法，用来快速找近重复。
