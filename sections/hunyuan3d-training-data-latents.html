训练时输入是图片输出是 latents 吗，训练数据集怎么构造

你的猜法大方向是对的：训练数据确实可以理解成“一个真实 3D 模型生成多张 2D 渲染图作为条件输入，同时这个 3D 模型对应的完整几何 latent 作为监督来源”。但有一个关键修正：DiT 训练时不是直接输出 clean latent，而是输出 flow matching / diffusion 的 velocity 或 noise 目标；clean latent 是用来构造训练目标的。

一句话：训练样本不是“图片 → 直接回归 latent”这么简单，而是“2D 渲染图做条件，3D surface 经 ShapeVAE encode 得到 clean latent；训练时给 clean latent 加噪成 noisy latent，DiT 输入 noisy latent + timestep + 图片条件，输出 velocity/noise 预测，用 MSE 对齐目标”。

这次我看了 Hunyuan3D-2.1 的训练代码，源码已经把数据组织方式写得很直接：

每个样本目录对应一个 3D asset。AlignedShapeLatentDataset.decode() 里把 item 当成一个资产目录，取 uid = item.split('/')[-1]。
一个 asset 有 24 张条件渲染图。源码构造 render_cond/{i:03d}.png，范围是 i in range(24)。这正是你说的“一个 3D 模型搞多组训练数据”。
同一个 asset 有完整几何数据。源码读取 geo_data/{uid}_surface.npz，里面取 random_surface 和 sharp_surface。这代表完整 3D 几何采样，不是某一张 2D 图。
每次训练随机选一个视角。load_render() 里用 self.rng.sample(imgs_path, 1) 从 24 张渲染图里抽一张作为本次条件图。
dataset 返回 image + surface。transform() 最后返回 surface、image、mask。所以训练 batch 里同时有 2D 条件图和 3D 几何监督。
Hunyuan3D-2.1 数据目录概念：
asset_uid/
  render_cond/
    000.png
    001.png
    ...
    023.png          # 同一个 3D asset 的 24 个条件视角
  geo_data/
    asset_uid_surface.npz
      random_surface # 3D 表面点/法线等
      sharp_surface  # 锐边表面点等

训练时一次 sample 大概取：
  image = 随机一张 render_cond/*.png
  surface = 同一个 asset 的完整 3D surface 数据

然后模型训练阶段怎么用这些数据？源码 Diffuser.forward() 里是这条链：

图片进入条件编码器。contexts = self.cond_stage_model(image=batch.get('image'), ...)。配置里 cond stage 是 SingleImageEncoder，主 image encoder 是 DinoImageEncoder，也就是用 DINOv2 Large 编码 2D 图片。
surface 进入 ShapeVAE。latents = self.first_stage_model.encode(batch[self.first_stage_key], sample_posterior=True)。配置里 first_stage_key='surface'，所以 clean latent 来自完整 3D surface，而不是来自 2D 图。
latent 做 scale。latents = self.z_scale_factor * latents，把 ShapeVAE latent 调到训练使用的尺度。
transport 构造 flow matching 训练目标。self.transport.training_losses(self.model, latents, dict(contexts=contexts)) 内部把 clean latent 当 x1，采样噪声 x0 和时间 t，得到 noisy/interpolated latent xt 以及目标 velocity ut。
DiT 预测 velocity/noise 目标。model_output = model(xt, t, contexts=contexts)，然后如果 model type 是 velocity，就用 (model_output - ut)^2 做 loss。

所以“输入是图片，输出是 latent”对不对

口语上可以这么理解，但严格讲不对。严格训练输入是：noisy latent xt + timestep t + image condition；训练输出是：velocity/noise prediction；clean shape latent 是监督数据，用来生成 xt 和目标 ut。

clean latent 从哪里来

不是数据集直接读一个 latent 文件，而是训练时用 frozen ShapeVAE.encode(surface) 从完整 3D surface 编码出来。配置里 first_stage_config 指向 ShapeVAE，并从 tencent/Hunyuan3D-2.1 加载。

一个 3D 模型会不会变成多组训练数据

会。源码每个 asset 目录有 24 个 render_cond 视角，每次随机抽一张。多轮训练后，同一个 3D surface latent 会配到不同 2D 视角输入。

这是不是在训练多视角对齐能力

是。因为不同视角图片都对应同一个 3D 几何监督，模型被迫学习“同一个物体从不同角度看，应该还原到同一个完整 3D latent”。这就是训练阶段多视角一致性的核心来源之一。

把你说的猜想改成更严格版本：

你的说法：
真实 3D 模型 -> 转换成 latents 作为输出
同一 3D 模型 -> 多视角渲染 2D 图片作为输入
这样训练多视角对齐能力

更严格源码版：
真实 3D 模型 -> 预处理成 surface.npz
训练时 ShapeVAE.encode(surface) -> clean shape latent x1
同一 3D 模型 -> render_cond/000..023.png
每次随机取一张 image -> DINO/conditioner -> contexts
flow matching: sample noise x0, timestep t, interpolate 得到 xt 和 velocity target ut
DiT 输入 xt + t + contexts，输出 model_output
loss = MSE(model_output, ut)

所以 clean latent 是监督来源，不是 DiT 直接回归的最终输出。

为什么这能学到背面

假设同一个椅子 asset 有正面、侧面、背面渲染图。训练时正面图、侧面图、背面图都能对应同一个完整 3D surface latent。模型就会学到：看到正面时，也要生成一个完整椅子，而不是只生成正面薄片。

为什么这不是“真实单图重建”

单张图的不可见区域仍然不唯一。训练让模型学到从可见图到完整 3D 的条件分布和类别先验，不代表推理时能知道真实背面，只能生成训练分布下合理一致的背面。

最短结论：你的理解基本正确，但要把“输出 latent”改成“用真实 3D 生成 clean latent 作为 diffusion/flow 监督”。数据集确实是一份 3D asset 派生多张 2D 条件渲染图；这种设计让模型在训练阶段学到视角不变性和多视角一致性。
