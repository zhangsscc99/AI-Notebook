详解：项目里的损失函数咋定义的

项目里的正式训练不是 SFT cross entropy，而是 GRPO / importance sampling 风格损失。最重要的文件是 /root/rlhf/fastapply_pipeline/grpo.py 和 /root/rlhf/fastapply_pipeline/train_mint_fastapply_grpo.py。

1）先把 reward 变成 advantage

rewards = [score(output_i) for output_i in group]
mean_reward = sum(rewards) / len(rewards)
advantage_i = reward_i - mean_reward

GRPO 不需要单独训练 value model。它直接在同一个 prompt 的一组候选里比较：谁比组平均好，advantage 为正；谁比组平均差，advantage 为负。

2）Datum 里怎么喂给 MinT

loss_fn_inputs = {
  "target_tokens": full[1:],
  "weights": [0]*prompt + [1]*response,
  "logprobs": old_policy_logprobs,
  "advantages": centered_advantages,
}
  • target_tokens：每个位置预测下一个 token。
  • weights：prompt 部分是 0，只训练 response token。
  • logprobs：采样时旧策略 π_old 的 logprob。
  • advantages：该 response 的组内优势，复制到生成 token 上。
当前 LoRA sampler 对同一 prompt 采样多条 response。
reward 函数给每条 response 打分。
组内中心化得到 advantage。
调用 training_client.forward_backward(datums, loss_fn="importance_sampling")。

直观数学式

ratio_t = exp(logπ_new(a_t|s_t) - logπ_old(a_t|s_t))
loss_policy = - Σ weights_t · advantage_i · ratio_t

如果 advantage 为正，最小化 loss 会提高这条输出的概率；如果 advantage 为负，最小化 loss 会降低这条输出的概率。

图片里那套 KL / entropy

RL-master smoke 里显式写了更完整的分解：

policy_loss = -min(ratio * adv, clipped_ratio * adv)
kl_loss = beta_kl * KL(policy || ref)
entropy_bonus = entropy_coef * entropy
total_loss = policy_loss + kl_loss - entropy_bonus

含义是：提高好样本概率，但别偏离 reference model 太远；同时保留一点熵，避免策略过早塌缩。

和 SFT 的区别

SFT 是“给定标准答案，逐 token 模仿”；这里是“同一 prompt 多个答案互相比，reward 高的提高概率、reward 低的降低概率”。所以它能优化 verifier 关心的最终行为，而不只是复制某条 gold response。

tiny smoke 的特殊点

为了 1–2 条 test 数据也能跑通，脚本可加入 oracle rollout 让 advantage 不退化。正式训练时应使用更大的 group size，例如图片配置里的 n=8。

一句话：损失函数的目标是 让高 reward 的 updated-code 轨迹更可能出现，让低 reward 轨迹更不可能出现，同时用 KL/entropy 控制训练不要跑飞。
