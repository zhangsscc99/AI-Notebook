HS10

接 Vercel Sandbox 后改一个文件到底发生在哪，怎么回传本地

这个问题要拆成三件事：模型推理在哪里发生、文件上下文从哪里来、editfile / patch 真正改的是哪里的文件。接 Vercel Sandbox 后，不是“AI 在本地分析完，只有 editfile 在云端机械执行”这么简单；更准确是：Hermes 主进程负责编排和调用模型，Vercel Sandbox 负责执行 terminal / file backend 里的命令和文件操作。

最短答案：模型上下文由 Hermes 主进程组装，里面包括用户问题、历史消息、以及从 Vercel Sandbox 读回来的文件/命令输出；模型基于这些上下文决定怎么改；真正的 read_file / patch / write_file 会通过 Vercel backend 作用在云端 sandbox 文件系统。云端改完不会自动改你的本地项目，除非你显式 git push / download / sync。

1. AI 推理在哪里发生

Hermes agent 主进程仍然在你启动 Hermes 的地方运行：可能是本机、VPS、gateway 服务器。它负责保存对话、组装 prompt、调用模型 API、接收模型返回的 tool call。

如果你用的是 OpenAI / OpenRouter / Nous Portal 等模型，真正 LLM 推理在对应模型服务商那里；不是在 Vercel Sandbox 里。Vercel Sandbox 主要负责“执行工具命令和文件操作”。

2. 文件上下文从哪里来

模型不是凭空知道云端文件内容。它要先通过工具拿上下文，例如：

terminal("git clone ...")
search_files("functionName", path=".")
read_file("src/app.ts", offset=1, limit=200)
terminal("npm test")

当 backend 是 vercel_sandbox 时，这些 search/read/test 命令都在 Vercel 云端文件系统里执行。执行结果返回给 Hermes 主进程，再进入模型上下文。模型是基于这些返回结果判断怎么改文件。

3. 修改文件“凭什么修改”

修改不是工具自己决定的。流程是：模型看到了用户需求 + 读文件结果 + 搜索结果 + 测试失败日志，然后输出一个工具调用，例如 patch 某个文件，把 old_string 换成 new_string。

也就是说，修改意图来自模型推理；修改落地由 file tool 执行。file tool 不做产品判断，它只是按模型给出的 patch/write 指令去云端文件系统执行，并返回 diff / success / error。

4. editfile 是不是只在云端发生

如果当前 terminal backend 是 vercel_sandbox，Hermes 的 ShellFileOperations 会通过 active terminal environment 执行 shell 命令。读文件用云端 cat / sed，写文件也通过云端环境落盘。

所以是的：对 sandbox 内文件的 patch / write_file 真正发生在 Vercel Sandbox 里，不是直接改本地磁盘。

5. 改完怎么回传本地

关键点：Vercel Sandbox 不像 Docker bind mount。Docker 可以把本地目录挂成容器 /workspace，所以容器改文件，本地马上变。但 Vercel 是远端云沙箱，没有直接 bind mount 你的本地目录。

所以云端改完要回到本地，通常靠这几种方式：

  • git push：云端 clone repo，修改后 commit/push，本地再 pull。
  • download/copy：显式把修改后的文件从 Vercel sandbox 下载回来。
  • 自定义 sync：你实现项目目录同步逻辑。
  • Hermes 状态同步：默认更偏 .hermes 状态，不等于同步整个项目源码树。

6. 如果本地已有项目，Vercel 怎么改它

Vercel Sandbox 默认不能直接看到你的本地项目目录。你需要先把项目放进云端，例如：

# option A: cloud clone
terminal("git clone git@github.com:you/app.git .")

# option B: upload selected files
upload src/app.ts to sandbox

# option C: generate files in sandbox
write_file("src/app.ts", content)

如果没有把项目放进 Vercel，模型在云端就没有真实项目文件可改。它最多只能基于你贴给它的上下文生成建议，但不能对本地文件产生真实落盘修改。

配置 Vercel backend。terminal.backend = "vercel_sandbox"，Hermes 创建/恢复 Vercel 云端 sandbox。
准备项目。通常在云端 sandbox 里 git clone 项目，或上传需要修改的文件。
读取上下文。模型要求 search/read/test；Hermes 在 Vercel 里执行这些工具，把结果返回给模型上下文。
模型决定修改。LLM 基于文件片段、错误日志、用户目标，生成 patch/write_file 工具调用。
云端执行修改。file tool 通过 Vercel backend 修改 sandbox 文件系统，并返回 diff / lint / error。
回传结果。如果要本地也有改动，需要 git push 后本地 pull，或显式下载文件；不会自动 magically 修改本地目录。
Vercel edit_file mental model

Hermes main process
  -> owns conversation
  -> calls model API
  -> receives tool calls
  -> routes file/terminal tools to active backend

Vercel Sandbox
  -> owns remote filesystem
  -> runs shell commands
  -> read_file/search_files see remote files
  -> patch/write_file modify remote files

Model context
  -> user request
  -> history
  -> tool outputs from Vercel reads/tests/searches
  -> model decides the edit from this context

Back to local
  -> NOT automatic local bind mount
  -> use git push/pull, explicit download, or custom sync
最终判断：接 Vercel Sandbox 后，工具执行和文件修改发生在云端；模型决策发生在 Hermes 编排的对话循环里，依据是云端工具读回来的上下文。改完是否回本地，不是自动的，要靠 git 或显式同步。
