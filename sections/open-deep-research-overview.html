概览介绍 Open Deep Research Agent

Open Deep Research Agent 不是整个 smolagents 框架本身，而是 Hugging Face 在 smolagents 仓库里的一个 Deep Research 复刻型示例项目。源码现在按实际目标 sparse clone 到服务器：/root/open_deep_research/examples/open_deep_research。原先误 clone 的 /root/smolagents 已删除。

一句话：它是一个“研究型多工具 agent team”：上层 CodeAgent 负责拆题、规划、调用视觉/文档工具、整合答案；下层 ToolCallingAgent 作为 search_agent 专门负责联网搜索、打开网页、翻页、页内查找、查 Wayback 归档和检查文件。

1. 项目定位：开源 Deep Research 复刻

README.md 写得很直接：这是对 OpenAI Deep Research 的开源复刻尝试，目标是在复杂研究任务上接近类似效果。README 里还给了 GAIA validation 的成绩描述：该 agent 达到 55% pass@1，对比原 Deep Research 的 67%。

所以它不是“通用 agent 框架介绍”，而是一个面向复杂问答、网页研究、文件理解、GAIA benchmark 的具体 agent 应用。

2. 入口：run.py

run.py 是普通使用入口：命令行读入 question 和 --model-id，调用 create_agent(model_id) 组装 agent，然后执行 agent.run(args.question)。

默认模型是 o1。源码里通过 LiteLLMModel 接模型，并在 model_id == "o1" 时设置 reasoning_effort="high" 和 max_completion_tokens=8192。

3. 上层 manager：CodeAgent

create_agent() 里最终返回的是 manager_agent = CodeAgent(...)。它的工具是 visualizer 和 TextInspectorTool，同时挂了一个 managed agent：text_webbrowser_agent。

这意味着上层 agent 不是只会搜索网页。它能写 Python action，把“调用搜索子 agent、检查文件、看图片、整理证据、计算答案”组织成一个可执行过程。

4. 下层 search_agent：ToolCallingAgent

text_webbrowser_agent = ToolCallingAgent(...) 是专职网页研究员。它的 name 是 search_agent，描述明确要求：需要浏览网页的问题都交给它，并且调用时要给完整自然语言任务，不要只给关键词。

它设置 max_steps=20、planning_interval=4、provide_run_summary=True，所以它会多轮搜索并把结果摘要回传给上层 manager。

核心工作流可以按线性顺序这样理解：

用户运行 python run.py --model-id o1 "问题"，parse_args() 取得问题和模型名。
create_agent() 创建 LiteLLMModel，配置 role conversion、token 上限；o1 额外启用 high reasoning。
创建 SimpleTextBrowser：设置 viewport、下载目录、User-Agent、timeout、cookies，并把网页转成适合 agent 阅读的文本视口。
组装网页工具列表：GoogleSearchTool、VisitTool、PageUpTool、PageDownTool、FinderTool、FindNextTool、ArchiveSearchTool、TextInspectorTool。
创建 ToolCallingAgent 作为 search_agent，它负责“找资料”，包括搜索、打开网页、查网页内关键词、翻页、读取 pdf/doc/xlsx 等文件文本。
创建上层 CodeAgent 作为 manager，挂载视觉工具、文档检查工具和 search_agent。
执行 agent.run(question)。manager 先理解问题，必要时把搜索任务委托给 search_agent，拿到网页证据后继续推理。
如果问题带文件，GAIA 入口 run_gaia.py 会先用 get_single_file_description() / get_zip_description() 生成文件说明，再把说明拼进增强问题。
最后由 manager 输出答案；GAIA 评测路径还会调用 prepare_response()，把完整 agent 轨迹再压成符合 benchmark 格式的 FINAL ANSWER。
from run import create_agent

agent = create_agent(model_id="o1")
answer = agent.run("How many studio albums did Mercedes Sosa release before 2007?")
print(answer)

它的工具层不是简单“网页搜索 API”。源码里拆得很细：

搜索和网页浏览

scripts/text_web_browser.py 定义 SimpleTextBrowser。它维护地址历史、页面标题、当前 viewport、分页边界，并把网页内容切成固定大小视口。VisitTool 负责打开 URL，PageUpTool / PageDownTool 负责翻页。

页内定位

FinderTool 和 FindNextTool 对应类似 Ctrl+F 的能力。它们不是把整页全部塞给模型，而是让模型在长网页中逐页定位关键词，减少上下文浪费。

归档网页

ArchiveSearchTool 调 Wayback Machine，输入 URL 和日期，找接近目标日期的历史快照。这对研究类任务很重要，因为很多答案依赖某个历史时点的页面内容。

文件理解

TextInspectorTool 用 MarkdownConverter 把 html、xlsx、pptx、音频、pdf、docx 和文本类文件转成 markdown/text，再用模型根据问题生成摘要或回答。visualizer 则处理图片问答。

它的 GAIA 评测入口比普通 run.py 多几层工程化处理：

run_gaia.py：批量评测

run_gaia.py 支持 --concurrency、--run-name、--set-to-run。它用 ThreadPoolExecutor 并发跑题，把每题结果追加写入 output/{set}/{run_name}.jsonl。

数据集加载

load_gaia_dataset() 会下载 gaia-benchmark/GAIA 或 smolagents/GAIA-annotated，把列重命名成 question、true_answer、task。

附件预处理

scripts/run_agents.py 里 get_single_file_description() 会根据扩展名区分图片、pdf/xls/doc、音频和普通文件；zip 会先解压，再逐个文件生成说明。

最终答案重写

scripts/reformulator.py 的 prepare_response() 会读取完整 agent 轨迹，要求模型输出严格的 FINAL ANSWER: ...。这是为了适配 GAIA 这种只看最终短答案的评测。

最短总结：Open Deep Research Agent = smolagents 上构建的研究型双层 agent。上层 CodeAgent 管全局推理和答案整合；下层 ToolCallingAgent 管网页研究；浏览器、文件转换、视觉问答、归档网页和 GAIA 评测脚本共同组成一个面向复杂研究任务的可复现实验系统。
本地源码：/root/open_deep_research/examples/open_deep_research。参考文件：README.md、run.py、run_gaia.py、app.py、scripts/text_web_browser.py、scripts/text_inspector_tool.py、scripts/run_agents.py、scripts/reformulator.py、scripts/visual_qa.py。
