Coordinator：多 worker 工作流编排

src/coordinator/coordinatorMode.ts 定义了 Claude Code 的 coordinator 模式。该模式把主 Claude 定位成“协调者”：它不应该把所有事情自己做完，而是把研究、实现、验证拆给多个 worker，并在 worker 结果回来后综合判断下一步。

角色分工

Coordinator 负责理解用户目标、拆任务、写清楚 worker prompt、综合结果并对用户汇报；worker 负责独立研究、实现或验证。

并行优先

源码 prompt 明确鼓励同时发起多个独立 worker：研究任务可以并行，写操作按文件边界避免冲突，验证可以与无冲突实现并行。

通知机制

worker 完成后以 <task-notification> 形式作为 user-role 内部消息回到 coordinator；coordinator 可用 SendMessage 继续同一个 worker，或用 TaskStop 停掉错误方向。

提示词约束

Coordinator prompt 要求每个 worker prompt 自包含：不能说“基于你的发现”，而要由 coordinator 先消化 findings，再给出具体文件、行号、目标和 done 标准。

User asks complex task
  -> Coordinator launches research workers in parallel
  -> workers return task-notification
  -> Coordinator synthesizes concrete spec
  -> continue existing worker or spawn fresh implementation worker
  -> independent verification worker proves behavior
  -> Coordinator reports final state to user
