syntax 那里能不能改写成支持更多常见编程语言

可以，已经把项目里的 fastapply_pipeline/ast_tools.py 改成多语言可插拔检查，不再只写死 Python 和 JS。现在逻辑是：有本地语法工具就用工具检查；没有工具就退回 heuristic，并在结果里标记 checked=False。

现在支持的方向

  • Python：ast.parse
  • JavaScript：node --check
  • TypeScript：tsc --noEmit
  • Java：javac
  • Go：gofmt -e
  • Rust：rustc --crate-type=lib --emit=metadata
  • C/C++：gcc/g++ -fsyntax-only
  • Shell/Ruby/PHP/Lua：对应 bash -n、ruby -c、php -l、luac -p
  • JSON/YAML：标准解析器 / PyYAML

注意：这仍不是运行测试

syntax 检查只回答“语法/解析层面是否过得去”。它不能保证代码运行不报错，也不能保证业务逻辑正确。比如变量未定义、数据库连接失败、单测失败、类型不匹配，都可能不是纯 syntax 能解决的。

ScopeInfo(
  language="typescript",
  parse_ok=True,
  checker="tsc",
  checked=True,
)
结论：syntax 已改成多语言可插拔，但真正严肃的代码 reward 应该继续叠加 unit tests、type checker、lint、沙箱执行和 LLM judge。
