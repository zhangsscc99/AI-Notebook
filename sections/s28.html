memory 安全边界

Memory 系统的安全边界主要是：哪些内容会被索引、哪些内容能被工具读、哪些内容会进入 prompt。

索引边界

默认只索引 workspace 的 MEMORY.md 和 memory/，以及配置允许的 extra paths / sessions。watcher 会跳过 .git、node_modules、虚拟环境、缓存目录等。

读取边界

memory_get 不是任意文件读取器。它按受控 memory path、QMD collection prefix 或 registered corpus supplement 读取，并限制行号范围。

session 可见性

session transcript 搜索会经过 filterMemorySearchHitsBySessionVisibility，避免把不该暴露的会话结果直接返回。

失败要显式暴露

embedding quota、provider 错误、FTS/vector 不可用时，工具会返回 disabled/unavailable/debug 信息，调用方不应该假装 memory 搜索成功。

安全上最值得查的不是“能不能搜到”，而是“这个来源是否应该被索引、是否应该被当前 session 看见、是否应该被注入上下文”。
