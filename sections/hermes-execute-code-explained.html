Hermes Agent 的 execute_code 是什么

execute_code 是 Hermes 里的一个特殊工具：它让模型写一段 Python 脚本，在脚本里批量调用 Hermes 工具，比如 read_file、search_files、terminal、web_search，然后只把脚本最终输出返回给主模型。

一句话：execute_code 不是普通 shell，也不是 Docker 本身；它是“Python 脚本 + 受限 Hermes 工具 RPC + 输出压缩/脱敏/限制”的组合，用来做多步工具自动化和上下文工程。

1. 它解决什么问题

普通 agent 如果要查 30 个文件、跑 5 个命令、过滤 1000 行日志，可能会产生很多工具调用结果。这些中间输出都会挤占上下文。

execute_code 的作用是：把这些低级过程放进一个 Python 脚本里做，最后只输出整理后的结果。

bad:
  model sees every search/read/terminal output

better:
  execute_code runs search/read/terminal internally
  script filters and summarizes
  model only sees final compact answer

2. 它怎么调用 Hermes 工具

Hermes 会自动生成一个 hermes_tools.py 模块。脚本里不是直接访问 Hermes 内部对象，而是这样调用工具：

from hermes_tools import search_files, read_file, terminal

matches = search_files("AuthError", path="src", limit=20)
content = read_file("src/auth.py", offset=1, limit=120)
test = terminal("pytest tests/auth -q")

print({
  "matches": matches,
  "test_summary": test["output"][-1000:]
})

这个 hermes_tools.py 背后通过 RPC 回到 Hermes 主进程，由主进程执行被允许的工具。

3. 为什么说它是“受限”的

脚本不是想调什么都能调。Hermes 会给 execute_code 一个允许工具集合；如果脚本调用不在白名单里的工具，会被拒绝。

它还有执行限制，例如 timeout、stdout 上限、工具调用次数上限。输出还会做 secret redaction，避免 token/API key 进入模型上下文。

意义：让模型能写脚本自动化工具流程，但不能无限制地把所有工具和所有输出都暴露出来。

4. 和 terminal 的区别

terminal 是直接跑一条 shell 命令，比如 pytest -q、npm install。

execute_code 是跑一段 Python 控制逻辑，Python 里可以循环、分支、解析 JSON、调用多个 Hermes 工具、过滤结果。

terminal:
  run one shell command

execute_code:
  run Python orchestration
  call many tools
  process outputs
  return one compact result

5. 和 Docker 沙箱的区别

Docker 回答的是“命令在哪台机器/哪个容器里执行”。

execute_code 回答的是“多步工具过程怎么在一个脚本里完成，并只返回必要结果”。

两者可以叠加：如果当前 terminal backend 是 Docker，execute_code 里的 terminal() 调用也会通过 Docker backend 去执行。

6. project 模式 vs strict 模式

Hermes 的 execute_code 有执行模式概念：

  • project：默认更贴近当前项目，脚本在 session working directory，用项目的 active venv/conda Python，方便 import 项目依赖。
  • strict：脚本在临时目录，用 Hermes 自己的 Python，更隔离、更可复现，但相对不方便直接用项目依赖和相对路径。

所以它不是永远“完全隔离临时目录”；具体行为取决于配置。

模型决定需要批处理。例如要查很多文件、跑多个命令、过滤日志。
Hermes 创建执行脚本。把模型写的 Python 和自动生成的 hermes_tools.py 放到执行环境里。
脚本调用工具。通过 hermes_tools 调用 read/search/terminal/web 等白名单工具。
脚本内部处理结果。过滤、排序、去重、聚合、摘要、截断。
只返回 stdout。主模型主要看到脚本打印出来的最终结果，而不是全部中间过程。
Hermes 做安全处理。限制工具、限制时间/输出/次数，并对输出做 secret redaction。
execute_code mental model

model writes Python
  -> Hermes generates hermes_tools.py
  -> script runs in project or strict mode
  -> script calls allowed Hermes tools through RPC
  -> script processes noisy outputs internally
  -> script prints compact final result
  -> Hermes redacts secrets and returns stdout to model

best use cases:
  - batch search/read across many files
  - parse long test logs
  - call 3+ tools with logic between calls
  - loop/retry/filter/rank/dedupe
  - reduce tool output before it enters context

not best for:
  - one simple command
  - interactive terminal sessions
  - tasks needing human input mid-script
  - replacing Docker/OS isolation
最终理解：execute_code 是 Hermes 的“工具编排脚本沙箱”。它让模型用 Python 写一个小 worker，替主模型做繁琐工具流程，最后只把有价值的压缩结果交回来。
